# 联机系统

服务端以 60 Hz 推进权威世界，常规 `STATE` 为 30 Hz，命中的相关角色可在中间 tick 收到状态。伤害、地形、拾取、复活和胜负由服务端结算。

| 模块 | 职责 |
|---|---|
| [RoomSession](../server/room_session.gd) | 席位、开局资格、就绪、断线宽限、重连凭据与消息投递 |
| [MatchRules](../server/match_rules.gd) | 回合阶段、计时、计分、出生和胜负 |
| [AuthorityWorld](../server/authority_world.gd) | 推进物理和战斗，执行换局与复活，采集权威状态 |
| [NetBus](../core/net/net_bus.gd) · [NetCodec](../core/net/net_codec.gd) | 传输派发、连接协议和快照编解码 |
| [PvpMatchClient](../scenes/pvp_match_client.gd) · [PredictionRollback](../core/net/prediction_rollback.gd) | 接纳权威事件和快照、更新世界代理、校正与推进本地角色 |

## 会话与基线

大厅的建房、查询、加入和手动回局与对局的自动重连共用 `NetSession` 的连接和应答超时。房号、模式、角色和令牌都从最近一次收到的房间状态读取。对局返回主菜单时保留中继和席位凭据，可在大厅重新进入。 [连接会话](../core/net/net_session.gd) · [房间状态](../core/net/pvp_session.gd)

每个服务端进程在同一 UDP 端口承载一个房间及其对局。大厅的 `LIST` 请求携带玩法标记，`ROOM_LIST` 返回该端点的房间或空结果。初次进场和重连的 `BASELINE` 包含原始地图字节，客户端可以直接解析建图。新回合沿用已安装的地图，恢复初始地形后应用权威差异。同一轮基线广播共用世界、地图差异与回合数据，各席位带自己的角色状态。

新回合从 `WAITING` 开始，计时为 0。客户端安装基线和碰撞后发送带回合号的 `READY`。席位全部就绪时进入 3 秒 `COUNTDOWN`，随后开始 `PLAYING`。局中重连的 `READY` 恢复该席位的快照发送。`WAITING` 中非房主席位离场会取消未开打的对局。开局和结算规则见 [对战模式](modes.md)。

断线后保留角色和席位 60 秒。客户端在 60 秒重连窗口内按次重试，连接后提交房间号与令牌获取基线。同回合重连沿用已加载地图，应用权威地形和角色状态。

## 消息与快照

游戏协议版本为 19，前缀为 `[199, 19]`，字段采用小端序。客户端与服务端使用同一版本。GNS 传输层有独立的 `GNS` 版本头，当前为 2。

| 流 | 通道 | 内容 |
|---|---|---|
| `INPUT` | 0，非可靠 | 最近 4 帧持续输入、未确认动作和 STATE ACK |
| `STATE` | 1，非可靠 | 公共世界、接收者自身状态、输入确认与地形版本 |
| `EVENT` | 2，可靠且通道内保序 | 房间信令、基线、地形、回合、弹丸与战斗事件 |

各通道独立到达。`NetBus` 可以合并同一派发区间内的连续 `STATE`，可靠事件会结束该区间。地形版本更高的 `STATE` 等待补丁，客户端复算光束前先提交已收到的地形更新。可靠弹丸事件以 tick 补齐快照之后的出生和终止，同 tick 终止优先。`HIT` 播放命中反馈，生命值和击退由 `STATE` 更新。

每个连接独立维护序号、ACK 和最多 64 份快照。差分相对接收者确认的基线。基线缺失时丢弃差分并以 ACK 0 请求全量。公共差分按基线和角色表复用，私有 `own` 包含本地状态、装备、输入续接点和回溯标记。装备实例 ID 变化时发送完整装备状态。公共世界包含玩家、掉落物和活弹。活弹快照只带类型、位置和速度，引信和直击标记留在服务端。Beta 账户快照包含余额、短期已用量、透支量与锁定状态，容量与倍率随开局规则发送。快照与解码历史共享未改动的记录。

`GnsEndpoint` 在提交时用 Fast LZMA2 编码，压缩结果较小时发送压缩数据。广播共用编码结果。可靠消息按顺序提交，超过单条 GNS 上限时分块。原生层在重组与解压前检查长度，单条消息的解码上限为 64 MiB。暂时无法提交的可靠帧留在队列，实时通道各保留最新待发包。原生轮询最多处理 256 条消息，单次收包和脚本派发各用 512 KiB、2 ms 的软预算。 [传输实现](../native/gns/gns.cpp)

## 输入与预测

输入按 epoch、序号和目标 tick 调度。`STATE` 用 `own.input.seq` 确认持续输入，用 `own.action_ack` 确认单次动作。持续输入在目标 tick 后保留 6 tick，动作超过 12 tick 后确认并丢弃。迟到且仍有效的输入移到下一 tick，未来窗口为 32 tick。客户端用同一份输入包发送并推进本地预测。 [输入缓冲](../core/net/input_buffer.gd)

每个物理步先应用可靠事件，再接纳地形版本可用的最新 `STATE`。预测保存 64 tick 的本地角色、装备、输入续接点及 Beta 本地账户，领先权威最多 32 tick。相同 tick 的这些状态一致时保留当前结果，存在差异时恢复权威状态并重放未确认输入到原预测末端。新 epoch、检查点超窗、权威 tick 领先或处于玩法回溯时直接对齐权威锚点。新 epoch 会清除旧输入。

地形、远端角色与活弹单独变化时只更新世界。重放查询已经安装的地形和角色代理，远端碰撞代理使用最近接纳的权威姿态。远端角色和掉落物的表现缓冲以 6 tick 为目标延迟，最多外推 6 tick。本地射击先显示临时弹丸和光束，随后由相同射击 ID 的权威消息接管。重放期间跳过一次性音画。 [预测步进](../core/net/prediction_rollback.gd) · [远端插值](../core/net/snapshot_buffer.gd)

## 本地服务与隧道

客户端建房时启动本游戏的无头服务端。服务端、转发和 EasyTier 控制端口动态选取。EasyTier 通过每次会话的临时配置目录以 `no_tun = true` 转发 UDP，压缩由游戏传输层处理。大厅补齐缺失的 `relay.txt` 并保留已有配置。加入房间时，节点查询、找房主和 UDP 转发失败各有对应提示。macOS 发布版使用用户数据目录，其他运行方式使用 EasyTier 组件目录。 [隧道](../core/net/tunnel.gd) · [组件与发布](../RELEASE.md)

`NetSession` 持有游戏启动的后台进程。Windows 用 Job Object 回收子进程，macOS 用独立进程组和寿命管道。客户端退出时关闭会话并回收进程。 [进程管理](../core/net/net_session.gd)
