# 远程网络联机系统架构方案

本文档说明游戏基于 EasyTier 用户态网络隧道（`--no-tun` 模式）实现的远程 P2P 联机方案。该方案无需安装系统级虚拟网卡驱动（如 Wintun、WinDivert），无需管理员权限，即可实现自动化 NAT 穿透与端口映射联机。

---

## 一、 系统架构设计

### 1. 网络拓扑与连接流程

```text
房主端                                                 客机端
─────────────────────────────────────────────        ─────────────────────────────────────────────
游戏客户端 (Cyancular Ruins.exe)                      游戏客户端 (Cyancular Ruins.exe)
  ├ 1. 动态申请本地空闲端口 P                          ├ 1. 输入 5 位数字房间号 (00000~99999)
  ├ 2. 启动服务端 Server.exe --port P                  ├ 2. 启动隧道进程 (--no-tun --dhcp)
  ├ 3. 本地探测 127.0.0.1:P 确认就绪                   ├ 3. 查询节点列表，解析房主主机名 cyr-host-P
  ├ 4. 生成 5 位房间码                                 ├ 4. 动态申请本地空闲端口 Q
  ├ 5. 启动隧道 (--no-tun -i 10.126.126.1)             ├ 5. 配置 UDP 端口转发 127.0.0.1:Q → 10.126.126.1:P
  │      设置主机名 cyr-host-P                         └ 6. 游戏客户端直连本地 127.0.0.1:Q 进入大厅
  └ 6. 本地客户端直连 127.0.0.1:P
                                                       EasyTier 用户态端口转发:
                                                       127.0.0.1:Q → 10.126.126.1:P → 房主本地 127.0.0.1:P
服务端进程 (Server.exe --port P)
  ├ 监听 ENet UDP 端口 P（单进程单端口）
  ├ RoomManager：大厅与房间调度
  └ MatchSession：开局后挂载对局节点，运行权威物理与 60Hz 状态广播
```

### 2. 核心架构特点
- **单进程单端口架构**：大厅匹配与对局运行在同一个服务端进程与同一个 ENet UDP 端口中。当房间满员开局时，`RoomManager` 直接将 `MatchSession` 节点挂载进服务端场景树，客户端全程保持连接，无需断开转连，消除了切换端口造成的连接中断与重连延迟。
- **全链路动态端口分配**：服务端监听端口 `P`、客机出站转发端口 `Q` 以及 EasyTier RPC 管理端口均直接向操作系统动态申请（通过短暂绑定 `127.0.0.1:0` 获取系统临时空闲端口后释放），杜绝硬编码端口冲突，支持单机多开测试。
- **用户态端口映射**：基于 EasyTier 内置的用户态网络栈，将虚拟网流量映射至本地回环网络。客机本地申请空闲端口 `Q`，透明转发至房主虚拟 IP 对应的端口 `P`，对游戏上层网络层完全透明。
- **纯 UDP 传输优化**：EasyTier 仅保留 UDP 监听端口（`-l udp://0.0.0.0:0`，`--default-protocol udp`，禁用 TCP 打洞），避免数据包在 TCP mesh 中产生队头阻塞，配合 BBR 拥塞控制与最低延迟优先策略（`--latency-first`）。
- **无需管理员权限**：完全基于用户态套接字运行，不安装虚拟网卡驱动，双击即可运行。
- **NAT 穿透与中继容灾**：通过初始共享节点交换端点，优先通过 STUN 完成 NAT 打洞建立 P2P 直连通道；在对称型 NAT 等无法直连的网络环境下，自动通过中继节点转发保底。

## 二、 目录结构与依赖管理

### 1. 文件与资源分布

```text
The Cyancular Ruins.exe             # 游戏客户端主程序
Cyancular Ruins Server.exe          # 独立服务端程序（房主建房时自动拉起）
easytier/                           # 隧道核心依赖目录
  easytier-core.exe                 # EasyTier 隧道通信进程
  easytier-cli.exe                  # EasyTier 命令行管理工具
  Packet.dll                        # 核心动态链接库
  wintun.dll                        # 备用依赖库
  relay.txt                         # 初始共享节点列表（必需配置）
log/                                # 运行时日志目录
  client.log                        # 客户端主日志
  server.log                        # 本地服务端日志
  client.old.log                    # 客户端历史日志（单文件超 2MB 自动归档）
  server.old.log                    # 服务端历史日志
  easytier-host-<pid>/easytier.log  # 房主端隧道日志（按父进程 PID 隔离）
  easytier-guest-<pid>/easytier.log # 客机端隧道日志
```

### 2. 依赖检查与日志管理
- **依赖完整性检查**：`easytier-core.exe` 静态依赖 `Packet.dll`。若缺少该文件，Windows 将无法启动该进程。因此在启动隧道前，`Tunnel.available()` 会强制检查依赖文件完整性。
- **中继节点配置 (`relay.txt`)**：EasyTier 没有内置默认对等节点，联机双方必须配置同一个可访问的初始共享节点。节点配置位于 `easytier/relay.txt`。若文件缺失，系统会自动生成模板并提示玩家配置。
- **进程隔离与日志清理**：为避免同机多开（房主与客机共存）产生日志文件写入冲突，系统按角色及父进程 PID 创建独立子目录（`log/easytier-<角色>-<pid>/`）。启动隧道前，`Tunnel._reap_orphans()` 会自动检测并回收已终止游戏的残留孤儿进程。

## 三、 端口分配与服务端管理

### 1. 服务端拉起流程 (`server/local_server.gd`)
房主创建房间时，客户端在后台拉起无头服务端：
1. **动态端口申请**：向系统请求分配空闲 UDP 端口（`PacketPeerUDP.bind(0, "127.0.0.1")` 获取临时空闲端口号 `P` 之后立即释放），通过 `--port P` 参数启动 `Cyancular Ruins Server.exe`。
2. **本地探测**：客户端轮询探测 `127.0.0.1:P`。若进程异常退出会重新申请端口并重试（最多 8 次）；若 10 秒内未监听且进程存活，提示可能存在防火墙拦截。
3. **连接直接复用**：本地探测连接成功后，该 ENet 连接直接保持并作为房主的大厅会话。

### 2. 单进程单端口调度 (`server/server_main.gd` + `server/lobby/room_manager.gd`)
- 服务端主入口为 `server_main.tscn`，监听唯一的 UDP 端口 `P`。
- 开局时 `RoomManager` 挂载 `MatchSession` 节点；对局结束触发 `MatchSession.finished` 信号，作废重连凭据并清理节点。
- `RoomManager` 定期执行超时扫描，自动清理超过 2 小时的陈旧房间。

## 四、 房间号编码与端口转发

### 1. 5 位数字房间码设计
- **随机生成**：房间码采用 5 位十进制数字字符串（`00000`~`99999`），前导零合法有效。
- **映射规则**：
  - EasyTier 网络名称：`cyr-<5位房间码>`（例如 `cyr-48213`）
  - EasyTier 访问密码：`<5位房间码>`
  - 虚拟网段：`10.126.126.0/24`（房主固定使用 `10.126.126.1`，客机使用 `--dhcp` 自适应分配）。

### 2. 端口发现与转发
1. **主机名传递端口**：房主启动隧道时将服务端口写入主机名（`--hostname cyr-host-P`）。
2. **客机自动发现**：客机加入房间后，轮询 `easytier-cli peer`，解析主机名前缀为 `cyr-host-` 的节点，提取房主虚拟 IP 及真实服务端口 `P`。
3. **客机空闲端口绑定**：客机动态申请空闲端口 `Q`，并下发出站转发命令：
   ```text
   easytier-cli port-forward add udp 127.0.0.1:Q 10.126.126.1:P
   ```
4. **客户端连接**：客机游戏客户端直连本地回环地址 `127.0.0.1:Q`，流量由 EasyTier 用户态 NAT 代理送达房主服务端。

## 五、 对局同步与规则裁决

### 1. 客户端预测与回滚
- **输入序列与回滚**：客户端本地运行物理预测，将玩家输入打上序号发送至服务端。服务端以 60Hz 频率向下广播世界快照与个人状态（包含已确认序号 `ack_seq`）。
- **贴身碰撞自适应容差**：两名玩家近距离接触缠斗时，物理接触将位置容差由 `2.0px` 自动放宽至 `8.0px`，消除频繁触发预测回滚引起的画面抖动。
- **60Hz 快照广播**：服务端周期广播权威物理全态，偏差超出阈值时由客户端执行状态还原与待确认输入重放。

### 2. 多人玩法模式规范
- **1v1 决斗**：抢五胜制，局间两队对调出生点，换局时重置场景瓦片与动态子弹。
- **多人大乱斗**：限时 300 秒，采用三级动态复活点选点算法，支持 AI 机器人补位与 3 秒击杀归因。
- **3v3 团队赛**：
  - 分队碰撞层实现友军穿透：1 队 `layer=2, mask=1|4|16`；2 队 `layer=16, mask=1|2|4`（掩码保留地形 Layer 1 防止穿墙）。
  - 子弹穿透队友，爆炸伤害无差别结算。

## 六、 断线重连机制

### 1. 局内掉线快速重连 (`GraceWindow`)
- 网络短暂断开时，服务端保留玩家角色节点与背包数据，启动 60 秒宽限期倒计时。
- 客户端在原端口重连后发送 `reclaim_role` 认领角色，通过 `match_sync` 补发断线期间被破坏的瓦片与地面武器列表。
- 大乱斗与 3v3 宽限到期后移除角色，其余玩家继续；1v1 宽限到期则直接判定对手获胜。

### 2. 退回大厅后的重连 (`RejoinRegistry`)
- 开局时为每位玩家生成 16 位 Token，映射至递增局号 `match_id`（有效期 1 小时）。
- 玩家退回主菜单后重新进入大厅，其所属的进行中房间会显示重连入口。点击后客户端向大厅发送 `rejoin_request`，校验放行后进入对局重新认领角色席位。
