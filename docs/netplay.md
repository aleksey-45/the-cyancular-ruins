# 联机系统

服务器和客户端预测共用一套对局模拟代码，各自以 60 Hz 推进。服务器通常每两个模拟帧发送一次状态快照，发生伤害或回合阶段变化时会额外同步。对局结束时通过可靠有序通道发送完整快照。

| 模块 | 职责 |
|---|---|
| [RoomSession](../server/room_session.gd) | 管理房间、席位、就绪、断线宽限和重连。每个物理帧先轮询连接，再推进对局会话并发布结果。 |
| [MatchSession](../core/net/match_session.gd) | 本地会话收集输入并以固定步长推进模拟。联机会话同步地形版本，处理输入确认，并根据服务器快照校正预测。 |
| [MatchWorld](../core/sim/match_world.gd) · [MatchRules](../core/sim/match_rules.gd) | 模拟战斗、时间技能、回合和复活，按需采集和恢复完整检查点。 |
| [NetBus](../core/net/net_bus.gd) · [NetCodec](../core/net/net_codec.gd) | 收发消息，编码输入、基线、地形和状态。 |
| [MatchSampler](../core/present/match_sampler.gd) · [MatchPresenter](../core/present/match_presenter.gd) | 按渲染时间采样，生成角色位置、倒地姿态、武器姿态和画面提示。 |

## 房间与对局

一个服务器进程在同一个 UDP 端口处理一个房间和对应的对局。大厅通过局域网广播生成房间列表。服务器仍支持通过 `LIST` 和 `ROOM_LIST` 查询单个房间。客户端根据最近的房间消息保存房间号、模式、角色 ID 和重连令牌。返回主菜单时保留隧道与重连凭据，可以从大厅重新加入。[连接与超时](../core/net/net_session.gd) · [房间资料](../core/net/pvp_session.gd)

## 局域网发现

房主建房后，服务器每秒向 UDP **7788** 端口广播房间信息。同一广播域的客户端监听该端口并更新房间列表，连续 3 秒未收到该房间的广播时将其从列表移除。广播包含房间号、模式、当前人数、人数上限、对局状态、Beta 标记和游戏端口。客户端从 UDP 数据报的源地址取得服务器 IP。

点击房间卡片优先直连房主的游戏端口并发送 `JOIN`。直连失败时，客户端通过房间号尝试 EasyTier 隧道。建房时可关闭局域网展示（`lan_public=false`），其他玩家可以手动输入 8 位房间号。

如防火墙拦截广播或游戏流量，检查 UDP 7788 和房间游戏端口。跨 VLAN 或 AP 开启客户端隔离时，可尝试通过房间号加入。[发现协议](../core/net/lan_discovery.gd) · [房主广播](../core/net/lan_beacon.gd)

首次进场、重连和换轮共用基线。服务器发送地图、规则配置、种子、完整检查点和当前地形差异。换轮沿用现有连接与席位，以新基线同步复位后的地形。客户端安装基线时清除旧的预测和待处理补丁。`player_collision` 随房间选项发送，服务器和客户端据此使用相同的移动碰撞遮罩。

新回合从等待就绪（`WAITING`）开始。客户端安装基线后发送带回合编号的 `READY`，服务器收到当前回合的确认后恢复向该席位发送普通快照。全部玩家就绪后进入 3 秒倒计时（`COUNTDOWN`），结束后开始交战（`PLAYING`）。在等待就绪期间移除非房主玩家会取消当前对局。[对战模式](modes.md)

断线后，服务器保留角色和房间席位 60 秒。对局客户端在 60 秒内分次重试连接。连接成功后用房间号和令牌发出 `REJOIN`，服务器为该角色更新输入版本号并发送基线。

## 消息与快照

游戏协议版本为 39，消息前缀为 `[199, 39]`。多字节字段使用小端字节序。GameNetworkingSockets 使用独立的 `GNS` 传输头，版本为 2。

| 消息 | 通道 | 内容 |
|---|---|---|
| `INPUT` | 0，不可靠 | 最近 4 份持续输入、未确认的单次动作、目标帧和状态确认序号。 |
| `STATE` | 1，不可靠 | 用于恢复模拟的完整状态及其地形版本。输入确认、断线宽限和接收方时序反馈随包发送。 |
| `BASELINE`、`TERRAIN`、房间消息 | 2，可靠有序 | 首次进场、重连或换轮基线、更新后的地形版本和子格耐久度、席位和就绪等消息。对局结束时的状态，以及编码后超过 256 KiB 的状态，也通过此通道以完整快照发送。 |

`STATE.tick` 是服务器模拟帧号。解码后的快照记录该帧结算后的状态，包括角色受击或开火产生的速度偏移、弹丸的引信、已飞行距离和直击记录，以及待结算爆炸、回合计分和 Beta 技能历史。表现层根据状态变化生成开火、命中、爆炸、弹丸消失和倒地等反馈。 [世界检查点](../core/sim/match_world.gd)

每个连接最多保留 64 份快照作为增量编码的基准。编码时只写入相对已确认基准有变化的字段，使用相同基准的连接可以共用编码结果。Beta 技能历史复用连续的历史采样，只编码新增的采样和弹丸运动变化。找不到基准时，客户端用确认序号 0 请求完整快照。需要传输大型恢复快照或对局结束时的快照时，服务器发送可独立解码的完整状态。对局结束时的快照只编码和压缩一次。 [状态编解码](../core/net/net_codec.gd)

各通道的消息独立到达。接收端可以合并同一连接的连续 `STATE`，保留发送序号最大的一份。可靠事件和连接通知会中断合并。客户端在所需地形版本可用后，才能用该快照校正预测。 [消息轮询](../core/net/net_bus.gd) · [地形版本](terrain.md#回溯与网络同步)

原生传输层尝试用 Fast LZMA2 压缩消息，结果较小时发送压缩数据，否则发送原数据。同一条广播共用编码结果。可靠消息按顺序排队，超过单条 GNS 消息上限时分块。每条消息最多解码 64 MiB。暂时无法提交的可靠消息留在队列，不可靠通道各保留最新待发消息。原生层每次轮询最多处理 256 条消息，轮询与脚本分发分别使用 512 KiB 和 2 毫秒的软预算。[原生传输](../native/gns/gns.cpp)

## 输入与预测

客户端每个物理帧先处理可用的权威快照，再根据当前玩家位置、装备和输入锁采样新操作。每份输入在第一次排帧时绑定 `epoch`、序号和目标帧，冗余副本和重放沿用同一个目标帧。每个输入包都能独立解码。持续输入在包内对“目标帧减序号”做增量编码，单次动作携带绝对目标帧。服务端校验版本和时间窗口，将有效记录交给输入缓冲区。新到的反馈只影响未来采样。复活、结束个人回溯和重连开启新输入版本。

服务端通过 `submit` 接收输入，快照原样转发它给该玩家的反馈。客户端预测器只需要在基线时初始化时钟、在快照到达时同步，然后为采样取得目标帧和模拟终点。收包分位数、反馈年龄、调速倍率以及选择何时补一步或少走一步，都由时序模块管理。所有武器沿用相同的帧号语义。[权威输入调度](../core/net/input_scheduler.gd) · [本地预测时钟](../core/net/input_clock.gd)

持续输入可沿用至目标帧之后 6 帧。单次动作超过目标帧 12 帧后仍确认序号，但跳过执行。有效的迟到输入移到下一帧，缓冲区接受未来 32 帧以内的输入。`STATE` 为每个角色附带输入确认记录，分别确认持续输入和单次动作的序号。所有武器都从同一权威步取用输入。[输入缓冲区](../core/net/input_buffer.gd)

客户端每个物理帧先轮询连接，将收到的地形补丁加入队列，再选择最新可用的 `STATE`。会话保留每个预测帧的本地玩家状态。同帧位置的环形距离误差在 0.1 像素内，其余玩家字段相同时，客户端可继续当前预测，同时处理权威快照和输入确认。地形待校正、回合或席位变化、输入版本重置及本地状态不符时，回滚到权威快照中的状态，按原目标帧重放仍有效的未确认输入。其他模拟差异可能保留至下一次完整校正。客户端最多预测到最新可用服务器快照之后的第 32 帧，最多保留 64 条未确认的持续输入。预测远端角色时，只在有限窗口内沿用最近的移动输入。 [会话固定步](../core/net/match_session.gd)

远端角色、武器、弹丸、光束与掉落物共用一条延迟渲染时间轴。位置沿可跨地图边界的最短路径插值，缺少新快照时最多外推 2 个模拟帧。实体的出现、消失和搭箭状态也按这条时间轴更新。校正本地角色的位置时，画面上的偏移随时间衰减。生命值和倒地状态取自最新可用的服务器快照。 [播放时钟](../core/net/snapshot_clock.gd) · [采样](../core/present/match_sampler.gd)

## 本地服务器与隧道

客户端建房时启动无界面的游戏服务器，动态选取游戏端口。加入方通过 EasyTier 节点列表查找房主，再把本机 UDP 端口转发到房主的游戏端口。EasyTier 的控制端口和转发端口动态选取。每次会话使用临时配置目录，以 `no_tun = true` 运行应用层转发。游戏传输层负责消息压缩。

大厅在 `relay.txt` 缺失时生成初始节点列表。macOS 发布版把它放在用户数据目录，其余运行方式放在 EasyTier 组件目录。Windows 使用 Job Object 管理游戏启动的后台进程，macOS 使用独立进程组和随父进程关闭的管道。退出游戏时关闭会话并清理子进程。[EasyTier 隧道](../core/net/tunnel.gd) · [进程管理](../core/net/net_session.gd)
