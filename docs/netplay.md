# 联机系统

联机采用状态同步，以服务器模拟结果为准。服务器模拟和客户端预测共用一套逻辑，模拟步长均为 1/60 秒。服务器通常每两个模拟帧发送一次状态快照，发生命中或回合阶段变化时会额外同步。对局结束时通过可靠有序通道发送完整快照。

| 模块 | 职责 |
|---|---|
| [NetSession](../core/net/net_session.gd) | 客户端按房号浏览、创建、加入或重连。保存实际路径与席位凭据，向大厅提供附近房间摘要与当前名单。 |
| [RoomSession](../server/room_session.gd) | 管理房间、席位、就绪状态和断线重连。每个物理帧先轮询网络消息，再推进对局模拟并同步状态。 |
| [MatchHost](../core/net/match_host.gd) · [PredictedMatch](../core/net/predicted_match.gd) | 权威主机按席位汇集本地输入和已调度的远端输入，再推进世界。客户端安装权威帧、校正预测并重放输入。 |
| [MatchWorld](../core/sim/match_world.gd) · [MatchRules](../core/sim/match_rules.gd) | 模拟战斗、时间技能、回合和复活，按需采集和恢复完整检查点。 |
| [NetBus](../core/net/net_bus.gd) · [NetCodec](../core/net/net_codec.gd) | 收发消息，编码输入、基线、地形和状态。 |
| [MatchSampler](../core/present/match_sampler.gd) · [MatchPresenter](../core/present/match_presenter.gd) | 按渲染时间采样，生成角色位置、倒地姿态、武器姿态和画面提示。 |

## 房间与对局

每个服务器进程通过一个 UDP 游戏端口管理一个房间。建房、入房请求直接携带昵称与色相。客户端确认建房后启动一次 EasyTier 房主入口。入口启动失败时保留房间，并提示房主远程入口不可用。暂时断开可在席位保留期内回局，主动离房会清除凭据。结算时用 `RETURN_TO_ROOM` 确认返回等待室。[房间管理](../core/net/net_session.gd)

## 局域网发现

房主建房后，服务器每秒向 UDP **7788** 端口广播房间信息。同一广播域的客户端监听该端口并更新房间列表，连续 3 秒未收到该房间的广播时将其从列表移除。广播包含房间号、模式、当前人数、人数上限、对局状态、Beta 标记和游戏端口。客户端从 UDP 数据报的源地址取得服务器 IP。

点击卡片和手输房号都调用 `join_room(code)`。房间管理优先接通新鲜广播中的地址，没有地址或直连不可达时按房号建立 EasyTier 转发。连接成功后只发送一次 `JOIN`。房间拒绝或回执丢失会结束本次请求。建房选项 `listed_nearby` 控制附近展示，关闭后仍可按房号加入。广播使用受限广播地址和各接口的实际 IPv4 广播地址。

如防火墙拦截广播或游戏流量，检查 UDP 7788 和房间游戏端口。跨 VLAN 或 AP 开启客户端隔离时，可尝试通过房间号加入。[发现协议](../core/net/lan_discovery.gd) · [房主广播](../core/net/lan_beacon.gd)

## 对局基线与重连

首次进场与重连使用 `BASELINE`，携带地图、开局名册、规则、种子、地形改动与完整检查点。换轮使用 `ROUND`，只携带地形与本轮的完整检查点。客户端应用基线时重置预测，清空待处理的快照和地形补丁。换轮沿用现有连接与席位，以新回合消息同步复位后的地形。服务器和客户端根据房间选项 `player_collision` 设置相同的角色移动碰撞遮罩。

新回合从等待就绪（`WAITING`）开始。客户端应用基线后发送带回合编号的 `READY`，服务器收到当前回合的确认后开始向该席位发送普通快照。全部玩家就绪后进入 3 秒倒计时（`COUNTDOWN`），随后开始交战（`PLAYING`）。等待就绪期间，非房主玩家离开房间或断线超时会取消当前对局。[对战模式](modes.md)

断线后，服务器保留角色和房间席位 60 秒。对局客户端在 60 秒内多次尝试重连。连接成功后，客户端发送带房间号和重连令牌的 `REJOIN`。房主始终重连本机游戏端口，客人先试上次成功的路径，再尝试另一条可用路径。服务器更新该角色的输入版本号并发送新基线。

## 消息与快照

游戏协议版本为 42，消息前缀为 `[199, 42]`。检查点的回合区段用一个字节标明是否带回合规则，含回合的对局继续使用字段差分。多字节字段使用小端字节序。GameNetworkingSockets 使用独立的 `GNS` 传输头，版本为 2。

| 消息 | 通道 | 内容 |
|---|---|---|
| `INPUT` | 0，不可靠 | 最多 4 份最新的持续输入、未确认的单次动作、各自的目标帧和客户端已确认的快照序号。 |
| `STATE` | 1，不可靠 | 解码后可恢复模拟的完整状态、地形版本、输入确认、断线宽限信息和接收方的时序反馈。 |
| `BASELINE`、`TERRAIN`、房间消息 | 2，可靠有序 | 对局基线、地形版本和子格耐久度更新、席位和就绪等消息。对局结束时的状态，以及编码后超过 256 KiB 的状态，也通过此通道以完整快照发送。 |

`STATE.tick` 是服务器模拟帧号。解码后的快照记录该帧结算后的状态，包括击退和后坐速度、弹丸的引信、已飞行距离和直击记录，以及待结算爆炸、回合计分和 Beta 时间技能历史。表现层根据状态变化生成开火、命中、爆炸、弹丸消失和倒地等反馈。[世界检查点](../core/sim/match_world.gd)

每个连接最多缓存 64 份快照，用于增量编解码。发送时以客户端已确认的快照为基准，编码变动的字段。同一批次中，基准相同的连接共用世界状态的编码结果。Beta 时间技能历史复用两份快照中连续重叠的采样，再编码新增的采样和弹丸运动变化。找不到基准时，客户端用确认序号 0 请求完整快照。对局结束时，服务器将可独立解码的完整快照编码、压缩一次后广播。[状态编解码](../core/net/net_codec.gd)

各通道的消息独立到达。接收端在一段连续的 `INPUT` 和 `STATE` 消息里合并状态快照，每个连接保留发送序号最大的一份。房间消息、地形更新和连接通知等消息会中断合并。所需的地形版本可用后，客户端才用该快照校正预测。[消息轮询](../core/net/net_bus.gd) · [地形版本](terrain.md#回溯与网络同步)

原生传输层用 Fast LZMA2 压缩消息，并在压缩数据与原数据中选较小的一份发送。同一条广播共用编码结果。可靠消息按顺序排队，超过单条 GNS 消息的大小上限时分片。每条消息解码后最多为 64 MiB。暂时无法发送的可靠消息留在队列，不可靠通道各保留最新的待发消息。原生层每次轮询最多处理 256 条消息。原生轮询和脚本分发各有 512 KiB 和 2 毫秒的软预算，在两条消息之间检查。[原生传输](../native/gns/gns.cpp)

## 输入与预测

客户端每个物理帧先轮询网络消息，将收到的地形补丁加入队列，再处理最新可用的权威快照。随后根据玩家的位置、装备和输入限制采样新输入。首次采样时为输入记录版本号 `epoch`、序号和目标模拟帧，冗余副本和重放沿用原目标帧。每个输入包都能独立解码。包内对持续输入的「目标帧减去输入序号」做增量编码，单次动作则记录完整目标帧号。服务器校验输入版本号和有效时间窗口。复活、结束个人回溯、重连或最新持续输入超出时序窗口时，服务器更新输入版本号。

服务器的输入调度器根据每份输入首次可用的时间估计延迟和抖动，随快照发回时序反馈。客户端用基线初始化预测时钟，随后根据采用的快照更新时钟，为新采样的输入安排目标帧并确定预测进度。时钟可多推进或少推进一个模拟步，两次调整至少间隔六次采样。按键或移动方向变化时，时钟保留本次模拟步。[服务器输入调度](../core/net/input_scheduler.gd) · [本地预测时钟](../core/net/input_clock.gd)

持续输入中的移动和按键状态可沿用至目标帧后第 6 帧。单次动作有效至目标帧后第 12 帧，超期后只确认序号。缓冲区接受目标帧在未来 32 帧以内的输入，迟到且仍有效的输入最早在下一帧执行。`STATE` 为每个角色分别确认持续输入和单次动作的序号。[输入缓冲区](../core/net/input_buffer.gd)

客户端按模拟帧缓存本地角色的预测状态。校正时，将同一帧的预测状态与权威状态对比，位置偏差按可跨越地图边缘的最短路径计算，容差为 0.1 像素。若其余角色字段也一致，且地形和对局状态无需更新，客户端可以继续预测并处理输入确认。地形需要校正、回合编号或阶段变化、角色数量变化、输入版本重置或预测状态不符，都会触发回滚。客户端恢复到权威快照，再按原目标帧重放仍有效的未确认输入。角色复活时直接从校正后的状态继续。其他模拟差异可能延续到下一次回滚。客户端最多预测到最新可用服务器快照之后的第 32 帧，最多保留 64 条未确认的持续输入。远端角色参与预测时，客户端只在短时间内沿用其最近的移动输入。[客户端预测](../core/net/predicted_match.gd)

远端角色、武器、弹丸、光束与掉落物在同一条延迟时间轴上采样。位置沿可跨地图边缘的最短路径插值，缺少新快照时最多外推 2 个模拟帧。实体出现、消失和搭箭状态也按这条时间轴更新。校正本地角色的位置时，画面上的偏移逐渐衰减。界面中本地角色的生命值和倒地状态取自最新可用的服务器快照。[快照时钟](../core/net/snapshot_clock.gd) · [表现采样](../core/present/match_sampler.gd)

## 本地服务器与隧道

客户端建房时以无头模式启动游戏服务器，动态选择游戏端口。使用 EasyTier 路径时，客户端在节点列表中查找房主，并把本机转发端口收到的 UDP 流量转发到房主的游戏端口。EasyTier 的控制端口和转发端口均动态分配。每次会话使用临时配置目录，并以 `no_tun = true` 启用应用层转发。

首次启动隧道时按需生成 `relay.txt` 初始节点列表。macOS 发布版把它放在用户数据目录，其余运行方式放在 EasyTier 组件目录。Windows 使用 Job Object 管理游戏启动的后台进程，macOS 使用独立进程组和随父进程关闭的管道。退出游戏时关闭会话并清理子进程。[EasyTier 隧道](../core/net/tunnel.gd) · [进程管理](../native/process_group/process_group.cpp)
