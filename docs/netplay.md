# 远程网络联机系统架构方案 (基于 EasyTier 用户态隧道)

本文档介绍游戏中基于 EasyTier 用户态网络隧道（`--no-tun` 模式）实现的远程 P2P 联机架构。该方案彻底摆脱了对虚拟网卡驱动（如 Wintun、WinDivert）以及 Windows UAC 管理员提权的依赖，实现免安装驱动、无需管理员权限、自动 NAT 穿透与端口映射的联机对战。

---

## 一、 系统架构设计

### 1. 网络连接拓扑

```text
房主端 (Host)                                         客机端 (Client)
─────────────────────────────────────────────        ─────────────────────────────────────────────
游戏客户端 (Cyancular Ruins.exe)                      游戏客户端 (Cyancular Ruins.exe)
  ├ 1. 向操作系统动态申请空闲端口 P (bind :0)          ├ 1. 玩家输入 5 位十进制房间号 (00000~99999)
  ├ 2. 后台启动单进程服务端 Server.exe --port P        ├ 2. 启动隧道进程 (--no-tun --dhcp)
  ├ 3. 本地探活 127.0.0.1:P 确认服务端就绪             ├ 3. 轮询 peer 列表，解析房主主机名 cyr-host-P
  ├ 4. 创建房间，生成 5 位纯数字房间码                 ├ 4. 向操作系统动态申请空闲端口 Q (bind :0)
  ├ 5. 启动隧道进程 (--no-tun -i 10.126.126.1)         ├ 5. 配置 UDP 端口转发 127.0.0.1:Q → 10.126.126.1:P
  │      设置主机名 cyr-host-P                         └ 6. 游戏客户端直连本地 127.0.0.1:Q 进入大厅
  └ 6. 本地客户端直连 127.0.0.1:P                   EasyTier 用户态端口转发 (NAT 自动处理)
                                                       10.126.126.1:P → 房主本地 127.0.0.1:P
服务端进程 (Server.exe --port P)
  ├ 监听 ENet UDP 端口 P（单进程、单端口架构）
  ├ RoomManager：大厅与房间会话编排
  └ MatchSession：开局后同进程内直接挂载对局节点，驱动权威物理与 60Hz 快照广播
```

### 2. 核心设计优势
- **单进程单端口会话架构**：大厅匹配与对局模拟运行在同一进程、同一 ENet UDP 端口内。房间满员开局时，`RoomManager` 直接将 `MatchSession` 节点挂载进场景树，客户端全程保持既有连接，无需断开转连其他 Worker 进程，彻底消除了进程间切换的网络断点与延迟。
- **全链路操作系统端口动态分配**：服务端服务端口 `P`、客机出站转发端口 `Q` 以及 EasyTier RPC 管理门户端口全部直接向操作系统动态申请（通过 bind/listen `127.0.0.1:0` 获取系统临时空闲端口后释放），杜绝硬编码与静态区间盲选冲突，单机双开客户端互连自测零端口碰撞。
- **用户态端口映射 (No-TUN)**：底层使用 EasyTier 内嵌的 smoltcp 用户态网络栈，将虚拟网流量映射至回环网络。客机本地动态向操作系统申请空闲端口 `Q`，透明转发至房主虚拟 IP 对应的端口 `P`，对游戏网络层完全透明。
- **全纯 UDP 数据面优化**：EasyTier 仅保留 UDP 监听端口（`-l udp://0.0.0.0:0`，`--default-protocol udp`，禁用 TCP 打洞），避免 ENet 数据包在 TCP mesh 中产生队头阻塞（彻底解决实测 511ms 延迟尖峰），配合 BBR 拥塞控制与最低延迟优先策略（`--latency-first`）。
- **零管理员提权 (No-UAC)**：完全基于用户态网络套接字运行，不安装系统级虚拟网卡驱动，双击即玩，启动零弹窗。
- **NAT 穿透与中继容灾**：通过初始共享节点交换端点，优先通过 STUN 完成 NAT 打洞建立 P2P 直连通道；在对称型 NAT 等无法直连的网络环境下，自动通过中继节点传输数据保底。

## 二、 目录结构与依赖管理

### 1. 文件与资源目录

```text
The Cyancular Ruins.exe             # 游戏客户端主程序
Cyancular Ruins Server.exe          # 独立服务端程序（房主建房时自动拉起）
easytier/                           # 隧道核心依赖目录（四件套缺一不可）
  easytier-core.exe                 # EasyTier 2.6.4 隧道核心通信进程
  easytier-cli.exe                  # EasyTier 命令行控制工具（查询 peer 与配置转发）
  Packet.dll                        # 核心动态链接依赖库（静态导入，缺失将报 0xC0000135）
  wintun.dll                        # 备用依赖库
  relay.txt                         # 初始共享节点列表（必需配置，支持自定义公网节点）
log/                                # 运行期日志输出目录
  client.log                        # 客户端主日志
  server.log                        # 本地服务端日志
  client.old.log                    # 客户端历史日志（单文件超 2MB 自动轮转归档）
  server.old.log                    # 服务端历史日志
  easytier-host-<pid>/easytier.log  # 房主端隧道日志（按父进程 PID 隔离）
  easytier-guest-<pid>/easytier.log # 客机端隧道日志
```

### 2. 依赖完整性与缺失防御
- **静态 DLL 依赖校验**：`easytier-core.exe` 静态导入 `Packet.dll`。若缺少该 DLL，Windows 将直接抛出 `0xC0000135` 异常退出且无标准输出，导致客户端报错表现与“打洞失败”完全相同。因此，`Tunnel.available()` 在运行前强制校验四件套文件完整性。
- **初始节点机制与 relay.txt**：EasyTier 没有内置默认对等节点，亦不进行跨主机自动广播发现。联机双端**必须配置同一个可访问的初始共享节点**。节点配置唯一定义于游戏目录下的 `easytier/relay.txt`，代码中不硬编码任何私有服务器地址。若文件缺失，系统会自动生成纯注释模板并提示玩家。
- **日志隔离与孤儿清理**：EasyTier 默认写入 `easytier.log`。为避免同机多开（房主与客机共存）产生写锁冲突，系统按角色及父进程 PID 创建独立子目录（`log/easytier-<角色>-<pid>/`）。启动隧道前，`Tunnel._reap_orphans()` 会自动检测目录尾部的父进程 PID，安全回收已终止游戏的残留孤儿内核，并保留最近 25 份日志供排查诊断。

## 三、 端口分配与服务端生命周期

### 1. 本地专用服务端启动 (`core/net/local_server.gd`)
房主创建房间时，客户端在后台拉起专用的无头服务端进程：
1. **操作系统动态分配端口**：直接向系统请求分配空闲 UDP 端口（`PacketPeerUDP.bind(0, "127.0.0.1")`，从操作系统动态端口池获取临时空闲端口号 `P` 之后立即释放），通过 `--port P` 参数拉起 `Cyancular Ruins Server.exe`，结构上杜绝端口碰撞。
2. **本地探活机制**：客户端调用 `NetBus.can_send_to_server()` 轮询探测 `127.0.0.1:P`。子进程因异常退出时会立即反馈失败并重新申请端口（最多重试 8 次）；若 10 秒内未监听且进程存活，判定为防火墙拦截并给出明确提示。
3. **连接直接复用**：本地探活建立成功后，该 ENet 连接直接保持并作为房主的大厅会话，无需拆除重建。

### 2. 单进程单端口架构 (`server/server_main.gd` + `server/room_manager.gd`)
- **同进程对局编排**：服务端主入口为 `server_main.tscn`，监听唯一的 UDP 端口 `P`。
- **开局与收局**：房间凑齐玩家或房主点击开局后，`RoomManager` 直接创建并挂载 `MatchSession` 节点。对局结束触发 `MatchSession.finished` 信号，`RoomManager` 作废凭据并销毁会话。
- **超龄清扫兜底**：`RoomManager` 每 10 分钟执行一次清扫，解散存在超过 2 小时的陈旧房间。

## 四、 房间编码、发现与端口转发

### 1. 5 位数字房间码设计
- **无偏随机生成**：房间码采用 5 位纯十进制数字字符串（`00000`~`99999`，通过 `randi_range(0, 99999)` 拒绝采样消除模运算偏置），前导零合法有效。
- **网络契约映射**：
  - EasyTier 网络名称：`cyr-<5位房间码>`（例如 `cyr-48213`）
  - EasyTier 访问密码：`<5位房间码>`
  - 虚拟网段：`10.126.126.0/24`（房主固定使用 `10.126.126.1`，客机使用 `--dhcp` 自适应分配，规避家用局域网常见网段）。

### 2. 端口传递通道与客机解耦转发
1. **元数据主机名传递**：房主启动内核时将服务端口写入主机名（`--hostname cyr-host-P`）。
2. **客机自动发现**：客机加入房间后，轮询 `easytier-cli peer`，解析主机名为 `cyr-host-` 前缀的对等节点，提取房主虚拟 IP 及真实服务端口 `P`。
3. **客机空闲端口绑定 (Q ≠ P)**：为支持同机多开联调，客机**不使用 P 作为本地转发端口**，而是使用 socket 绑定 `127.0.0.1:0` 由操作系统动态分配一个空闲端口 `Q`，随即释放并下发出站转发指令：
   ```text
   easytier-cli port-forward add udp 127.0.0.1:Q 10.126.126.1:P
   ```
4. **客户端连接**：客机游戏客户端直连回环地址 `127.0.0.1:Q`，流量由 EasyTier 用户态 NAT 代理送至房主服务端。

## 五、 多人对局同步与权威仲裁

### 1. 客户端预测与权威回滚 (C2 Rollback)
- **输入序列与回滚**：客户端本地运行物理预测，将玩家输入打包附加序号发送至服务端。服务端以 60Hz 频率向下广播世界渲染状态与个人权威状态（包含 `ack_seq`）。
- **接触期自适应容差**：两角色在近距离碰撞缠斗时，物理接触会将位置容差由平常的 `2.0px` 自动放宽至 `8.0px`，消除频繁触发预测回滚引起的画面抖动。远端玩家在本地生成幽灵碰撞体参与滑动摩擦，保持打击手感真实。
- **60Hz 拆分广播**：服务端将广播包解耦为：
  - `snapshot_world`（单次序列化不可靠广播全员坐标、朝向、姿态与动画状态）；
  - `snapshot_self`（定向发送各角色专用的权威物理状态与输入确认，不产生 $O(N^2)$ 带宽开销）。

### 2. 多人玩法模式规范
- **1v1 回合对决 (Duel)**：抢五胜制，局间两队对调出生点，换局时重置场景瓦片基线与动态投射物。
- **自由大乱斗 (Royale)**：限时 300 秒击杀争夺。采用**三级动态复活点选点算法**（开阔候选池、降级备用池、极限连通池），要求连通区域大于自适应门槛且与存活对手保持 8 格避让距离，彻底杜绝在封闭死角复活；支持 AI 机器人自动补位与 3 秒击杀归因。
- **3v3 团队对抗 (Team)**：
  - 分队碰撞层实现**友军物理穿透**：1 队 `layer=2, mask=1|4|16`；2 队 `layer=16, mask=1|2|4`（掩码中严格保留地形 1 防止穿墙）。
  - 子弹穿透队友，爆炸武器 AOE 伤害无差别结算。
  - 队伍颜色自适应着色：依据基准主色计算比例，防止纹理发灰发暗。
- **Beta 时间玩法**：
  - **服务端权威粒子经济 ([TimeEconomy](file:///d:/Codes/Antigravity/cyr/server/time_economy.gd))**：每个角色独立维护 `GrainAccount`，通过击杀敌方、造成伤害、破坏 16px 子格与自然恢复累积粒子，10Hz 下发镜像数据。
  - **个人专属加速与回溯**：加速仅对发动者生效（初速与射速提升），其他玩家视角呈现「▶▶ 3x」标识；回溯者进入无敌状态，沿 12s 快照历史轨迹倒退，倒流子弹穿过敌人照常结算二次伤害。

## 六、 断线重连与会话准入控制

系统实现了完整的两阶段断线恢复机制：

### 1. 阶段 1：局内快速闪断重连
- **60 秒统一宽限期 ([GraceWindow](file:///d:/Codes/Antigravity/cyr/core/net/grace_window.gd))**：当网络短暂波动导致底层连接中断时，服务端保留玩家角色实体与内存状态，暂停其输入队列。
- **原端口直接认领**：客户端自动在原端口尝试重连并发送 `reclaim_role`，重连成功后通过 `match_sync` 补发断线期间被破坏的瓦片与地面武器列表，世界无缝对齐。
- **模式到期分派**：大乱斗与 3v3 宽限到期后移除角色、其余人继续战斗；1v1 宽限到期则直接判定对手获胜并结束对局。

### 2. 阶段 2-B：退回大厅后的房间断线重连
- **凭据注册表 ([RejoinRegistry](file:///d:/Codes/Antigravity/cyr/server/rejoin_registry.gd))**：开局时为每位玩家生成 16 位 Hex Token，映射至递增局号 `match_id`、角色与过期时间（TTL 1 小时）。凭据脱离房间独立存活，避免因房间销毁导致状态丢失。
- **大厅列表交互**：玩家退至主菜单后重新进入大厅，其所属的进行中房间会点亮重连入口。点击后客户端通过 `rejoin_request` 向大厅请求重连凭据，大厅校验放行后进入对局并认领席位。
- **准入控制与防碰撞**：进行中的房间对未持有凭据的外部玩家显示“对局进行中无法加入”，防止外部人员误入；凭据以局号为键作废，防止不同模式同名房间号冲突误删。
