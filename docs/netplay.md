# 联机系统

服务端以 60 Hz 推进权威世界，常规 `STATE` 为 30 Hz，有击退或受击倒地的中间 tick 也发送状态。伤害、地形、拾取、复活和胜负由服务端结算。

| 模块 | 职责 |
|---|---|
| [RoomSession](../server/room_session.gd) | 席位、开局资格、就绪、断线宽限、重连凭据与消息投递 |
| [MatchRules](../server/match_rules.gd) | 回合阶段、计时、计分、出生和胜负 |
| [AuthorityWorld](../server/authority_world.gd) | 推进物理和战斗，执行换局与复活，采集权威状态 |
| [NetBus](../core/net/net_bus.gd) · [NetCodec](../core/net/net_codec.gd) | 传输派发、连接协议和快照编解码 |
| [PvpMatchClient](../scenes/pvp_match_client.gd) · [PredictionRollback](../core/net/prediction_rollback.gd) | 接纳权威事件和快照、更新世界代理、校正与推进本地角色 |

## 会话与基线

大厅的建房、查询、加入和手动回局与对局的自动重连共用 `NetSession` 的连接和应答超时。房号、模式、角色和令牌都从最近一次收到的房间状态读取。对局返回主菜单时保留中继和席位凭据，可在大厅重新进入。 [连接会话](../core/net/net_session.gd) · [房间状态](../core/net/pvp_session.gd)

每个服务端进程在同一 UDP 端口承载一个房间及其对局。大厅的 `LIST` 请求携带玩法标记，`ROOM_LIST` 返回该端点的房间或空结果。初次进场和重连的 `BASELINE` 包含原始地图字节，客户端可以直接解析建图。新回合沿用已安装的地图，恢复初始地形后应用权威差异。同一轮基线广播共用全部角色状态、地图差异与回合数据。

新回合从 `WAITING` 开始，计时为 0。客户端安装基线和碰撞后发送带回合号的 `READY`。席位全部就绪时进入 3 秒 `COUNTDOWN`，随后开始 `PLAYING`。局中重连的 `READY` 恢复该席位的快照发送。`WAITING` 中非房主席位离场会取消未开打的对局。开局和结算规则见 [对战模式](modes.md)。

断线后保留角色和席位 60 秒。客户端在 60 秒重连窗口内按次重试，连接后提交房间号与令牌获取基线。同回合重连沿用已加载地图，应用权威地形和角色状态。

## 消息与快照

游戏协议版本为 25，前缀为 `[199, 25]`，字段采用小端序。客户端与服务端需使用同一版本，因为预测依赖相同的碰撞规则。GNS 传输层有独立的 `GNS` 版本头，当前为 2。

| 流 | 通道 | 内容 |
|---|---|---|
| `INPUT` | 0，非可靠 | 最近 4 帧持续输入、未确认动作和 STATE ACK |
| `STATE` | 1，非可靠 | 公共世界、各角色状态及输入确认、接收者输入时序与地形版本 |
| `EVENT` | 2，可靠且通道内保序 | 房间信令、基线、地形、回合、弹丸与战斗事件 |

各通道独立到达。`NetBus` 可以合并同一派发区间内的连续 `STATE`，可靠事件会结束该区间。地形版本更高的 `STATE` 等待补丁，客户端复算光束前先提交已收到的地形更新。`FIRE` 在命中结算前广播出手 tick、角色、射击序号和发射参数。`EXPLOSION` 与 `BULLET_END` 确认弹丸终止。`HIT` 逐次发送权威伤后生命值、位姿和速度。覆盖命中 tick 的 `STATE` 接管。

每个连接独立维护序号、ACK 和最多 64 份快照。差分相对接收者确认的基线。基线缺失时丢弃差分并以 ACK 0 请求全量。公共差分按基线和角色表复用。每个角色使用同一套模拟状态，包括着地、装备、持续输入、回溯标记和计划复活 tick。私有 `own` 携带输入时序反馈。装备实例 ID 变化时发送完整装备状态。活弹快照只带类型、位置和速度，行程、引信与直击标记由模拟算出。Beta 账户快照包含余额、短期已用量、透支量与锁定状态，容量与倍率随开局规则发送。

`GnsEndpoint` 在提交时用 Fast LZMA2 编码，压缩结果较小时发送压缩数据。广播共用编码结果。可靠消息按顺序提交，超过单条 GNS 上限时分块。原生层在重组与解压前检查长度，单条消息的解码上限为 64 MiB。暂时无法提交的可靠帧留在队列，实时通道各保留最新待发包。原生轮询最多处理 256 条消息，单次收包和脚本派发各用 512 KiB、2 ms 的软预算。 [传输实现](../native/gns/gns.cpp)

## 输入与预测

输入按 epoch、序号和目标 tick 调度。`STATE` 中的角色记录用 `input` 的序号确认持续输入，用 `action_ack` 确认单次动作。持续输入在目标 tick 后保留 6 tick，动作超过 12 tick 后确认并丢弃。迟到且仍有效的输入移到下一 tick，未来窗口为 32 tick。客户端用同一份输入包发送并推进本地预测。 [输入缓冲](../core/net/input_buffer.gd)

每个物理步先应用可靠事件，再接纳地形版本可用的最新 `STATE`。预测保存 64 tick 的角色模拟状态、输入续接点和 Beta 账户，领先权威最多 32 tick。快照改变模拟状态或延长已用完的预测范围时，从权威快照重放到原预测末端。新本地 epoch、检查点超窗、权威 tick 领先或本地处于玩法回溯时直接对齐权威锚点。新 epoch 会清除该角色的旧输入。

角色出手和收到的 `FIRE` 都在角色移动后进入战斗步进。相同射击 ID 以确认的发射参数和 tick 为准。客户端复用弹丸运动、命中查询和爆炸延时来预测击退，生命值、倒地与地形损伤由权威消息确认。重放期间跳过一次性音画。 [预测步进](../core/net/prediction_rollback.gd)

预测和重放与服务端按同一角色顺序运行 `ActorStep`。远端角色复用着地、重力、加速、台阶、连射及装备状态，沿用最近确认的持续输入，最多前推 6 tick。后续快照提供新的输入和状态；拾取、丢弃和主动回溯由服务端处理。确认倒地在命中 tick 结束时更新碰撞体，计划复活 tick 结束时停用旧碰撞，等快照确认复活位置。远端表现缓冲以 6 tick 为目标延迟，最多外推 6 tick。 [远端插值](../core/net/snapshot_buffer.gd)

## 本地服务与隧道

客户端建房时启动本游戏的无头服务端。服务端、转发和 EasyTier 控制端口动态选取。EasyTier 通过每次会话的临时配置目录以 `no_tun = true` 转发 UDP，压缩由游戏传输层处理。大厅补齐缺失的 `relay.txt` 并保留已有配置。加入房间时，节点查询、找房主和 UDP 转发失败各有对应提示。macOS 发布版使用用户数据目录，其他运行方式使用 EasyTier 组件目录。 [隧道](../core/net/tunnel.gd) · [组件与发布](../RELEASE.md)

`NetSession` 持有游戏启动的后台进程。Windows 用 Job Object 回收子进程，macOS 用独立进程组和寿命管道。客户端退出时关闭会话并回收进程。 [进程管理](../core/net/net_session.gd)
