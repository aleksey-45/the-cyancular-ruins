# 联机系统

对战采用服务器权威模式。服务器以 60 Hz 更新对局，确认生命值、击退、地形破坏、拾取、复活和胜负。状态快照通常以 30 Hz 发送，击退和受击倒地也可在中间的模拟帧触发发送。

| 模块 | 职责 |
|---|---|
| [RoomSession](../server/room_session.gd) | 作为服务端场景根节点启动监听，管理成员、开局校验、就绪、断线宽限及重连凭据。每个物理帧调用当前对局的 `step()` |
| [MatchRules](../server/match_rules.gd) | 回合阶段、计时、计分、出生点和胜负 |
| [AuthorityWorld](../server/authority_world.gd) | 按固定步长推进战斗、回合和复活，生成服务器快照。终局后保留结算结果直到返回房间 |
| [NetBus](../core/net/net_bus.gd) · [NetCodec](../core/net/net_codec.gd) | 收发和分发消息，编解码输入、事件及状态快照 |
| [InputScheduler](../core/net/input_scheduler.gd) · [InputClock](../core/net/input_clock.gd) | 服务端接收带首次目标帧的输入并产生时序反馈。客户端接收反馈，为新输入排帧并返回本步预测终点 |
| [PvpMatchClient](../scenes/pvp_match_client.gd) · [PredictionRollback](../core/net/prediction_rollback.gd) | 应用服务器消息，更新远端角色，预测和校正本地状态 |

## 房间与对局

一个服务器进程在同一个 UDP 端口处理一个房间和对应的对局。大厅用 `LIST` 查询端点，附带普通或 Beta 玩法标记。`ROOM_LIST` 返回对应房间的信息或空结果。客户端根据最近的房间消息保存房间号、模式、角色 ID 和重连令牌。返回主菜单时保留隧道与重连凭据，可以从大厅重新加入。[连接与超时](../core/net/net_session.gd) · [房间资料](../core/net/pvp_session.gd)

首次进场和重连时，服务器以 `BASELINE` 发送原始地图字节、房间选项、角色状态、地形差异和回合状态。同一回合重连时，客户端可复用已加载的地图。新回合的基线复用同一地图，客户端先恢复初始地形，再应用服务器差异。`player_collision` 随房间选项发送，服务器和客户端据此使用相同的移动碰撞遮罩。

新回合从等待就绪（`WAITING`）开始。客户端加载地图、地形碰撞和角色后发送带回合编号的 `READY`。全部玩家就绪后进入 3 秒倒计时（`COUNTDOWN`），结束后开始交战（`PLAYING`）。局中重连后，`READY` 恢复该连接的快照发送。在等待就绪期间移除非房主玩家会取消当前对局。[对战模式](modes.md)

断线后，服务器保留角色和房间席位 60 秒。对局客户端在 60 秒内分次重试连接。连接成功后用房间号和令牌发出 `REJOIN`，服务器为该角色更新输入版本号并发送基线。

## 消息与快照

游戏协议版本为 35，消息前缀为 `[199, 35]`，多字节字段使用小端字节序。客户端与服务端需要同时更新。GameNetworkingSockets 扩展使用独立的 `GNS` 传输头，版本为 2。

| 消息 | 通道 | 内容 |
|---|---|---|
| `INPUT` | 0，不可靠 | 最近 4 份持续输入、未确认的单次动作、每份记录的首次目标帧，以及状态快照确认序号 |
| `STATE` | 1，不可靠 | 角色和世界状态、输入确认、接收方输入时序与地形版本 |
| `EVENT` | 2，可靠且通道内按序送达 | 房间与回合消息、基线、地形和战斗事件 |

各通道独立到达。`NetBus` 可合并同一连接尚待分发的多个 `STATE`，保留序号最大的快照。可靠事件和连接通知分隔合并范围。引用较新地形版本的快照会等到对应的地形更新可用。[消息分发](../core/net/net_bus.gd)

`FIRE` 在伤害结算前发送攻击参数。蓄力和弹丸速度倍率只有偏离默认值时才编码。`EXPLOSION` 记录引爆的位置、类型、弹丸 ID 和模拟帧，`BULLET_END` 确认弹丸终止。`HIT` 发送中弹后的生命值、位置、朝向和速度。覆盖命中帧的 `STATE` 到达后，以该快照为准。

每个连接独立维护发送序号、确认信息和最多 64 份快照。增量快照以接收方确认过的快照为基准。找不到基准时，接收方丢弃该增量并用确认序号 0 请求完整快照。基准快照及角色列表一致时，多个连接共用公共状态的编码结果。

每个角色的快照包含模拟状态、持续输入和动作确认、输入版本号、回溯标记与计划复活帧。接收方专用的 `input_feedback` 是调度器产生的字节串。基线携带完整字节串，状态增量只在相对已确认基准有变化时替换它。手持武器实例变化时发送完整武器状态。仍在运动的弹丸按 ID 索引，以 `[type_id, pos, vel]` 传输，行程和引信由模拟更新。仍可见的光束按射击 ID 记录消失的物理帧号和折线上的各个点。两个集合都按字段发送增量，内容与基准相同时省略。Beta 账户按角色 ID 索引，依次记录余额、短期额度用量、透支量和锁定状态。[快照编解码](../core/net/net_codec.gd)

原生传输层尝试用 Fast LZMA2 压缩消息，结果较小时发送压缩数据，否则发送原数据。同一条广播共用编码结果。可靠消息按顺序排队，超过单条 GNS 消息上限时分块。每条消息最多解码 64 MiB。暂时无法提交的可靠消息留在队列，不可靠通道各保留最新待发消息。原生层每次轮询最多处理 256 条消息，轮询与脚本分发分别使用 512 KiB 和 2 毫秒的软预算。[原生传输](../native/gns/gns.cpp)

## 输入与预测

客户端按固定物理步采样。每份输入在第一次排帧时绑定 `epoch`、序号和目标帧，冗余副本及回放沿用同一个目标。每个输入包都能独立解码。持续输入在包内对“目标帧减序号”做增量编码，单次动作携带绝对目标帧。服务端校验版本和时间窗口，将有效记录交给原有输入缓冲区。新到的反馈只影响未来采样。复活、结束个人回溯和重连开启新输入版本。

服务端通过 `submit` 接收输入，快照原样转发它给该玩家的反馈。客户端预测器只需要在基线时初始化时钟、在快照到达时同步，然后为采样取得目标帧和模拟终点。收包分位数、反馈年龄、调速倍率以及选择何时补一步或少走一步，都由时序模块管理。所有武器沿用相同的帧号语义。[权威输入调度](../core/net/input_scheduler.gd) · [本地预测时钟](../core/net/input_clock.gd)

持续输入可沿用至目标帧之后 6 帧。单次动作超过目标帧 12 帧后仍确认序号，但跳过执行。有效的迟到输入移到下一帧，缓冲区接受未来 32 帧以内的输入。`STATE` 的角色记录用 `input` 确认持续输入，用 `action_ack` 确认单次动作。所有武器都从同一权威步取用输入。[输入缓冲区](../core/net/input_buffer.gd)

客户端每个物理帧先处理可靠事件，再选取地形版本可用的最新 `STATE`。采样和发包仍按 60 Hz 进行。预测器按时钟给出的终点推进固定模拟步。新按键或移动方向发生变化时，时钟优先给它一个立即执行的本地步。少走一步时，将持续输入排到尚未模拟的下一帧，同帧采样由原缓冲区合并。预测最多领先服务器 32 帧，保留最近 64 帧的模拟检查点。预测帧复用世界回溯的战斗检查点，保存角色、最近的持续输入与动作确认、弹丸运动、可见光束和待结算爆炸，再附上 Beta 账户和当帧射击。爆炸记录包含类型、位置和结算帧。[战斗检查点](../core/sim/combat_snapshot.gd) · [预测帧](../core/net/prediction_frame.gd)

校正时比较同一模拟帧的预测和服务器状态。位置按跨边界的最短距离测量，偏差小于 0.1 像素且其他需要比较的字段一致时，可继续使用预测结果。存在需校正的差异或远端预测范围扩大时，从服务器快照重放到原来的预测进度。输入版本变化、检查点超出缓冲范围、服务器帧领先或本地角色使用时间回溯时，客户端直接采用服务器状态。输入版本变化同时清空该角色先前的输入记录。[预测回滚](../core/net/prediction_rollback.gd)

发射、命中、弹体终止、爆炸和地形更新按帧进入预测器。已模拟帧收到有变更的事件时，从权威检查点重放。发射帧使用当时的地形计算光束路径，地形补丁在所属帧末生效。重放不会重复播放一次性画面和音效。地面武器快照直接记录受限角色 ID 和解除限制的完整模拟帧号。本地提示与服务器拾取共用距离、装备类型和时限判定。

服务器和客户端预测都按角色 ID 顺序运行 `ActorStep`。远端角色沿用最近确认的持续输入，最多预测 6 帧。远端角色的拾取、丢弃和时间回溯使用服务器结果。客户端在计划复活帧结束时停用该角色的旧碰撞体，等快照确认新位置。

远端播放时钟按已可用快照的时间分布每四分之一秒更新目标余量，以 0.85–1.10 倍的连续速率靠近目标。两份快照间对位置和速度插值，等新快照时最多外推 2 帧。其余显示字段直接取自选中的服务器快照。[播放时钟](../core/net/snapshot_clock.gd) · [远端快照缓冲](../core/net/snapshot_buffer.gd)

## 本地服务器与隧道

客户端建房时启动无界面的游戏服务器，动态选取游戏端口。加入方通过 EasyTier 节点列表查找房主，再把本机 UDP 端口转发到房主的游戏端口。EasyTier 的控制端口和转发端口动态选取。每次会话使用临时配置目录，以 `no_tun = true` 运行应用层转发。游戏传输层负责消息压缩。

大厅在 `relay.txt` 缺失时生成初始节点列表。macOS 发布版把它放在用户数据目录，其余运行方式放在 EasyTier 组件目录。Windows 使用 Job Object 管理游戏启动的后台进程，macOS 使用独立进程组和随父进程关闭的管道。退出游戏时关闭会话并清理子进程。[EasyTier 隧道](../core/net/tunnel.gd) · [进程管理](../core/net/net_session.gd)
