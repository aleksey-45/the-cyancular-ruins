# 测试 / 探针 / 守卫的写法

> 本页只讲**怎么写**。保留 / 删除的判据在 [`test-economy.md`](test-economy.md)(唯一真相源);怎么跑、判词、跑批纪律在 [`tests.md`](tests.md) 与 [`tests/README.md`](../../tests/README.md)。
> 一句话:这个仓测的是**行为**,不是"代码长什么样";每条断言都要能回答「去掉什么它才会红」。

## 1. 先选桶:按"要什么资源",不按"测多少代码"

| 桶 | 目录 | 要什么 | 判词形态 |
|---|---|---|---|
| **单元**(`-s`) | `tests/unit/` | 单进程;autoload 未实例化;不碰网络/磁盘/真场景 | `… OK(n)` / `… ALL-OK` |
| **场景探针** | `tests/scene/` | 真实例化 `.tscn`;走 `_ready`/信号/资源加载 | 同上 |
| **端到端** | `tests/e2e/` | 真端口、真子进程、真协议 | `SMOKE PASS` / `… ALL-OK` / `RUN_REAL OK` |

选错的代价:纯逻辑写进场景探针 ⇒ 慢、且被渲染路径污染;场景行为写进 `-s` ⇒ autoload 未实例化,静态引用会在编译期炸。

## 2. 文件与断言的粒度

- **一个文件 = 一个失败域**(例:编辑器文档模型 / 选区与剪贴板 / IO 与校验),不是"一个类的所有东西"。
- **一个断言 = 一个缺陷**。失败信息必须写清"期望 vs 实得",并且**指向去哪修**(文件名 + 函数 + 判据)。
- 单文件超过 **~60 条断言**或 **~600 行**就该问:"它是不是两个失败域?"(不是硬上限;`test-economy` D8 有正式判据)。
- **禁止恒真断言**(`_check(true, "")`、`_check(x == x)`):它只买条数,不买保证。if/else 两个分支都断言时,两边的消息都要能指向缺陷。
- 每条新断言先答「**去掉什么它才会红**」;答不出就不写。

## 3. 条数闸:每支自带

- 场景探针 / 冒烟:`const EXPECTED_CHECKS := N`,跑完自检 `_checks == N`。
- ★ `ALL-OK` 只证明"没有断言失败",**不证明每条断言都跑过**(脚本错误只中止出错函数,调用方继续)。没有条数闸的 `ALL-OK` 等于"没输出"。
- 端到端(`.sh`)没有 `EXPECTED_CHECKS` 时,判词必须是**唯一一行**、且脚本失败时**不能**打出它。

## 4. 断言该写什么

| 写 | 不写 |
|---|---|
| 行为:返回值、状态迁移、帧间不变量、序列化往返 | 源码里的字面量("有没有写那段字") |
| 契约:协议键集、快照往返、命中几何、环面最短差 | 引擎/框架自己的行为 |
| 承重面:回滚等价、输入包、存档/地图格式、导出裁剪 | 配色 / 版式 / 手感 / 观感(只能人眼) |
| 一条判定类别一条守卫 | 一个数值一条断言(拆成 N 条) |

**源码文本守卫**(读 `.gd` 文本判形态)默认不写。只有当"顺序 / 接线"承重、又**没有廉价的行为观测**时才允许,且必须:

1. 在函数头写明「**代理判据:读源码文本,不是行为;行为证据见 `<真链路脚本/探针>`**」;
2. 判词不可读成"功能没问题";
3. 每次搬家/改名都要复核(它最容易因"位置变了"而红)。

## 5. 确定性测试

- 回滚 / 重放:先取快照 → 跑固定输入 → `restore` → 同输入重放 → **逐帧 pos/vel 精确相等**;失败时给出第一处分歧帧。
- 大数组比 checksum(FNV/哈希)优于逐帧向量数组——但**首次失败定位**要能落到帧号。
- 随机:必须 `seed(...)` 固定;不要依赖帧率、墙钟、节点顺序。
- 时间:用 `await get_tree().physics_frame` / `process_frame`,**不要 `sleep`**。

## 6. 夹具与共享

- 可复用的纯逻辑夹具放 `tests/lib/`(如 `scan_util.gd`);状态型辅助(信号计数、watcher)留在使用它的文件里,别做成全局单例。
- 需要真实场景时实例化 `.tscn` 并 `set_physics_process(false)` 之类的"冻结"手段由用例自己负责;用例结束前 `queue_free()`。
- fixture 文件放 `tests/fixtures/`,并用 `path_integrity` 覆盖"引用的文件真的存在"。

## 7. 框架立场

**不引入 GUT / gdUnit4。** 本仓的判据是"脚本自打判词 + 聚合入口 grep",已经覆盖了游戏工程需要的三层(纯逻辑 / 场景 / 端到端);换框架要重写全部探针,还会把"资源桶"的边界藏进框架里。可借用它们的两个思路:

- **参数化**(表格驱动):同一判据多组输入时写数据表,不复制函数;
- **mock / spy**:只在"外部 IO 无法在 headless 里跑"时用,优先换成注入端口(见 `PlayerPickup` 的双 Callable)。

## 8. 目录与命名

- 桶看目录(见 §1);`lib/` 只放夹具/基类,`fixtures/` 只放输入数据;`.sh` 只能出现在 `e2e/`。
- 命名:`*_smoke` = 单元;`*_probe` = 场景/端到端;`.tscn` 与 `.gd` 同 stem;`probe_id()` 返回短名,判词用它。
- 新增/改桶时同步 `tests/README.md` 的"文件分层"表;支数与闸值**不抄**,以 `--list` 为准。

## 9. 一次改动的验收顺序

1. 单支跑:判词行出现 `OK` / `ALL-OK`;
2. 默认批:`RUN_ALL OK(n runs / m gated-assertions)`;
3. 碰承重面(协议/回滚/命中/导出)再加真链路批:`RUN_REAL OK(n entries)`;
4. 每条承重断言至少一次变异(去掉它必须红),变异后回滚再跑绿。

## 10. 覆盖形状:按风险分配,不按"容易测"

- **优先承重面**:协议 / 输入包 / 回滚与快照 / 存档与地图格式 / 导出裁剪 / 命中与碰撞。这里的断言挡的是"很久以后才发现"的缺陷。
- **可测但不承重的域**(编辑器、版式、纯 UI)冻结新增断言,除非是在修一个真实事故;它们已经占了这个仓约 40% 的断言。
- 新增断言前先答两个问题:① 去掉什么它会红?② 它挡的是**哪一次真实事故**或**哪条登记的债**?答不出就不写。
- 大数组比较优先 checksum(注意首次失败要能落到帧号);不要用"逐帧全量数组"当默认手段。
