## 3. ★★ 本批真正的产出:一条判据纪律

**两个并发会话在这一天里各自撞上同一个形态 —— 至少十次。** 现在它在 `CLAUDE.md` 与本档里都有落点。

> **任何判据(文本 / 计数 / 单侧断言 / 进程检查)能给的保证,都窄于它读起来的样子;
> 而它的失明方向恒为绿 —— 所以"跑一遍"发现不了。**

十次取样(都真实发生):

| 声称 | 实际 |
|---|---|
| 「断言增量 +4」 | 有 4 个 `_check(` 调用点,但**一个在早退后永不执行** ⇒ 实际 +3 |
| 报到梯的 smoke「验证了」 | 它起的是 worker,**结构上看不见大厅模式** ⇒ 大厅自杀那条它全绿 |
| 「`!= PLAYING` 会让 PLAYING 也停记账,`death_drop_probe` 守住了」 | `!= PLAYING` 在 PLAYING 下**为假**;差集是 `{ROUND_OVER, COUNTDOWN}`,而那一格**没有守卫** |
| 相②「覆盖了未入树窗口」 | 只有负向半;删 `_mag_ready = true` 会让**已上线功能静默消失**而全仓不红 |
| 守卫「对改名/重排/抽 helper 免疫」 | 实测**取首合取项** + 全文件 `contains` ⇒ 后两者是**假红** |
| 审阅者建议的 `contains("1800")` | **恒真**(同文件另有 `TEAM_MATCH_ESTIMATE := 1800.0`) |
| 上界链「两环都钉着」 | 有**第三环**(值的写点不钳位;worker 侧完全不钳) |
| `#6a`「接线两半」 | **写入端一行都没有**:删掉它,原 bug 原样回来而全仓不红 |
| ROUND_OVER 相「把承诺钉住了」 | `== MATCH_OVER` 与 `== PLAYING` 的差集是两格,只钉了一格 |
| `git status`「只许有自己那一个文件」 | 别人的 hunk 落在**你的文件**里时逐字相同 ⇒ **必然放行** |

**两条可直接执行的规矩**(从十次里提炼):

1. **用 `== A` 表达"不是 B"的断言,把被排除的那一集(`B \ A`)写进判词。**
   补一条相只解决这一处;写进判词,下一个人才当场看得见边界在哪。
2. **提交前逐文件 `git diff` 认领每个 hunk** —— 跨会话共享工作树时,`git status` 只挡"别人的文件"。
   同理:审阅包用 `git show <本任务的提交>` 逐个拼,不用 `BASE..HEAD`(会把并发会话的提交带进来)。

## 4. 本条线上被抓住的两个**自身**引入的严重缺陷

1. **#10 的分支会打死专用大厅。** 条件写成**三个否定的合取**,而大厅进程里那三项**全成立** ⇒
   `start_server.bat` 起的大厅**开机 30 秒后 `quit(0)` 自杀**,7777 上的一切随之死掉。
   新增的 smoke 起的是 worker,**结构上永远看不见**;由审阅者读 `grep set_process` 零命中发现。
   修法:门取**正的** `_worker` 标志,并在大厅分支加 `set_process(false)`
   (必须用它而不是 `process_mode` —— 后者会沿继承关掉子节点 `RoomManager`)⇒ **整类结构性不可达**,
   实测即使条件写回否定式也照样活到 45 秒。
2. **#6a 的写入端没有守卫。** 探针**自己**注入 `note_disconnect_round(1)`,验的是读取端;
   删掉 `_enter_grace` 里那一行 ⇒ `_leave_round` 永远空 ⇒ 回落旧值 ⇒ 原 bug 原样回来而**全仓不红**。
   ⇒ 行为面补相:out-of-tree 实例化真 `server_main` + 真 `TeamHost`,调真 `_enter_grace`。

**成因表述(最准的一版,值得记住)**:

> **探针把夹具的写入当成了被测行为的一部分,于是被测的那一半从来没被验过。**
