# 64px 砖块 + 0-15 形状掩码设计

日期:2026-08-25
状态:已批准(待实现)

## 背景与目标

当前系统:TILE_SIZE=32,地图 250×150 格 = 8000×4800 世界像素,每格一个 32px 砖块,
格值 0-9/A(0=空气,1-10=10 种砖块纹理)。敌人/寻路/刷怪都在 250×150 网格上按 32px 运行。

目标:**把砖块(方块)大小改成 64×64,同时保持世界与关卡不变**。实现方式是地图格子数
减半到 125×75(125×64=8000, 75×64=4800,世界尺寸不变)。同时让 **半砖(32px)、
1/4砖(32×32)、3/4砖(L 形)** 成为合理、可表达、参与真实碰撞的砖块。

关键决策(经与用户确认):

1. 地图文件 = 125×75,每格 = 一个 64px 砖块,内部 = 2×2 的 32px 子格。
2. 形状掩码 0-15(4 bit,15=全砖,0=空气占位)决定哪些子格是实体 → 半砖/1/4砖/3/4砖。
3. 每格同时保留纹理(1-10,10 种砖)。
4. 内部逻辑网格也全部用 64px(125×75):TILE_SIZE=64,寻路/刷怪/敌人判定都在新网格上。
5. 贴图:现有 structure.png(32px 砖块)最近邻 2× 放大成 64px,作为永久方案(不换新图)。
6. 旧地图(250×150,无标记)加载时自动转换成 125×75;`map/demo.cyrm` 直接转换入库。
7. 编码紧凑(2 字符/格,体积比旧版减半),不做 RLE。

## 核心模型

- 每格 = 一个 64px 砖块,内部 2×2 个 32px 子格。
- 形状掩码 0-15 = 4 bit,每 bit 代表一个子格是否实体:

```
+------+------+
| bit0 | bit1 |   ← bit0=1 左上, bit1=2 右上, bit2=4 左下, bit3=8 右下
+------+------+
| bit2 | bit3 |
+------+------+
```

- 全砖 = 15(4 bit 全置位)。
- 空气 = 0(占位,暂只表示空)。
- 常用形状:
  - 1/4砖:1(左上)、2(右上)、4(左下)、8(右下)
  - 半砖:3(上)、12(下)、5(左)、10(右)
  - 3/4砖:7(缺右下)、11(缺左下)、13(缺右上)、14(缺左上)
  - 全砖:15

- 碰撞语义:形状掩码非 0 即实体(寻路/敌人判定整格为"有墙");实体的物理外形由
  "哪些 32px 子格是实"决定(展开成 32px 子格做矩形碰撞)。

## 文件格式(.cyrm v2)

首行(任一位置)标记 **`# cyrm-v2`** 用于区分新旧格式。每格 **2 字符**:

```
[纹理字符][形状十六进制字符]
```

| 单元 | 字符 | 含义 |
|------|------|------|
| 纹理 | `0` | 空气 |
| 纹理 | `1`-`9`, `A` | 纹理 1-10 |
| 形状 | `0`-`9`, `A`-`F` | 掩码 0-15 |

- 空气 = `"00"`;全砖纹理5 = `"5F"`;左上 1/4 砖纹理3 = `"31"`。
- 纹理字符为 `0` 时形状必须为 `0`(空气);形状为 0 的格一律按空气处理。
- spawn 元数据坐标按新网格:`# player <col> <row>`、`# enemy <type> <col> <row>`。
- 行宽 = 125 格 × 2 字符 = 250 字符。旧格式行宽也是 250(单字符/格),靠 `# cyrm-v2`
  标记区分,不以行宽判断。
- 体积:125×75×2 = 18750 字符,比旧版 250×150(37500)减半 —— 即"压缩"。

## 游戏内部表示

- `current_grid`:125×75,格值 = **packed** `texture * 16 + shape`(0 = 空气)。
  - 辅助函数:`texture_of(v) = v / 16`,`shape_of(v) = v % 16`。
  - 寻路/LOS 沿用 `!= EMPTY(0)` 判定 → 任意实体格(含半砖)视为不可走(对 ~120px 敌人
    而言 32px 缝隙本就过不去,保守判定合理)。
- `TILE_SIZE = 64`:`MAP_WIDTH = 125×64 = 8000`,`MAP_HEIGHT = 75×64 = 4800`。
- `cell_of(pos, ts=64, cols=125, rows=75)` 等环面数学在新网格上运行。

## 游戏侧改动

### Globals/gameParameters.gd
- `TILE_SIZE`:32 → 64。

### Globals/maze_generator.gd
- 新增 v2 解析:`# cyrm-v2` 标记 + 2 字符/格 → packed 格值。
- 旧格式检测与自动转换:
  - 无 `# cyrm-v2` 标记 → 按旧格式(单字符 0-9/A,250×150)解析。
  - 转换:2×2 分组 → 形状掩码(旧实体子格对应 bit 置位)+ 纹理(取组内左上首个实体格的
    纹理);spawn 坐标 ÷2(floor);奇数宽高丢弃多余行列并 push_warning。
  - 旧格值为 1-10(纹理)的整墙 → 新格 = 全砖(shape=15),几何完全一致。
- `map_size()` / `load_map_file()` / `load_spawns()` 统一走"检测→解析(或转换)",返回
  125×75 网格。
- 保持 `EMPTY=0`;`SOLID` 常量改为"任意非 0"(或加 `is_solid(v)` 辅助),确认现有调用
  均以 `!= EMPTY` 判定后无需改寻路代码。

### Scenes/level_0.gd
- **渲染(新)**:
  - 启动时读 structure.png(320×320,顶行 10 块 32px 砖),逐块最近邻 2× 放大为 64px。
  - 对每(纹理 1-10)×(形状 0-15)生成 64px 瓦片:放大后的纹理图,把掩码为 0 的 32×32
    象限清成透明。共 160 个瓦片。
  - 拼成一张 atlas(16 列 × 10 行,64px/格 = 1024×640),用 `Image` + `Texture2D.create_from_image`
    运行时生成。
  - 建 TileSet(tile_size=64,atlas texture_region_size=64),160 个瓦片,瓦片坐标 =
    `Vector2i(shape, texture-1)`。
  - `_paint_maze`:铺 125×75 × 3×3 环面;格值 → `Vector2i(shape, texture-1)`。
- **碰撞(新)**:
  - 形状掩码展开成 250×150 的 32px 子格(每 64px 格 → 2×2 子格,实体子格 = 32px 实心)。
  - 沿用现有贪心合并矩形逻辑(ts=32),覆盖 3×3 环面。矩形位置与世界 8000×4800 对齐。
- **玩家放置**:`pos.x * ts + ts/2`,ts=64。

### 敌人与参数
- 大多参数按像素,不动。只需改:
  - `EnemyParams.BlackBird.teleport_min_tiles` 4→2,`teleport_max_tiles` 8→4(保持
    128-256px 像素距离不变)。
- 复核按格的参数:`FlyBird.path_max_visit`、`escape_search_range` 是搜索预算/上限,网格
  变小后更宽裕,保留即可;若冒烟测试暴露问题再微调。

## 编辑器改动(structure-editor.html)

- 画布网格 = 125×75,每格画 64px 砖(纹理按掩码裁切,空气象限透明)。编辑器内对
  (纹理 × 形状)预计算并缓存 64px 图片(用离屏 canvas 从 structure.png 2× 放大 + 掩码)。
- **调色板**:10 种纹理(2× 放大贴图)+ 空气(swatch 背景改用预计算的全砖 64px 图)。
- **形状面板**:2×2 迷你格(4 个象限,点击翻转对应 bit)+ 预设按钮
  (全砖/上·下·左·右半砖/四个 1/4 角砖/四个 3/4 缺角)。
- 画笔/矩形/油漆桶/橡皮按格操作(整格写入 [纹理,形状]);橡皮 = 空气 `"00"`。
- 结构库 JSON 与编辑器内部网格:格值一律用 packed `texture * 16 + shape`(0-175,与游戏
  一致),`validateGrid` 校验 0-175。
- 导入:`# cyrm-v2` → 新格式解析;无标记 → 旧格式解析 + 自动转换(与游戏一致)。
- 导出:写 v2(带 `# cyrm-v2` 标记)。
- `PLAYER_TILES` = 120/64 = **1.875**(参考图)。
