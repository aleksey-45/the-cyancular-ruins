## 1. 目标与非目标

**目标**：新增第三个联机模式 3v3（团队对抗）。复用 1v1 的回合机与 C2 链路，**队伍维度是唯一的新概念**。

**不做**（写下来是为了防"顺手也做了"）：

- 不做 AI 补位（`AINavigator` 至今"首次实跑待用户验收"）；**不做 2v2/4v4 泛化** —— 队伍规模固定 3。
- 不做新地图；不做观战/回放。
- **不改 `NetBus` 方法表**（硬纪律：与原版服务端逐字节一致）；新 RPC 一律进 `NetBusExt`。
- 不做联机 UI 的版式/配色/字号重做 —— 归第二份规划（§11 是交付给它的契约）。
- **不动 1v1 与大乱斗的既有行为**：`MatchBootstrap` 一行不改，`RoyaleHost` **行为**一行不改（★ 例外的形状已登记：A 册 Task 3 把它的静态出生几何**逐字搬**到 `core/sim/spawn_picker.gd` 并留一行转发 —— 3v3 必须共用同一套"别出生在密封小间"的判据，抄第二份就是本仓明令禁止的那种重复）；**共享层的改动必须满足"空参数 = 原行为"**。

## 2. 事实基础（带行号）

1. **队伍维度是全仓新的**：`server/`、`core/`、`scenes/` 下 `team|ally|friendly` 零命中。role 只有编号语义，唯一的 role→值 映射是昵称（`names`）与色相（`hues`）。
2. **role 号会有空洞、不能推导**：`lobby_rooms.gd:319-323` 取"最小空闲号"且**有人退出不重排**；`RoyaleHost.plan_spawns` 已按"容忍不连续 role"写。→ **队伍必须显式下发**。
3. **两人假设散落 6 处**：`_opponent_of`（`match_combat.gd:200-204` —— "非我即敌"的本体）、`_spawn_cell` 的 `player/player2` 二选一（`match_state.gd:119-122`）、`_reset_survivor`（`match_round.gd:81-94`）、`MatchBootstrap` 的 `role==1 ? s1 : s2`（`match_bootstrap.gd:31`）、`_side_swap`、`scenes/pvp_game.gd` 的 `3 - role`。
4. **友伤钩子为零**：玩家层不在子弹 mask 里（`bullet.tscn:10-11`，mask=5 = 地形+敌人）→ 玩家本来就**不挡子弹**；命中全靠半径裁决（`match_combat.gd:45-53`，只过滤"不是射手"）。爆炸只把 shooter 用于归因、伤害照吃（`explosion.gd:34-57`）。
5. **协议有省事路**：`match_sync` 加字段即可（旧端忽略未知键）；新 RPC 只能进 `NetBusExt`（`net_bus_ext.gd:3-8`），且**不得与 `NetBus` 同名**（`beam_fired` 的重名是"静默 no-op"的先例）。
6. **大厅/worker 的模式开关是二分的**：`teardown_room` 的 `is_royale`（`lobby_rooms.gd:404/415/421-430`）、两个端口延迟常量（`worker_launcher.gd:31/:38`）、`_sweep_stale_rooms` 的 royale 分支、`server_main.gd:259-270` 的两条超时梯（20s 降级开局 / 10s 退出）。
7. **6 人局的已知放大点**（两条本来就"未实测"的风险，人数 2 → 6 是 3 倍）：快照每条 `c2` 逐 peer 定向（O(N) 而非 O(N²)）、`hit_event` 每次伤害都定向发（`match_combat.gd:194`）、输入队列**每物理 tick 恰好消费 1 包**且无上限无丢弃。

## 3. 规则（产品口径）

| # | 规则 | 取值 |
|---|---|---|
| 1 | 队伍规模 | 每队 3 人，满 6 人才开；无 AI 补位、无降级 |
| 2 | 进房 | 房主建房（公开/私密 + 邀请码，照大乱斗那套） |
| 3 | 选边 | 进房后自己点"加入 A 队 / B 队"，每队上限 3（**该队已满则拒绝**并回一条 `server_message`，沿用邀请码错误那条应答路）；**房主点开始** |
| 4 | 回合 | 三局两胜；每队先到 **9 杀**赢一局；局间**整队换边** |
| 5 | 局内死亡 | 2s 复活（满血/满防水、背包只随机保留一把 —— 沿用现规则） |
| 6 | 击杀后 | **只把击杀者本人**送回本方出生点、保留血量（不治疗）；队友不动 |
| 7 | 计分 | **不分死因**：任意玩家倒地 → **对方队 +1**（枪杀/爆炸/溺水/自伤/队友误炸一律如此） |
| 8 | 子弹 vs 队友 | 穿透（不伤害、不挡弹道） |
| 9 | 爆炸 vs 队友 | 满效（伤害 + 击退）；自伤保留 |
| 10 | 掉线 | 身体留场 30s 可重连；超时算"离开"、该队少人继续；**整队走光**才终局 |
| 11 | 地图 | `factory_1V1(260827).cyrm`；出生点程序算 |
| 12 | **队友之间不互挡**（用户裁定，设计初稿**漏了这条**） | **完全穿透**：队友之间不挡路、也不推挤（可以站在同一格）。★ 代价见 §4.7 —— Godot 碰撞**按节点**配，要实现"队友穿、敌人挡"**必须把两队放到不同层位**，且客户端**副本的幽灵碰撞体也要跟着分队**，否则预测侧与服务器不一致 → 新的回滚源 |

**第 6 条的边界**：⑩ 需要"谁是击杀者"，而第 7 条本身**不分死因、不做归因**。两者的接法是 —— 复位走 `CombatFeedback` 的归因 meta（`last_damager` + 3s 窗口 `ATTRIB_WINDOW_MS`）：**3s 内归因到击杀者、且击杀者属于得分队**才复位；队友互炸 / 自伤 / 溺水 / 无归因一律**不复位**（设计上可接受：那些情况没有"占便宜的击杀者"要防）。

## 4. 服务端设计

### 4.1 队伍归属的唯一权威 = 大厅

不能从 role 号推（§2 第 2 条）。队伍是玩家在房间里选的，只有大厅知道：

```
大厅 TeamRoom { peer→role(1..6)、role→team(1|2) }
   └─ 满员判据 = 两队各 3 人（不是"人数 ≥ 6"—— 6 个人可能是 4v2）
      └─ 起 worker：-- --worker --team --port P --roles 1,2,3,4,5,6 --teams 1,2,1,2,1,2
                                                   （与 --roles 同序；长度不等 → 拒绝启动）
         └─ TeamHost.start_on → 算 spawns → 建 TeamHost
```

★ `--teams` 与 `--roles` **同序**、长度必须相等；不等 = **拒绝启动**（fail fast，别静默取默认值）。

★ 生成端（`worker_launcher.gd`）与解析端（`server_main.gd`）**必须逐字对应** —— 这条由 `room_sweep_smoke.gd:79-105` 的**双向**断言钉住（正向：两边都得有该开关；反向：旧协议标识符不得复活）。⚠ 该断言的**文件清单只有这两处**，只改一半不会被自动发现。

### 4.2 `TeamHost extends MatchHost`

照 `RoyaleHost` 的中间层模式。继承链：

`TeamHost → MatchHost → MatchRound → MatchCombat → MatchSnapshot → MatchState → Node`

★ 与 `RoyaleHost` 同受中间层纪律约束：**中间层不得定义 `_init`/`_ready`/`_physics_process` 等生命周期钩子**（`match_state.gd:14-16`）。

覆写清单：

| 覆写 | 现状（1v1） | 3v3 |
|---|---|---|
| `_init` | — | **先算 spawns 再 `super._init`**：父类 `_init` 会**虚调** `_spawn_cell(role)`，反了则首次摆位拿到 `(-1,-1)` 且被 `_spawned_once` 闩锁 |
| `_spawn_cell(role)` | `player/player2` 二选一 | 开局 → 本方散点；之后 → 按队的复活点 |
| `_opponent_of(role)` | 非我即敌 | 返回**对方队号**（改名为 `_enemy_team_of`，让语义变化在 grep 里可见） |
| `_match_round_tick` | 计分键 = role | 计分键 = **队**；`PLAYING` 的胜负判据 = "任一队 ≥ `KILLS_TO_WIN`" |
| `_reset_survivor` | "另一方" | 只送**击杀者本人**（§3 第 6 条） |
| `_round_over` / `_match_winner` / `_broadcast_round_state` | 按 role | 按**队**（`scores` / `rounds_won` 的键都换成队号） |
| `_side_swap` | 交换两人的出生侧 | **两队散点集整体对调**（满 6 人开局 ⇒ 两队严格对称，可以整体对调） |
| `role_spawns()` | 基类走 `_spawn_cell` | 覆写：**必须返回开局散点**，不能返回动态复活点（`match_state.gd:124-128` 的既有纪律） |

★ `_attributed_killer` 现在住 `RoyaleHost`（`royale_host.gd:315-328`）。`TeamHost` **自带一份**：上提到基类会撞上 `kh_l5_probe` 的"基类不得含子类方法"反向断言，为省 12 行动那条探针不划算。

### 4.3 友伤落点

- **子弹**（穿透队友）：玩家层本来就不在子弹 mask 里，"穿透"是现状的自然延伸 —— 只需在 `match_combat.gd:45-53` 的候选循环里加一条"同队 → `continue`"（**`continue` 不是 `break`**：队友不挡弹道，后面若有敌人照样打得到）。**榴弹的「直击」同口径**（`_adjudicate_grenade` 的半径结算），**爆炸那一层不在此列**。**副作用要写进文档**：现状下玩家也不挡敌弹，所以队友**不会替你挡枪**（既有行为，不是本次引入的）。
- **爆炸**（对队友满效）：**`Explosion` 一行都不用改** —— "队友吃满爆炸"本来就是现状的默认行为（`apply_aoe` 的玩家分支不看任何关系，只把 shooter 用于归因）。★ 早先这一节写的是"给它加一个 `team_of` 参数"，那是把规则误读成"免伤但保留击退"时写的；**规则定为满效之后，这条作废** —— 加参数反而会引入一个"空表 = 原行为"的新分叉。同理 `bullet_base.gd:241` 那层 `if apply_damage` 的门也不必动（客户端视觉副本本来就不调 `apply_aoe`）。
- ★ 本批在伤害路径上的**唯一**改动是"子弹/榴弹直击跳过队友"；1v1 / 大乱斗 / 单机的既有探针必须全绿，那是本批的回归线。

### 4.4 出生点与复活点

- **开局散点**：复用 `GridPathfinder.spread_cells`（洗牌 + 环面贪心 + clearance 逐级放宽，`grid_pathfinder.gd:330`）：① 先取**两个基座**（两两 ≥ `SPAWN_CLEARANCE` = 15 格）；② 每队基座附近各取 3 个格（队内小间距）。两队的点集大小相同 —— 这是 `_side_swap` 能"整体对调"的前提。
- **复活点**：沿用 Royale 那条动态选点（`royale_host.gd:224-249`），但判据从"离**所有存活玩家** ≥ `RESPAWN_CLEARANCE`"改成"离**所有存活敌人** ≥ `RESPAWN_CLEARANCE`" —— 意图不变（别在敌人脸上复活），队友反而不该被躲开。
- ★ 广播给客户端的 spawns 必须与服务器摆位是**同一份**（`RoyaleHost.start_on` 的既有纪律：`spread_cells` 内部有 `shuffle()`，重算会得到另一份）。
- ★ 复活点的动态选择**带 `_spawned_once` 副作用**：下发必须走 `role_spawns()` 这个只读取法，不能直接读私有字段。

### 4.7 队友不互挡（分队碰撞层）

**为什么不是"改个掩码"就完事**：Godot 的碰撞是**按节点**配的（`collision_layer` / `collision_mask` 都在节点上），**没有"按对"的开关**。今天所有玩家同在第 2 层、掩码都含第 2 层（`player.tscn:124-125` 是 `layer=2 / mask=5`，服务器 `match_host.gd:38/:56`、两个客户端各 `|= 2`，副本幽灵体 `player_replica.gd:77` 也是层 2）⇒ 互相碰撞且完全不看队伍。

**做法：把两队的层位分开，各自掩码只指对方那一位。**

| | `collision_layer` | `collision_mask` |
|---|---|---|
| 队 A 玩家 | `2`（沿用"玩家层"） | `地形1 \| 敌人层4 \| 队B层16`（**不含 2**） |
| 队 B 玩家 | `16`（新层位 5） | `地形1 \| 敌人层4 \| 玩家层2`（**不含 16**） |
| 副本幽灵体 | 按**它代表那名玩家的队**设 | `0`（不变） |

于是 A↔B 互挡（各自掩码含对方层），A↔A 与 B↔B 全穿透。第 5 层位（值 16）目前空着（1 地形 / 2 玩家 / 3 敌人 / 4 掉落物）。

★ **客户端必须同步**：本地玩家的掩码要按**自己的队**设，且每个副本幽灵体的 `layer` 要按**那个副本的队**设 —— 漏了就是"本地预测穿过去、服务器挡住"（或反过来）→ 每帧回滚。★ 队伍表是 `match_sync` 才到的，所以**在它到之前保持今天的"全员互挡"**（`|= 2`），一到就改成分队版（过渡期只有开局倒计时那几秒，玩家不动）。
★ **单机 / 1v1 / 大乱斗一行不受影响**：只有 3v3 那条路会碰这两个位（`TeamHost` 覆写 + `team_game` 客户端）。

### 4.6 掉线与重连

沿用阶段 1 已落地的机制，只改**终局判据**：

- 掉线 → **身体留场**、`_enter_grace`（清输入队列 + 复位输入源，`server_main.gd:200` 那两件事一件都不能少）→ 30s 内经 `reclaim_role` 可回来（新 token 由大厅在 `go_match` **之前**发）。
- 宽限到期 → 走 **`mark_disconnected` 那一套**（Royale 的语义：节点释放 + 排行榜标"离开"），**不是** 1v1 的"收场退进程" —— 6 人局里一个人超时不该收掉整局。
- **终局判据 = 整队走光**（不是"剩余 < 2 人"）。★ 这正是 `royale_disconnect_count_probe` 钉过的那类坑（判终局用**哪个集合**），3v3 需要自己的双向断言：掉 1 人**不得**终局 / 整队走光**必须**终局。
- ★ **走光即弃权 —— 胜者是"活下来的那支队"**（本节原稿只定了终局**判据**、**漏了胜者**，实现阶段才暴露）：
  - 某队走光 → **对方队胜**；两队都走光（或最后一人也走）→ **平局（0）**。
  - ★ 这条**优先于**"按局胜比、并列偏 1 队"那条正常收局兜底，但**不修改**它 —— 走光时两队必然都还没到 `TEAM_ROUNDS_TO_WIN`，走兜底会**把胜者报成走光的那一队**（`match_winner` 会进 `round_state`，客户端据此播报 ⇒ 留下的三人被告知"你输了"）。实现方式：一个"弃权胜者"字段 + `_match_winner()` 首行先看它，**别改 `_broadcast_round_state`**（让 `match_winner` 保持只有一个来源）。
- 重连成功后：`round_state` 已由 `_on_reclaim` 补发；`match_sync` 的补态（destroyed / ground_weapons，阶段 2-A）也要拉 —— 3v3 的 `match_sync` **另外**要带 `teams`（§6）。

## 5. 客户端设计

**新场景 `scenes/team_game.gd/.tscn`**，`extends PvpMatchClient`（与 `pvp_game` / `royale_game` 同基类）：

- 组成：Level0(`pvp_mode`) + PostProcess + **5 个 `PlayerReplica`**（照 `royale_game` 的 N 副本循环）+ `TeamHud` + 小地图 + 血条/拖尾（按 `Settings`）。
- **C2 预测链路一行不改**：`reconcile()` 已经能收敛"服务器外部事件"（2s 复活瞬移、换局换边、击杀后复位），3v3 没有引入新的事件类型。
- **队色是"能玩"的必要条件**：3v3 下身体的染色由**队色**决定，`peer_hues`（个人色相）**不生效**。★ 必须显式写进注释与 `CLAUDE.md`，否则"我设了颜色没反应"会被当 bug 报。
- **最小可用 UI（版式留白，第二份重做）**：记分条显示"队 A 击杀 N — 队 B 击杀 M / 局胜 / 第 N 局"（新 `ui/team_hud.gd`，照 `pvp_hud.gd:70-71` 那段硬编码 P1/P2 改）；中央广播按队；头顶名与血条按队色；小地图允许加"分队上色"的**参数**（版式不动）。
- ★ 队色具体色值、记分条位置尺寸、队伍标记的视觉形式 —— **全部归第二份规划**。本份只保证"信息在、读得出来"。

★★ **`deaths` 更正（A 册实现期）**：本节与 §11 第 2 条原先把 `deaths` 与 `scores` / `rounds_won`

`winner` / `match_winner`），`TeamHost` 里压根**没有** `_deaths` 这个计数器，补它 = 新增一个
**没有任何读者**的协议字段；② 3v3 的 HUD 口径（§5 的"记分条显示队 A 击杀 N — 队 B 击杀 M /

③ 协议字段是**加得上去**的（`round_state` 各模式本来就带各自的状态键），B 册真需要时再随
**消费者**一起加，而不是先在 A 册留一个无人读的键。守 `CLAUDE.md` 那条"只留一条投递路径 /
最小协议"的纪律。**本段落地后的契约以这里为准，§11 第 2 条已同步删掉 `deaths`。**

## 9. 风险与未验证项

1. **6 人局带宽与输入积压**（§2 第 7 条）：快照 O(N)、`hit_event` 每次伤害定向发、输入队列无上限无丢弃。**8 人局与 6 人局都没有实测数据** ⇒ 计划里必须有一条 6 人真链路压测任务，量三样：快照间隔的稳定性、`rollback_count()` 是否持续增长、6 人同帧交火时的包量。
2. **`_opponent_of` 家族要逐个复查调用点**：改语义但保留名字是最容易漏的一类（所以本设计要求**改名**为 `_enemy_team_of`，让 grep 能发现漏改）。
3. **换边的一致性**：换边 = 服务器把两队点集整体对调，客户端**不能自己推**（否则本地出生与权威不一致 ⇒ 每帧回滚）。
4. **端口延迟的已知边界照旧**：计时从房间拆除（≈开局瞬间）起算，**不是**从局内断线起算 ⇒ 一局中后段掉线时端口可能已被复用。3v3 一局比 1v1 长得多（三局两胜 × 9 杀），这条缺口在 3v3 下更大。
5. **未验证**：无 AI 补位（不碰未跑通的 `AINavigator`）；`TeamHost` 受中间层纪律约束（不得定义生命周期钩子）。
6. **`room_sweep_smoke` 的断言覆盖面**：它只扫那两个文件，只改一半（例如只加了 `--team` 没加 `--teams`）不会被自动发现 —— 新增开关时两个文件与断言要一起改。

## 10. 验收守卫（细节归实施计划）

| 守卫 | 钉什么 |
|---|---|
| 队伍表**显式下发** | 构造 role 空洞（如 `{1,3,4,5,6}` 的队映射），断言客户端拿到的是大厅给的那份，不是推导出来的 |
| 子弹穿透队友 / 爆炸满效 | 同队站位开火（无伤害、子弹继续飞）、同队贴脸爆炸（掉血 + 被推）、自伤保留 |
| 计分按队 + 不分死因 | 枪杀/溺水/自伤/队友误炸四种死因，断言**对方队**都 +1 |
| ⑩ 只复位击杀者 | 有归因（敌方击杀）→ 击杀者回出生点；无归因（溺水/自杀）与队友误炸 → **无人**被复位 |
| 掉线终局判据 | **双向**：掉 1 人不得终局 / 整队走光必须终局（照 `royale_disconnect_count_probe` 的形状，含反向断言） |
| 启动协议双向断言 | `room_sweep_smoke` 扩到 `--team` / `--teams` |
| 共享层回归 | 1v1 / 大乱斗 / 单机的既有探针**全绿**（"空参数 = 原行为"的证明） |
| 6 人真链路压测 | 快照连续性 + `rollback_count()` 不持续增长 + 6 人同帧交火 |
| 队色可辨识 | 视觉探针取图（**归第二份规划**，本份只保证数据在） |
