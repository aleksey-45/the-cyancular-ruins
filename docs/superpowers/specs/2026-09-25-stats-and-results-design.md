# 数据与结算（KDA / 伤害 / 惩罚 / 计分口径）— 设计（2026-09-25）

**一句话**：把逐人统计从"3v3 独有、且口径依赖队伍语义"改成**三模式通用的一套**，
结算页从"K/D"扩成 **K/D/A + 造成伤害 + 承受伤害**，并把 **计分公式（kscore / ACS）**
换成不依赖队伍语义、且**含死亡与惩罚**的一套。

**顺带修掉一个已定位的口径反转**：今天的击杀分按"敌方存活人数"加权，在**局内复活**的规则下
语义反转，系统性抬高败方 —— 这是用户报的"MVP 经常在败方"的结构性来源（§1.3）。

## 1. 背景

### 1.1 用户要的四件事（2026-09-25）

1. **把 KD 改成 KDA**（A = 助攻）
2. **炸队友和炸自己有惩罚**
3. **结算页分析自己造成伤害和承受伤害**
4. **大乱斗和 1v1 也统计伤害相关数据**

外加两条现场追加：**死亡要算进分数**、**ACS 也要改**。

### 1.2 现状：三个宿主差得很远

| 宿主 | 逐人统计 | `round_state` 带什么 |
|---|---|---|
| **1v1**（`server/match_round.gd`） | 只有 `_scores`（role → 击杀）+ `_rounds_won` —— **无死亡、无伤害** | `scores` / `rounds_won` |
| **大乱斗**（`server/royale_host.gd`） | `_scores`（击杀）+ `_deaths` —— **无伤害** | `scores` / `deaths` / `rounds_won`（空占位）|
| **3v3**（`server/team_host.gd`） | `_stats` = `{kills, deaths, dmg, kscore}` 整场累计 | `stats`（= `stats_payload()`）/ `mvp` |

★ 而 **3v3 那两键到今天没有任何消费者** —— `ui/match_result_payload.gd::for_team` 读的是
`round.state` 的 `stats` / `mvp`（唯一读者），而 1v1/大乱斗那两条分支**根本不发这些键**。
CLAUDE.md 记着它们的预定消费者就是"赛后结算面板"。

### 1.3 "MVP 经常在败方" —— 根因（读代码得出，**未实测**）

ACS 的口径是 `server/team_host.gd::_acs_of`：

```gdscript
# ACS = (击杀分 + 伤害) / 局数。★ **死亡不扣分**(用户裁定 ①:Riot 的 ACS 不含死亡惩罚)。
func _acs_of(role: int) -> float:
	var total := int(s.get("kscore", 0)) + int(s.get("dmg", 0))
	return float(total) / float(maxi(_rounds_for(int(role)), 1))
```

而 `kscore` 只由击杀产生，单价来自：

```gdscript
static func kill_bonus_score(enemy_alive: int) -> int:
	return KILL_BONUS_BASE + KILL_BONUS_PER_ALIVE * n     # 50 + 20×n → 1/2/3 人 = 70/90/110
```

输入是 `_enemy_alive_including_victim(victim_role)` —— **倒下瞬间受害者那一队的存活人数**。
设计意图（注释写着）是「**首杀最高、收尾最低**」。

**但那套语义成立的前提是"一局内不复活"**（Valorant 如此：越接近收尾，敌人存活越少，
所以"存活人数"就是"离收尾还有多远"）。**本作 3v3 是局内 2 秒复活** ⇒ 这个量退化成
"**敌人有多健康**"：

| | 拿人头时敌人通常还剩 | 每个击杀值 |
|---|---|---|
| **赢方** | 少（他们在碾压，对面常在等复活） | **70 / 90** |
| **败方** | 多（对面很少倒，基本满员） | **110** |

⇒ **败方的每个击杀系统性更值钱**，而且赢方必然拿到"最便宜的那一杀"（收尾）。
再叠上「**死亡不扣分**」—— 败方的主要代价（死得多）完全不进 ACS。
两条合起来：**ACS 里没有任何东西反映"赢了"，而败方在击杀单价上还占便宜。**

★ **这条是读公式推出来的，没有实测。** 本次的修法是**换掉公式**（§3.2），
换掉之后偏置的来源消失；**不另加"测量偏置"的探针**（公式没了，测它没有意义）。
真正的守卫是 §6 那条"死亡更多 ⇒ ACS 更低"的性质断言。

### 1.4 一个必须避开的陷阱：ACS 会**双重计入伤害**

今天 `_acs_of` = `(kscore + 伤害) / 局数` —— 这**成立**仅仅因为今天的 `kscore` **不含伤害**
（它只有击杀分）。§3.2 的新公式**把伤害并进 kscore**，此时若 ACS 照旧再加一次伤害，
**伤害就被算了两次**，而且**不报错**、只是所有排名静默偏移。

⇒ 新口径必须写死一条：**`acs = kscore / 局数`，伤害只出现在 kscore 内部一处。**

## 2. 目标与非目标

### 目标

1. 三模式共用**一套**逐人统计，口径一致。
2. 结算页出现 **K / D / A / 造成伤害 / 承受伤害**。
3. 计分公式**不依赖队伍语义**（这样它才可能被三个模式共用，见 §3.2 末尾）。
4. **死亡与惩罚进分数**。
5. 助攻可被统计（今天全仓没有这个概念）。

### 非目标

- **不改伤害本身**：爆炸对队友满效是用户既有裁定（见阵营 spec §1.4），本 spec 只在**计分**上惩罚，
  不动 `Explosion.apply_aoe`。
- **不做局内实时伤害 HUD**（用户已选"结算页里每个人的两列"）。
- **不改结算页的版式/排序/庆祝**（`ui/match_result.gd` 的既有口径与 `ui/match_result_payload.gd`
  的三条不改会静默出错的口径全部保留）。
- **不给 1v1/大乱斗加"队伍"概念**。

## 3. 设计

### 3.1 三模式统一的逐人字段

```
{ kills, deaths, assists, dealt, taken, kscore, acs }
```

- 3v3 的 `dmg` → **改名 `dealt`**（口径不变：只算对**异队**造成的伤害）；
  新增 `taken` / `assists`。
- 1v1 / 大乱斗 新增同一套（今天只有 `_scores` / `_deaths`）。
- **`taken` 与 `dealt` 口径对称**（用户 2026-09-25 裁定）：**都只算敌人**。
  ⇒ 队友爆炸炸到我不进 `taken`，自己炸自己也不进。那两类的代价走**惩罚**（§3.5），
  在**肇事者**那一行上体现，不在受害者行上。
- 承载：`MatchState` 基类（**上提**）。★ 今天这套住在 `TeamHost`，且混着队伍语义
  （`_enemy_alive_including_victim`、`_on_player_hit` 的 `same_team` 过滤）——
  **§3.2 换成不依赖队伍语义的公式之后才提得上去**，这是两件事的顺序关系，不是巧合。

### 3.2 计分公式（kscore）—— 三模式统一

```
kscore = 击杀 × 100
       + 助攻 × 50
       + 伤害 ÷ 5                 # 伤害 = dealt
       − 死亡 × 50
       − 惩罚                      # 见 §3.5
```

**权重的标定依据**（不是拍的）：

| 依据 | 数 |
|---|---|
| 玩家满血 | `PlayerParams.player_max_hp` = **50** |
| 打死一个人需要的伤害 | 50（手枪 5 发 ×10 / 步枪 ~13 发 ×4 / 重狙 2 发 ×30 / 霰弹 8 丸 ×5） |
| 3v3 一局 | 每队先到 **`TEAM_KILLS_TO_WIN` = 9** 杀 |

⇒ `伤害 ÷ 5` 的含义是「**打光一个人的血 ≈ 10 分**」，即**一个击杀 = 打死 10 个人的伤害量**。
击杀因此压倒性主导，但伤害不白打。`死亡 × 50` = 半个击杀：死一次疼，但不至于让"敢冲"变成亏本。

★ **这组数是首版默认值，属于平衡参数、预期会被调**。守卫不是"钉死数值"，而是钉**性质**
（§6：死亡多 ⇒ ACS 低；击杀多 ⇒ ACS 高；惩罚 ⇒ ACS 低）。★ **但"调数不应该让探针红"这句是错的**
（2026-09-26 实测订正）：`tests/score_rules_smoke.gd` 确实与权重取值无关，可 `tests/stats_delivery_probe` ①
与 `tests/team_host_probe` ⑬d/⑬e/⑬f/⑬g 把 `100/50/5/50/100` 写进了期望值（实测 `KILL_SCORE` 100→110 ⇒
前者红 **1** 条、后者红 **6** 条，而 `score_rules_smoke` / `match_result_payload_smoke` 照旧全部通过）。它们正是
"新公式真的走在生产路径上"的守卫，**调权重必须同步改那两处**（或改成从 `ScoreRules` 常量派生）。

**为什么必须不依赖队伍语义**：旧的 `kill_bonus_score(敌方存活数)` 在 1v1（两人）与大乱斗
（自由混战）里根本没有对应物。换成上面这套之后，**同一份计算可以三模式共用** ——
这正是 §3.1 能把统计面上提到基类的前提。

### 3.3 ACS 与 MVP

- **`acs = kscore ÷ 局数`**（§1.4：伤害已在 kscore 内，**不得再加**）。
- 局数口径沿用 `_rounds_for(role)`：全场已进行局数；中途离开者**冻结在他离开时所处的局号**
  （`_left_round`）。这条既有口径与它的代价（离开者分母更小 ⇒ ACS 偏高）**保持不变**，
  是用户裁定的取向。
- **MVP = 整场 ACS 最高者**，并列判据不变（击杀多 → 阵亡少 → role 升序）。
  **不限制在胜方** —— 换公式之后偏置的来源没了，"全场最佳"这个语义可以保住。
- ★ **大乱斗是单局死斗、不换局** ⇒ 局数恒为 1 ⇒ `acs` 恒等于 `kscore`。
  故大乱斗的结算页**不列 ACS**（恒等 ⇒ 零信息），与"模式没有的列不进"同一条口径。

### 3.4 助攻

今天全仓**没有**"谁打过谁"的表 —— 归因只有 `CombatFeedback.attribute` 写的单个
`last_damager` meta（时效 `ATTRIB_WINDOW_MS` = 3s），只够判"谁拿的击杀"。

**新增**：`victim_role → {attacker_role: 最后命中时刻(ms)}`（每受害者一张小表）。

- **写入点**：与 `attribute` **同一处**（"归因写端统一入口"是既有纪律），即所有伤害路径
  （子弹 / 榴弹直击 / 爆炸 AoE / 激光）**自动覆盖** —— 不必去改 `Explosion`。
- **判定点**：受害者倒地边沿（`_record_down`），把表里**除击杀者之外**、且
  `now - t <= ATTRIB_WINDOW_MS` 的 attacker 各记一次助攻。
- ★★ **必须再过滤一层：只记「与击杀者同队」的 attacker。** 否则会出一条荒谬的助攻 ——
  受害者的**队友**误伤过他（爆炸），随后敌人把他补掉 ⇒ 那位队友**因为打死自己人而拿到助攻**。
  判据写成 `same_team(attacker, killer) and not same_team(attacker, victim)`。
  ★ **免费的正确性**：1v1 / 大乱斗 里所有人的队号都是 0，而 `same_team(0, 0)` **恒为 false**
  ⇒ 那两模式**天然拿不到任何助攻**，不需要特判 —— 与 §3.6「助攻只在 3v3 出列」自动一致。
  （这条又依赖 `same_team` 的 0 语义，见 §5.6，别去"优化"它。）
- **窗口复用 `CombatFeedback.ATTRIB_WINDOW_MS`（3s）**，**不新开第二个窗口常量**
  （"归因口径只有一处来源"）。
- 表的清理：该受害者**复活时**清空（每次生命一条历史），与"助攻只算这一次倒地之前"一致。

### 3.5 惩罚

```
惩罚 = (对队友造成的伤害 + 对自己造成的伤害) ÷ 5     # 与"伤害"同倍率 ⇒ 1:1 冲销
     + 击杀队友 × 100                                # 额外重罚(一个击杀的分量)
```

- 三项都记在**肇事者**的 `kscore` 上（只减分，不进 `dealt` / `taken`）。
- **触发数据从哪来**：需要两笔新账 —— 对队友的伤害、对自己的伤害。今天的
  `_on_player_hit` **按队过滤**（注释写着理由："不过滤就等于朝队友扔雷即可刷 ACS"），
  那条过滤**保留**（`dealt` 仍只算异队）；惩罚走**另一笔账**，两者不共用。
- **自伤确实会发生**：`core/sim/explosion.gd::apply_aoe` 的玩家循环**不排除投掷者**
  （归因那一步对 `attacker == victim` 静默跳过，但 `take_hit` 照跑）。
  故"自伤"有触发点，不需要新机制。
- **自杀（K 键 / 溺水 / 坠落）**：今天在 3v3 已算"无归因"→ 对方队 +1。本 spec **不再额外扣分**
  （死亡已经 −50，再扣是双罚）。

### 3.6 结算页的列

`ui/match_result.gd` 的 `COLUMN_TITLES` 加 `{"assists": "助攻", "dealt": "造成", "taken": "承受"}`，
并把 `"dmg"` 改名 `"dealt"`（与 §3.1 同步）。

各模式的列（按既有口径"**模式没有的列不进**"）：

| 模式 | 列 |
|---|---|
| 1v1 | 击杀 / 阵亡 / 造成 / 承受 / ACS |
| 大乱斗 | 击杀 / 阵亡 / 造成 / 承受（**无 ACS**，见 §3.3；**无助攻**，自由混战无归属）|
| 3v3 | 击杀 / 阵亡 / **助攻** / 造成 / 承受 / ACS |

★ `match_result_payload.gd` 三条"不改会静默出错"的口径**原样保留**：
`columns` 由数据决定、排序确定性、`match_winner == 0` 是平局。

## 4. 协议与投递

- `round_state` 新增/沿用 **`stats`** 键（**向后兼容增量扩展**：3v3 已有，1v1/大乱斗新增）与 **`mvp`**（3v3 已有；1v1 也可给）。
- `stats` 的每条 = §3.1 那七个字段。**只在非空时带该键**（与 `destroyed` / `ground_weapons` 同款纪律）。
- 老接收端忽略未知键 ⇒ **不需要两端同版本**（与阵营 spec 的激光修法同性质）。
- ★ **`stats` / `mvp` 从"3v3 独有的两个无消费者键"变成"三模式共用的、有消费者"的键** ——
  这次真的接上了 `ui/match_result_payload.gd`。CLAUDE.md 那条"用户裁定保留这两个键"的登记
  可以随之订正为"消费者已到位"。

## 5. 已知边界与残余（登记，不修）

1. **`taken` 不含队友伤害与自伤**（§3.1 的对称口径）。⇒ 被队友炸的人在结算页上看不到那笔伤害，
   它只出现在肇事者那一行的惩罚里。
2. **伤害总量没有"溢出/过量"区分**：打死一个剩 5 HP 的人，打出 30 伤害的枪照样记 30。
   与本作"每发结算一次"的判据一致，登记，不改。
3. **助攻窗口 3s 是复用归因窗口，不是为助攻调的**。若将来发现"助攻太容易/太难拿"，
   需要**新开一个常量**（并接受"归因口径不再只有一处"）—— 那是另一件事，本次不动。
4. **大乱斗 ACS 恒等于 kscore**（§3.3），故不列该列。若将来大乱斗改成多局，这条要重看。
5. **`_left_round` 的已知口径边界**（CLAUDE.md 已登记）：它记的是"宽限期到点"的局号，
   若那 30s 跨了一次换局，离开者的分母会**多算一局**、ACS 被压低。本 spec **不放宽**。
6. **1v1 / 大乱斗 没有"队伍"** ⇒ `same_team(0, 0)` 恒 false ⇒ 那两模式的 `dealt` / `taken`
   **天然等于"对所有人的伤害"**，无需特判。★ 这是 `same_team` 的 0 语义（任一方 0 → false）
   带来的免费正确性，**别去"优化"成 `same_team(0,0) == true`**（那会让 1v1 的两人互为队友、
   子弹互相穿透）。

## 6. 验收判据

1. **新探针（计分性质）**：`kill_bonus_score` 那张静态表**删掉**，改为断言新公式的**性质**——
   - 击杀更多 ⇒ ACS 更高
   - **死亡更多 ⇒ ACS 更低**（今天不成立；这条是新性质，也是"MVP 在败方"的守卫）
   - 惩罚 > 0 ⇒ ACS 更低
   - 助攻 ⇒ ACS 更高
   - **伤害只被计入一次**（§1.4）：构造"伤害翻倍但击杀不变"的两个 case，断言 ACS 的增量
     恰好等于 `伤害增量 ÷ 5 ÷ 局数`（**不是** `÷5×2` 那种双计）
2. **新探针（助攻）**：真建宿主，甲打乙 60 伤害、丙补掉乙 → 丙记击杀、**甲记助攻**；
   若甲的最后一次命中在窗口外 → 不记助攻。（★ 后半条是鉴别点：只断言"甲记了助攻"的话，
   把窗口判据删掉也能过。）
3. **新探针（惩罚）**：甲用榴弹炸死队友乙 → 甲的 `kscore` 减少、`deaths` 不变、
   `kills` 不变；甲自己站在爆炸里 → 同样扣。
4. **既有探针全部通过**：`team_host_probe`（⑬ 逐人数据 / ACS / MVP 那一族 **需要按新公式改写期望值**——
   这是本批**必然**会红的既有断言，改它是"认新口径"而不是"放宽"）、`hud_declarative_probe`、
   `match_result_payload` 相关的 `-s` 冒烟、`kh_l6_probe` 的 ⑯（结算数据包实参顺序）。
5. **实机**：3v3 打完一局，结算页五列齐全；**故意炸死一次队友**，看自己那一行的分是否掉。

## 9. 已排除的伪发现（勿重复排查）

1. **"MVP 在败方 = 巧合/方差"** —— 不是。有结构性来源（§1.3），且**会在本次被换掉公式后消失**。
2. **"死亡不扣分是 bug"** —— 不是 bug，是用户 2026 年的**裁定 ①**（Riot ACS 口径）。
   2026-09-25 用户**改了这条裁定**（"把死亡算进去"），故本次是新决定，不是修 bug。
3. **"`_stats` / `mvp` 两个键是漏接线"** —— 不是。CLAUDE.md 明确登记为"用户裁定的例外，
   消费者是赛后面板"。本 spec 正是那个消费者到位。
4. **"爆炸不会伤到投掷者"** —— 错。`apply_aoe` 不排除投掷者（§3.5），自伤真实可达。
5. **"`same_team(0,0)` 应该返回 true 才对"** —— 不能改。它恒 false 正是 1v1/大乱斗
   "无队伍 ⇒ 互相都能打"的实现基础（§5.6）。
