## 4. 本会话反复出现、值得带走的纪律

1. ★★ **"守卫比它读起来强"出现了 10+ 次**，每次都**静默地绿**：恒真断言 / 重写时丢了承重的调用而判词没改 / 查子串不查分支 / 验了"该清"没验"该记" / 探针够不到承重分支 / 判词说"按按钮"而实现绕过按钮 / 否定断言退化成子串 / **在出厂默认下恒真**（`true == true`）/ 子串匹配被兄弟标签喂绿。
   ⇒ **每条新断言都要能回答"去掉什么它才会红"**；写不出就别写。
2. ★★ **枚举会过期，判据不该是枚举。** 本会话两次踩到：计划里的文件清单漂了（漏掉两个测试文件）；Task 7 的"场景路径替换"清单漏了"按新接口重写"的那一类。**改成"跑 grep 逐条处理"**之后才对。
3. ★★ **共用工作树**：`git add <具体文件>` **只保证不带走别人的文件，不保证不带走别人在同一文件里的 hunk** —— 本会话真发生过（`671e610` 把另一 agent 在途的背景改动一起提交了）。**提交前逐文件 `git diff` 认领每个 hunk。**
4. ★★ **取图命令不要带 `--headless`** —— headless 下没有视口纹理，探针**静默地什么都不存**，而"人眼验收"那一步的全部意义就是看图。
5. ★★ **变异验证要打在断言真正读的那条路径上**：我做过一次**打在错误模式上**的变异（自然模式 vs `--payload` 模式），得出了**假结论**。
6. ★ **"同配置跑两次"是分清噪声与信号的关键手法**：字体那一步有 4 张图对不上，用"同配置跑两次"证明**运行间抖动 ≥ 跨配置差异**，从而判定**不是退化**。
7. ★ **参数的方向要写进注释与派发**：`dim` 那件事的根因就是"实现是乘子、用户读成浓度"，而**我转达时没核方向**，导致用户连续三轮"越调越黑"。
8. ★ **不要把对比度当验收**（用户明确取消过一次）；**看图判断即可**。
9. ★ **改了 A 就会有一串 B 过期**：删三个大厅页之后，注释、`reconnect_smoke` 的写死数量、`kh_l4_visual_probe` 的按钮数下限、`kh_l5_probe` 的文件清单、`rejoin_watcher` 的按钮文案……全部**静默过期**。**改完 grep 一遍。**
