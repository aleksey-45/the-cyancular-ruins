# PvP 客户端预测与回滚机制架构复盘与实施准则

> **文档定位**：本文系统性复盘 PvP 客户端预测（Client-Side Prediction & Rollback）早期实现的缺陷成因与工程教训，并确立后续重构客户端预测回滚系统时必须满足的架构前置条件（Checklist）。  
> **基线说明**：早期实现曾因预测分歧与位置拉扯问题，临时回退至无本地预测的纯服务端权威插值方案（Server-Authoritative Interpolation）；本复盘作为后续全面落地输入重放式预测回滚架构的技术准则。

---

## 一、 缺陷演进与修复历程

在最初的设计中，本地角色运行完整物理逻辑进行客户端预测，服务端在无头进程中运行相同实体并依据网络输入驱动模拟。当双端模拟轨迹出现偏差时，客户端尝试通过位置平滑进行校正，从而引发频繁的位置拉扯现象。各阶段排查出的核心缺陷如下：

| 提交版本 | 表面现象与处理 | 底层真实原因分析 |
|---|---|---|
| `5558ad1` | 快照增加序号，引入分级容差校正 | 快照基于 30Hz 不可靠通道传输且缺乏单调序号，旧快照乱序到达时被误作为最新状态消费，导致实体被错误回拉至历史坐标。 |
| `e901254` | 攀爬与游泳组件重构为注入式输入源 | 服务端实体内部子组件仍直接调用全局 `Input` 单例（无头服务端恒判定为无按键输入），导致服务端实体无法正常执行抓梯与游泳物理，每当接触特殊地形必产生状态分歧。 |
| `2046143` | 输入消费重构为有序队列处理 | 覆盖式单包消费逻辑在短时间内批量到达输入包时，会直接覆盖并丢失先到达包中的边沿触发事件（`just_pressed`），导致服务端漏执行跳跃与抓梯动作。 |
| `c57fa1b` | 持续输入覆盖最新、边沿事件按位累积 | 完善输入消费模型，确保在单物理帧内完整保留瞬时边沿触发事件，解决丢键与漏动作问题。 |
| `8de536e` | 暂时降级为纯服务端权威插值基线 | 为迅速消除体验级拉扯，暂时移除本地预测物理，确立重构标准后再行演进。 |

## 二、 核心架构缺陷反思

1. **形式上的客户端预测，实质上的双端脱节模拟**：  
   早期输入包缺乏严格的单调序列号，客户端无法精确获知服务端已确认处理的具体输入帧，导致无法实现“重置至权威基线并重放未确认输入”的标准回滚机制。原有校正仅在偏差超过阈值时强行插值拉回，使得预测与校正处于割裂状态。
2. **单纯复用实体物理场景的隐蔽缺陷**：  
   双端复用同一个 `Player.tscn` 场景必须严格保证所有状态判定均基于抽象输入源、且具备严格的时序确定性。在重构初期，部分组件仍隐式依赖全局输入，在无头环境下产生系统性判定偏差。
3. **单帧边沿触发与平台跳跃机制的敏感情形**：  
   平台跳跃物理高度依赖瞬间边沿判定（抓梯瞬间、离梯跳跃、土狼时间 Coyote Time 与输入缓冲）。若边沿事件在网络传输中被覆盖或延迟处理，将导致双端物理分支彻底分歧。
4. **经验性阈值缺乏物理量纲支撑**：  
   网络预测下的合理超前量理论上取决于实体移动速度、往返时延（RTT）及网络抖动。若脱离物理推导直接设定硬编码像素容差，实体在高移速与击退状态下极易超出容差被误判为异常漂移。
5. **早期缺乏确定性双端对照测试套件**：  
   初期测试侧重于网络消息流转，未对两端物理模拟器注入相同轨迹进行确定性数学收敛验证，导致边缘物理问题难以在单测阶段暴露。
6. **环面边界（Torus Wrapping）放大坐标校正异常**：  
   在地图回绕接缝处，若未采用环面最短向量算法直接进行绝对坐标差值计算，会导致实体在跨界瞬间发生全屏视距跳变。

## 三、 客户端预测回滚重构的前置准则（Checklist）

为确保客户端预测回滚系统的健壮性，新架构必须严格满足以下准则：

- [x] **P1 协议携带单调序号与确认机制（Acking）**：  
  输入包必须携带单调递增的 `seq` 序号；服务端每物理帧严格按 FIFO 顺序消费一个输入包并在快照中回传 `ack_seq`；客户端快照包含单调 `tick`，丢弃过期的乱序快照（落地于 `match_host._ack_seq` 及输入队列管理）。
- [x] **P2 标准回滚预测模型（Rollback & Re-simulate）**：  
  服务端快照到达时，若发现预测偏差，客户端严格执行“恢复权威历史快照状态 + 重放未确认输入队列”的标准回滚算法，彻底摒弃简单的暴力坐标插值（落地于 `core/prediction_rollback.gd`）。
- [x] **P3 双端物理组件确定性注入（Twin Fidelity）**：  
  实体及其子系统（移动、攀爬、游泳、跳跃与武器瞄准）的所有输入通道必须完全抽象为 `InputSource`，在服务端运行时绝对隔离全局输入。
- [x] **P4 逻辑与表现的确定性分离**：  
  核心物理与状态模拟（位置、速度、姿态、生命值与技能冷却）严禁包含非确定性随机数；武器散布与视觉特效的随机计算严格隔离在表现层或服务端权威端。
- [x] **P5 自动化双端收敛验证套件（Twin Smoke Tests）**：  
  构建自动化测试（如 `pvp_twin_smoke` 与 `pvp_reconcile_smoke`），向双端物理注入确定性输入流，强制断言回滚后的状态必须逐帧数学收敛。
- [x] **P6 基于时延与物理量的自适应容差**：  
  摒弃粗暴的固定容差判定，结合角色运动状态与物理接触状态动态调整校正容差（如贴身缠斗时启用接触期容差放宽），抑制高频微小回滚。
- [x] **P7 严格遵循环面最短向量几何计算**：  
  快照存储、状态还原与距离判定全流程遵循规范化坐标 `[0, MAP)`，跨接缝距离与插值统一通过 `toroidal_delta_px` 计算最短位移差。

## 四、 兜底保障策略

无预测的纯服务端权威插值方案虽然存在固有操作延迟（约等于端到端往返时延），但具备零预测误差与零状态回滚的物理稳定性。当极端网络抖动或环境无法满足低延迟预测要求时，系统保留降级退回至权威插值或放宽预测容差的能力，确保整体游戏对局不发生阻断。
