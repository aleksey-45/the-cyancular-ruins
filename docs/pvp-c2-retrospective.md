# PvP 客户端预测(C2)复盘与重试锚点

> 时间线锚点:`docs/pvp-networking.md` 是 **C2 时代(弃 C2 前一刻)** 的现状快照(还写着 30Hz/自校正/分档);
> 本文记录 C2 为何失败、以及 2026-09-05 决定**重试一次**时必须守住的前提。代码锚点:弃 C2 提交 `8de536e`。
> 现状(2026-09-05,main):本地玩家 = **服务器渲染**(`player.gd` `server_rendered`,`_update_server_rendered`),零本地预测。

## 1. 症状 → 真因(按修复史)

本地玩家在跑 C2(客户端预测,读真实输入、全量物理),服务器另跑一份权威模拟(同一 `Player.tscn`,
输入由 `NetworkInputSource` 注入包驱动)。两端一旦分歧,客户端 `_self_correct` 把自己往服务器位置拉
——玩家体感就是"服务器疯狂拉回/橡皮筋"。逐层补丁暴露的真 bug:

| 提交 | 表面修复 | 真正的洞 |
|---|---|---|
| `5558ad1` | 快照加 tick、自校正分档 | 快照 30Hz unreliable **无序号**,乱序旧包当新包 → 拉回过去位置 |
| `e901254` | swim/climb 组件改走注入输入源 | **服务器上的子组件仍直接读全局 `Input`**(headless 恒"无按键")→ 服务器那份玩家不会爬梯/游泳,客户端会 → 每碰梯/水必分歧 |
| `2046143` | 输入改按序队列消费 | 覆盖式"只留最新包"把批量到达的先到包 **`just_pressed` 边沿冲掉** → 服务器没执行你的抓梯/跳跃 → 客户端跳了服务器没跳 |
| `c57fa1b` | held 取最新、边沿累积、整帧应用 | 上一条的模型补齐(边沿 1 帧即失,消费模型不能丢) |
| `8de536e` | 弃 C2 → 服务器渲染 | 上述分歧源的共同解:不再有第二份模拟 |

## 2. 架构层根因(为什么会被写成这样)

1. **名义 C2、实际"权威位置 + 客户端追"的双份独立模拟。** 输入包无序号(只有
   `ax/held/pressed/released/weapon/aim`),客户端无从知道服务器确认到哪一包 → 做不了教科书式
   "重置到权威态 + 重放未确认输入"的校正;`_self_correct` 只会拉位置。预测从未立在权威地基上,
   分歧只能靠阈值硬拉。`983e5c3`(纯 C2、无权威)手感好到能跑 → `2cfbea3` 才回头补校正,
   次序反了:预测与校正是先后拼的,不是一体设计的。
2. **"两端复用同一份 Player.tscn 物理"是看似正确、实则致命的捷径。** 孪生前提 = 所有输入读口都走
   注入源 + 帧时序一致 + 确定性。注入重构是增量做的(player 主干 → weapon → swim/climb),任何漏网
   的 `Input.*` 在 headless 服务器上都是"无按键",系统性制造分歧。梯子/水恰是分歧最烈处。
3. **边沿=1 帧信息,与平台跳跃机制是 C2 至暗组合。** 本作物理重度依赖 `just_pressed`(抓梯/到顶跳离/
   开火)、coyote、跳缓冲、姿态碰撞箱切换。一个边沿在服务器上没复现 = 持续分歧,而校正把每次分歧
   放大成可见橡皮筋。
4. **校正阈值全在治标,从物理量推过。** `96 → 64/0.35/3格 → 2格` 一路调。预测**正常领先量**
   ≈ 速度 × RTT + 抖动,高移速/击退/跳跃下轻松破 2 格;把良性领先当"传送级错误"硬回 = 玩家感知的
   "卡一下又回去"。且只拉位置、从不采纳服务器速度/姿态(仅 hp/wp/downed),分歧每个快照周期重积累。
5. **缺"孪生确定性"测试。** 冒烟只测协议链路(loopback:输入→快照→子弹),从不喂**同一段输入轨迹给
   两端模拟断言收敛**。四个分歧 bug 全在真机对打以"疯狂回拉"浮现、反应式打补丁。
6. **环面把 naive 校正再放大一档。** 任何不经最短向量/不取模的绝对位置校正,在接缝处 = 整屏横跳。

## 3. 重试 C2 的硬前提(checklist,做不到就别上)

> 以下任意一条不满足,新的 C2 会以同样的方式死掉。重试前逐条打勾。
> 状态(2026-09-06):P1/P2/P5 已落地并有冒烟钉死;P3/P4/P6/P7 已按实现落实,尚欠「真机联调」最终验收。

- [x] **P1 输入包带序号** + 快照带 tick + `ack_seq`:输入包带单调 `seq`;服务器每物理 tick 恰好消费 1 个 FIFO 包并回带 ack;快照带 tick 序号(乱序丢弃)。落地:`match_host._ack_seq`/FIFO + `pvp_match_smoke` 断言 ack 推进。
- [x] **P2 校正 = 权威锚定 + 未确认输入重放**(rollback to last acked + re-simulate buffered inputs):
      不做橡皮筋拉拢。落地:`core/prediction_rollback.gd`(`on_authoritative` 到期 → 分歧则 `restore_state` + 按 `_inputs` 重放);`pvp_reconcile_smoke` 注入外部传送断言一次性 rollback 收敛。
- [ ] **P3 孪生保真**(已按实现落实,无自动守卫):player.gd + climb/swim/combat/weapon 的输入读口
      已全部走注入源(swim/climb/weapon 注入重构先于本重试落地);武器瞄准经 `input_is_network` 分叉,
      服务器永不读全局 Input。缺:一处"全局输入全零仍能正确模拟"的守卫冒烟。
- [ ] **P4 确定性**(已按实现落实,火力路径欠测):同一 Player.tscn、同 1/60 物理步、输入走注入源;
      玩家状态整态(影响判定的 pos/vel/姿态/血/武器冷却)不含 randf;子弹散射 randf 只落视觉/权威侧。
      缺:`twin/reconcile` 冒烟均不开火(武器 0、无攻击位),火力下两端收敛未自动钉死。
- [x] **P5 孪生冒烟**:同一输入轨迹喂 A/B 两端模拟断言收敛。落地:`pvp_twin_smoke`(capture/restore 完整性,
      restore every 12 tick 仍逐 tick 收敛)+ `pvp_reconcile_smoke`(权威/预测 + 人工 ack 延迟 + 外部事件)。
- [ ] **P6 阈值从物理量推**(现状为经验容差):`_close_enough` 用 pos 1px/vel 20 拍脑袋常数,但 reconcile 冒烟
      D=8 下事件前 dev 恒 <1px 支撑该容差。欠:按"速度×RTT+抖动"从物理量推导 + 真机抖动验证。
- [x] **P7 环面纪律**:capture/restore/重放全程 canonical(两端同 Player 物理自带 wrap_to_range),无 naive
      set canonical 拉拢;渲染/副本插值已有 `toroidal_delta_px` 最短向量纪律(见 CLAUDE.md)。

## 4. 为何放弃"服务器渲染"这条现成的路不在讨论内

服务器渲染(现状)天然无回拉,代价是操作延迟 ≈ 满 RTT + 追赶尾巴(见 pvp_client/player 注释)。
它仍是**保底方案**;新 C2 若在 P1–P7 之下做不出来可接受的延迟/手感,应回落到它,而不是退回旧 C2 的分歧+拉拢模型。
