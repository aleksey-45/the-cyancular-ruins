# 世界与地图

地图的左右边缘相连，上下边缘也相连。实体的模拟坐标与网络快照使用 `[0, width) × [0, height)` 的范围。`GridPathfinder` 计算跨边界的最短位移、最近的平移副本和 A* 路径。碰撞与渲染在边缘附近使用平移副本，让角色、弹丸和镜头连续穿过边界。[寻路与坐标](../core/sim/grid_pathfinder.gd) · [地形碰撞](terrain.md)

## CYRM 地图

游戏读取 `.cyrm` v4 文件。20 字节的文件头记录 `CYRM` 标识、版本、压缩方式、解压后的数据长度、CRC32、地图宽高和图层标志。宽高以子格计。地图主体可直接存储或用 Deflate 压缩，解压后的上限为 64 MiB。

编辑器有前景、场景、后景和背景四层。游戏使用场景层生成地形。每块 64 像素瓦片包含 4×4 个 16 像素子格。场景层为每个子格保存纹理 ID、色相、亮度、饱和度和透明度。读取场景层时，解析器根据材质表映射纹理 ID，并验证调色板和索引。64 像素瓦片以最常出现的非空纹理和 2×2 占用掩码表示，碰撞和绘制可读取更细的子格数据。[CYRM 解析器](../core/sim/map_format_v4.gd) · [材质表](../data/tile_defs.json)

本地文件和联机基线中的地图字节由 `MapFormat` 解析。预览、地图校验和建图会复用相同字节的解析结果，每场对局分别创建 `Terrain` 实例。地图列表查找 `res://maps` 和可执行文件所在目录。随机选图优先尝试可执行文件所在目录，指定地图读取失败时取消开局。[地图加载](../core/sim/map_format.gd) · [地图列表](../core/sim/map_catalog.gd)

## 出生点

地图文本元数据中的坐标从零开始，以 64 像素瓦片为单位。

| 记录 | 用途 |
|---|---|
| `# player X Y` | 单人玩家的出生点 |
| `# player2 X Y` | 为兼容旧地图保留的标记 |
| `# enemy TYPE X Y` | 单人敌人的类型和出生点 |
| `# respawn SIDE X Y` | 联机开局和复活使用的点位，`SIDE` 为 1 或 2 |

玩家与敌人点位的坐标格式错误或越界时，地图解析失败。单人地图没有 `player` 条目时，使用找到的第一个空瓦片。重开关卡沿用同一个点。

联机开局时检查 `respawn` 的格式与坐标。每个点都要有站立空间和脚下支撑，各点须互不重合，且能沿容得下站立角色的空间连通。1v1 每侧至少 1 个点，团队赛每侧至少 5 个点，大乱斗两侧合计至少与本场人数相同。指定地图不合格时会显示原因，随机选图会继续尝试其余地图。[对战选点规则](modes.md) · [地图点位校验](../core/sim/spawn_picker.gd)

## 水体

水体按 64 像素瓦片采样。`Water` 从当前碰撞包围盒的顶边和底边中点确定头部与脚底位置。脚底浸入至少 8 像素时开始游泳。已经在游泳时，脚底可高出水面 2 像素。水深沿连续水柱向上测量，可以跨地图边界，整列都是水时返回无穷大。

玩家头部浸水后每秒损失 1 点氧气。头部出水后清空溺水计时，每 0.3 秒恢复 1 点氧气。氧气耗尽后，每浸水 1.5 秒损失 5 点生命值。多人在交战阶段由服务器结算。敌人也受浮力和溺水影响，使用自己的氧气上限和伤害参数。

弹丸在水中按 `exp(-drag × delta)` 降低速度。水下目标受到的爆炸伤害和击退速度乘以水材质的衰减系数 0.25。[浸水查询](../core/sim/water.gd) · [玩家状态](../core/sim/actor_body.gd) · [伤害结算](../core/sim/combat_simulator.gd)
