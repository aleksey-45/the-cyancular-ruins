# 世界与地图

游戏世界在水平和垂直方向循环。实体和网络快照以 `[0, width) × [0, height)` 为坐标区间。`GridPathfinder` 提供回绕、最短位移、就近副本和环面寻路。物理查询使用规范坐标及接缝附近的镜像，视觉投影见 [渲染](render.md)。

## CYRM 地图

游戏读取 `.cyrm` v4。20 字节文件头包含 `CYRM` 标记、版本、压缩方式、解压后长度、CRC32、子格尺寸和图层标志。地图主体可以原样存储或用 Deflate 压缩，解压后的上限为 64 MiB。编辑器支持前景、场景、后景、背景四层。游戏用场景层建立地形及其贴图。

每个 64 像素格含 4×4 个 16 像素子格。场景子格描述符包含纹理 ID、色相、亮度、饱和度和透明度。`MapFormatV4` 校验场景调色板，并用材质表中的 `legacy_texture_map` 转换仍在文件中的旧纹理 ID。宏观格用出现最多的非空纹理和 2×2 占用掩码表示，子格保留精细形状。 [格式解析](../core/sim/map_format_v4.gd) · [材质表](../data/tile_defs.json)

文件与联机地图字节共用 `MapFormat` 解析入口。同一进程按原始字节复用成功解析的结果，预览、开局校验和建图都使用这份结果。关卡和服务端对局各自用它创建 `Terrain`，碰撞查询从所在物理空间取地图尺寸与地形。地图列表扫描内置 `res://maps` 和游戏可执行文件同级目录。选择随机地图时优先尝试同级目录，选定地图无法读取时开局失败。 [地图加载](../core/sim/map_format.gd) · [地图列表](../core/sim/map_catalog.gd)

地图注释中的点位使用从零开始的 64 像素格坐标。

| 元数据 | 用途 |
|---|---|
| `# player X Y` | 单人及 1v1 的第一出生点 |
| `# player2 X Y` | 1v1 的第二出生点 |
| `# enemy TYPE X Y` | 单人敌人类型和出生点 |
| `# respawn SIDE X Y` | 团队地图侧 `1` 或 `2` 的出生和复活点 |

玩家和敌人点位格式错误或越界会使解析失败。团队点位的格式错误由团队开局校验报告，净空和支撑要求见 [对战模式](modes.md)。单人缺少 `player` 时选首个空格，重开沿用进场确定的位置。

## 水体

水体按 64 像素格采样。`Water` 从当前碰撞包围盒的顶边和底边中点取得头部和脚底位置。脚底浸入至少 8 像素时开始游泳，已在游泳时允许脚底高出水面 2 像素。深度沿连续水柱向上查询，可以跨接缝。整列都是水时深度为无穷大。 [水体查询](../core/sim/water.gd) · [地形采样](../core/sim/terrain.gd)

玩家头部浸水每秒消耗 1 点氧气，出水后每 0.3 秒恢复 1 点并清除窒息计时。氧气耗尽后每持续浸水 1.5 秒扣 5 HP。多人在正式交战时由服务端结算。敌人也受浮力与窒息影响，使用自己的氧气上限和伤害参数。水下弹丸速度按 `exp(-drag × delta)` 衰减，爆炸对水下目标的伤害和冲量乘以水材质系数 0.25。 [玩家状态](../core/sim/actor_body.gd) · [伤害结算](../core/sim/combat_simulator.gd)
