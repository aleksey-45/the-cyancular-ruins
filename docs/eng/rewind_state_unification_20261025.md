# 地形 HP 历史修复与武器、弹丸快照统一

日期：2026-10-25，目标分支 siri_v0.5.0。本次在非联机功能移植后继续处理用户提出的地形 HP 回溯问题，并统一单人与多人的武器、弹丸恢复代码；没有移植 main 的对应实现。

## 规则边界

单人是世界回溯，地形应随历史恢复。多人 Beta 是个人回溯，只恢复自身状态和仍存活的自身弹丸，地形与地面拾取物不随技能倒退。这与 main 的描述及当前 siri 实现一致。本次没有新增“多人技能回溯地形”的玩法。

当前多人预测撤销已经保存并恢复实际子格 HP，包括受损未碎和临时破坏；本次没有改动该路径或网络协议。

## 单人地形 HP

原账本只在子格死亡后记录改前 HP，导致未碎伤害没有历史，格级 HP 只能补成满血，无法恢复真实残血。

- 在 [TileDefs](../../core/sim/tile_defs.gd) 的格级/子格写入口增加可选写前通知。单人 [Level0](../../scenes/level_0.gd) 每帧每个改动格只保存一次格级网格、格级 HP 与全部 16 个子格 HP，未变地形不复制。
- [原生地形（替代旧模块）](../../native/simulation/terrain.cpp) 恢复实际记录，支持残血中间态、连续修改和时间线分支；区间二分定位，等时记录按写入逆序处理。
- 静默恢复不产生新伤害记录或破坏收益。正值 HP 之间的恢复不改几何版本、不重建碰撞；子格存亡改变才重铺贴图和更新碰撞脏块。
- 进入回溯前提交尚未入账的改动；退出裁掉已改写的未来；重开单人关卡清空实体与地形旧历史。历史回调只由单人注册，并在所属场景退出时释放。
- 联机也使用的 `Level0._restore_sub()` 保留原语义，单人完整快照由 `_restore_rewind_cell()` 应用。

## 武器只保留一套格式和恢复实现

[WorldRewind](../../core/sim/world_rewind.gd) 直接记录 `Player.capture_state(true)`，使用与 `BetaHistory` 完全相同的玩家快照格式；只读历史背包在内容未变时共享。删除旧 `_snapshot_player()` 及单人专用 `widx/wmags/wlive` 数据。

[Player](../../scenes/player/player.gd) 的单人回放入口直接调用现有 `_apply_weapon_state()`，与多人 `restore_state()` 共用：

- 完整背包 `inv`，按武器实例 ID `winst` 恢复手持装备；
- 实际弹量 `mag`，换弹状态 `rld`、进度 `rld_t`；
- 开火冷却 `fire_cd`、蓄力和开火缓冲等现有武器字段。

`_apply_weapon_state()`、`WeaponComponent.restore_inventory()` 和 `apply_mag()` 的实现没有改动，不新增第二套恢复顺序或弹量哨兵规则。单人与多人仍各自决定位置、生命和世界范围如何回放；多人保留射击序号防重复等原有处理。

单人现在也恢复完整背包成员，能回到历史空手状态。恢复自身背包不表示地面掉落物随之回溯；多人原有的这项范围边界保持不变。

## 弹丸状态与对象生命周期分开

单人原来只在回放对象首次创建时恢复速度，后续复用只更新位置和引信，退出回溯后可能沿着错误速度继续飞。多人 Beta 原来已逐帧恢复自身存活弹丸的位置、速度、引信，只是恢复代码散落在管理器中。

当前 [BulletBase](../../scenes/weapons/bullet_base.gd) 的 `rewind_state()/apply_rewind_state()` 统一供两边调用，内部复用现有 `motion_state()/restore_motion()`，保存位置、速度、行程、引信、直接命中状态，以及重建所需的射程、重力、尺寸、颜色与伤害参数。朝向由恢复的速度更新。`EnemyBullet` 通过现有覆写扩展自身伤害和水下倍率。客户端可视弹丸先做环面最近副本映射，再调用同一个运动恢复入口，线上消息字段没有变化。

对象是否存在由调用方控制：

- 单人 `WorldRewind` 按目标帧的历史 ID 对齐对象集合。缺失时依据场景路径重建；多余时回收，不留下隐藏活弹。重建对象保留历史 ID，数组排序变化不会串用不同弹丸，二次录制仍能追踪原弹丸。
- 多人 `BetaHistory` 只在当前存活的自身弹丸与目标帧 ID 之间取交集。不重建已消亡弹丸，不回溯他人弹丸；已结束但尚待销毁的对象也跳过。
- 当前仍活着、但目标帧尚未出生的自身弹丸，沿用现有多人行为：不删除、不编造历史状态，跳过恢复；回溯结束后继续运行。例如现在第 10 秒、弹丸在第 9 秒出生，个人回溯到第 8 秒时，该快照没有这颗弹丸。

共同状态恢复函数不负责创建、删除对象，也不按单人/多人分支；两种玩法的集合管理留在各自管理器。
