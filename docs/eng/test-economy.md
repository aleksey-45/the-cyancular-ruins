# 测试经济学 —— 为什么本仓要**删掉大量探针与测试**

> **这份文档的性质**:它不是"怎么跑测试"(那是 [`tests.md`](tests.md)),也不是"有哪些已知红"(那是
> [`registered-debt.md`](registered-debt.md))。它回答一个之前没人问过的问题:
> **「这条守卫值它自己的维护成本吗?不值就删。」**
>
> **由来(2026-10-05,用户裁定)**:本仓的测试面已经长到 **1.72 : 1(测试行数 : 产品行数)**,而
> 一个 AI 编码代理在**没有游戏工程经验**的情况下,会**本能地把 Web/后端/企业软件那套"防御性工程"
> 搬过来** —— 加断言、加守卫、加护栏、加边界检查。这套在**契约稳定、可纸面判定**的领域收益很高;
> 在**手感主导、数值天天调、确定性难**的游戏里,它产出的是**负资产**。用户要求:先弄清这个病的
> 外部证据,据此**删掉很多探针和测试**,并把判断依据留档。
>
> ★ 本文与 [`tests.md`](tests.md) 末节「守卫能给的保证总是比它读起来少」是**同一枚硬币的两面**:
> 那一节教你怎么**发现**坏的守卫;这一节教你**直接删掉**不值得救的守卫。

## 1. 外部证据:这个病有名字,而且被反复记录过

| 现象 | 来源 | 与本仓的对应 |
|---|---|---|
| **货物崇拜软件工程**:模仿成功实践的**形式**,却丢掉让它成立**上下文** | McConnell, *Cargo Cult Software Engineering* ([PDF](http://www.stevemcconnell.com/psd/03-CargoCultSoftwareEngineering.pdf)) | 把"每个模块都要有单元测试/每条断言都要变异验证"当**仪式**执行,不问它在本项目里的收益 |
| **臆测性通用化**(speculative generality):为**想象的**未来需求加抽象与钩子 | Fowler 的 code smell 列表([镜像](https://github.com/mjmirza/patterns/blob/main/patterns/02-code-smells/speculative-generality.md)) | 为本仓**不存在**的用法写守卫(如"非 BulletBase 混进快照"这类真机不可达的防御分支) |
| **YAGNI**:你不会需要它 | [archman-dev 的原则页](https://github.com/archman-dev/website/blob/main/docs/core-design-and-programming-principles/general-principles/yagni.mdx) · Microsoft: [Don't build more than what you need](https://learn.microsoft.com/es-es/archive/blogs/nicgrave/dont-build-more-than-what-you-need) | 同上 |
| **回归套件是墓地,而你还在往上加墓碑**:测试只增不减,没人敢删;成本是**维护费 + 假信心** | StickyMinds, *Your Regression Suite Is a Graveyard…* ([链接](https://www.stickyminds.com/article/your-regression-suite-graveyard-and-youre-still-adding-headstones)) | 本仓 140 条枚举 / 110 条默认跑,**没有任何一条因"不值"被删过** |
| **AI 代理会"修好"正常代码**:代理的修法本身是回归来源 | AWS, *バグ修正のパラドックス* ([链接](https://aws.amazon.com/jp/blogs/news/bug-fix-paradox/)) | 本批实测:Task 3 首版把 `as` 提到有效性判定之前 ⇒ **运行期中止、每次跑 36 次**,而判词照打 `OK` |
| **代理的"护栏"会误伤正常操作,代价是**连续性** | claude-code [#87121](https://github.com/anthropics/claude-code/issues/87121)(★ 我读到了全文:4 次误报打断同一场正常开发) | 过度防御的代价**不只是行数**:它让每次改动都要伺候一堆守卫 |
| **游戏架构的过度工程化** | Unity 官方开发者社区,「游戏架构设计｜过度工程化的陷阱与应对」([链接](https://developer.unity.cn/projects/69e57ff4edbc2a001f11372a)) | 游戏域特有的:抽象层/模式/守卫堆在"玩法还在变"的代码上 |
| **"每个测试一条断言"是被误传的教条** | Stack Overflow Blog, [Multiple assertions are fine](https://stackoverflow.blog/2022/11/03/multiple-assertions-per-test-are-fine) | 本仓大量"一条断言一个数值"的细粒度守卫 ⇒ 变更时**成排红** |
| **测试应当"懒"**:投入要跟着**风险**与**回报**走 | AAAI-99 workshop, *Intelligent Testing can be Very Lazy* ([链接](https://www.aaaipress.org/Papers/Workshops/1999/WS-99-09/WS99-09-008.pdf)) | 本仓缺少这条:**没有"这条守卫值多少"的核算** |
| **自动化测试需要定期评审**(而不是只增) | SSW.Rules, [Do you regularly review your automated tests?](https://www.ssw.com.au/rules/review-automated-tests) | 本仓缺"定期删"的机制 |

> ★ **诚实标注**:上表里 McConnell / StickyMinds / Unity 三份我只拿到了**标题与摘要**(前两者是 PDF 与
> 403 Cloudflare 墙,Unity 是 JS 渲染页)。**结论方向我有把握,但谁要引用原句,请自己打开链接核对** ——
> 这正是本仓"文档引用的行号会过期"的同一纪律。

## 2. 为什么"Web/后端那套"不能平移到游戏

| 维度 | Web / 后端 / 企业软件 | 本仓(2D 横版射击 demo) |
|---|---|---|
| **正确性判据** | 契约可**纸面写死**(状态码、schema、幂等性) | 大量是**手感/观感**("跳得对不对""加速够不够明显"),没有廉价判据 |
| **数值稳定性** | 业务规则相对稳定 | 手感/数值**天天调** ⇒ 钉死数值的断言每次调参都红,**是负资产** |
| **确定性** | 请求-响应可重放 | 物理/浮点/时序/帧率 ⇒ 脆弱断言与 flaky |
| **Oracle 问题** | 期望值好写 | "这一帧画面该是什么样"**没有**可写的期望值 ⇒ 只能人看图 |
| **主要验证手段** | 自动化测试 + CI | **人工试玩**;自动化只能覆盖"能纸面判定的那一小撮" |
| **失败代价** | 数据错、钱错、安全事故 | 多半是"不好玩",而**不好玩不会被断言抓到** |

⇒ **结论**:在游戏里,自动化守卫的**收益面窄**(只覆盖协议/存档/几何/回滚这类**恰好可纸面判定**的),
而**成本面一样宽**(每条守卫都要维护、要伺候、会在每次合法改动时红)。所以**取舍线必须比 Web 高得多**。

## 4. 删除判据(可执行、可否证)

> 一条守卫要被**保留**,必须**同时**过 K 组;只要命中 D 组任意一条,就是**删除候选**。
> ★ 与 [`tests.md`](tests.md) 的纪律一致:判据必须能回答「**去掉什么它才会红**」;答不出 ⇒ 删。

### D 组(删)

| # | 判据 | 为什么 |
|---|---|---|
| **D1** | **答不出"去掉什么它才会红"** | 恒真/空转守卫;本仓已抓到十次以上 |
| **D2** | **断言数为 0,判词靠打印字符串**(纯 `print` 的"探针") | 它不测任何东西;入口 grep 它的**字面量** ⇒ 改名字/改格式就静默失效。**降级为人工工具**(取图/取日志),移出默认批 |
| **D3** | **钉死"会被反复调整的数值/时序/手感"** | 每次调参都红 ⇒ 负资产;改由**人工验收**(看图/试玩) |
| **D4** | **与别处同源重复**(同一个事实有两份断言) | 「重复的真相源 + 一条盯着它的守卫 = 永久税」(`AGENTS.md` §2 自己写过) |
| **D5** | **只证明"引擎/框架/第三方库的行为"**,不证明本仓契约 | 引擎自带测试;我们重复它没有收益 |
| **D6** | **靠"读源码文本"判形态**(grep 源码里有没有某段字) | 它测的是"某人有没有写字",不是行为;可被注释/字符串/改名绕过(本批实测:字符串诱饵 ⇒ ALL-OK),且**每次重构都红**。⇒ 行为能测就测行为;**不能测就承认没覆盖**,不要拿文本形态冒充 |
| **D7** | **真机不可达的防御分支的守卫**(为"想象的"未来写) | 臆测性通用化;典型:只有测试桩能造的输入形状 |
| **D8** | **单文件 > 600 行且断言密度低** | 维护费高、读的人少;拆或删 |
| **D9** | **同一条判定类别被拆成 N 条"一条断言一个数值"** | 变更时成排红;合成**一条**覆盖该类别的断言 |

### K 组(留)

| # | 判据 |
|---|---|
| **K1** | 能红,且红起来**指向一个具体缺陷**(不是"某行字变了") |
| **K2** | 测的是**本仓契约**(协议字段/存档格式/回滚等价/环面几何/命中判定) |
| **K3** | 覆盖的是**"改坏了很久才发现"**的面(档 3:协议/输入包/回滚与快照/存档与地图格式/导出与裁剪/命中与碰撞/联机权威) |
| **K4** | **一条守卫覆盖一个判定类别**,而不是一个数值 |
| **K5** | 失败信息能让人**直接知道去哪修** |

★ **保留上限**:每条守卫都要能算清"它挡住的是哪一种**真实发生过**或**极可能发生**的缺陷"。
**算不出就不留** —— 这条比 D 组任何一条都重要。

## 5. 删除台账(逐条)

> 格式:`文件 → 判据 → 处置 → 依据`。处置 ∈ `删` / `降级为人工工具` / `移出默认批` / `合并`。
> ★ 台账**逐条累积**,每次删除都写在这里;删完的条目**不许**只留在 commit message 里。

### 5.0 第一批:源码形态守卫(D6)—— 本批最大一刀

| 文件 | 判据 | 处置 | 依据与后果 |
|---|---|---|---|
| `tests/probe/rewind_weapon_probe.gd` | **D6** | **删 35 条断言 / 净 −273 行**(1383 → 1110;diff `+38 / −311`) | 删的是 **S10 形状 12 条 + S11 全部 10 条 + S12 形状 13 条**。它们 `_code_view()` 读产品源码、断言"某段字在不在"。**本批实测两条否证**:① 塞一行 `var _decoy := "_local.input_source"` 即 `149✓ ALL-OK`;② 三支照抄的副本**同一轮内就漂移**。 |
