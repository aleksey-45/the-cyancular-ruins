# 武器、弹药与背包系统

> 本文档属于 [`CLAUDE.md`](../../CLAUDE.md) 架构分域文档。
> 涵盖范围：武器基类体系 · 弹道与命中判定 · 背包容量与数量限制 · 地面武器生成与拾取 · 数据驱动武器注册表。

---

## 一、 武器基类与派生体系

### 1. 实体射击武器 (`WeaponBase`)
- **属性配置**：通过 `@export` 暴露完整的射击参数：射击冷却时间（`fire_cooldown`）、弹丸速度、射程、尺寸、颜色、单发弹丸数量（`pellet_count`）、散射角（`spread`）、直接伤害与冲击力、后坐力反冲及镜头震动幅度。
- **瞄准方向解耦**：开火方向完全解耦于角色的水平移动朝向。调用 `fire()` 时，优先通过鼠标光标位置推导瞄准角度（`_auto_aim()`），确保角色在后退走位时射击弹道仍精准指向准星方向。
- **抛物线预瞄轨迹**：当武器启用 `preview_arc`（如榴弹发射器）时，开火准备阶段自动计算重力曲线，在界面上绘制抛物线轨迹及落点爆炸范围指示。

### 2. 即时光束武器 (`LaserWeaponBase`)
- **射线追踪模型**：继承自 `WeaponBase`。开火时不产生实体子弹，而是在发射当帧通过虚方法 `_spawn_projectiles()` 接管为射线几何追踪与一次性伤害结算。
- **网格反射追踪 (`core/sim/beam_trace.gd`)**：
  - 基于 DDA 算法在 32px/16px 子格网格中快速步进，只阻挡固体墙体（光束可穿透水体与梯子）。
  - 支持镜面反射计算（如激光枪 `laser_gun` 支持至多 5 次镜面反射），返回光束折线点集与碰墙交点。
- **命中相交判定**：光束折线各线段与目标的实际身体轴对齐包围盒（AABB）进行扩口（乘 `HIT_MULT = 1.75`），采用 Liang-Barsky 算法判定线段与矩形相交。
- **网络表现同步**：服务端作为权威方判定开火与命中，在帧末收集待同步光束报告并通过 `NetBus.rpc("beam_fired", ...)` 广播给远端客户端，由远端实例化 `laser_beam.tscn` 播放高亮淡出动画；本地射击端由客户端本地即时预测渲染，避免出现双重光束。

## 二、 弹药与伤害判定

### 1. 子弹基类 (`BulletBase`)
- **常规子弹**：在开火时由对应武器注入直接伤害（`hit_damage`）与冲击力（`hit_impact`）。
- **爆炸子弹（如榴弹发射器）**：
  - 配置 `explodes = true`。碰撞实体或墙体时执行弹性反弹；触碰实体或达到引信时间（`fuse_time` / `hit_fuse_time`）后触发范围爆炸。
  - **PvP 直接触碰机制**：对敌方玩家通过 `PLAYER_HIT_RADIUS = 40` 判定接触并触发短引信，直接触碰由服务端裁决伤害与命中确认，引信到期前不提前销毁子弹实体以保证爆炸效果完整呈现。
- **范围爆炸伤害 (`core/sim/explosion.gd`)**：
  - 核心区域（内圈 40% 半径）为满额伤害，外圈按二次方平滑衰减。
  - 视线遮挡计算（LOS）：实体处于掩体墙体后方时保留 75% 伤害；爆心近距离内圈免疫视线遮挡，避免由于墙角凸起导致近身爆炸伤害异常衰减。
- **客户端视觉子弹碰撞消除**：
  - 由于客户端本地对手为仅具备表现层的副本节点，客户端本地视觉子弹（`apply_damage == false`）在飞行中每物理帧通过 `PvpMatchClient._cull_bullet_contacts()` 检测是否触碰对手；命中后立即销毁本地视觉节点，避免视觉子弹穿透对手的画面瑕疵。

## 三、 背包管理与地面拾取

### 1. 背包容量与数量限制 (`WeaponInventory`)
- **双重限制规则**：背包同时受到容量预算（默认 8 格）与武器数量上限（默认 4 把）双重约束。
  - 轻型武器占用 2 格容量，中型武器占用 3 格，重型武器占用 4 格。
  - 最大容量 `DEFAULT_CAPACITY = 8`，最大数量 `DEFAULT_MAX_WEAPONS = 4`。
- **唯一实例追踪 (`inst`)**：
  - 背包持有列表内部结构为 `Array[Dictionary]`，每项包含 `{type, inst, mag}`。
  - 弹药量按武器实例 `inst` 独立存储，杜绝通过丢弃空弹武器再拾取同类武器实现免费换弹的逻辑漏洞。
- **切换寻址定义**：
  - `type_id`：整数标识，表示武器类型。
  - `inst`：逐把唯一的递增实例标识。网络同步输入包中使用 `winst` 传递目标武器实例。
  - `index`：本地背包槽位下标（0-based），仅在本地输入解析与 HUD 界面展示中使用。

### 2. 地面武器实体与交互 (`WeaponPickup`)
- **地面掉落物表现**：
  - 属于独立场景（`CharacterBody2D`），子节点挂载对应武器场景作为静态展示。
  - 碰撞多边形基于武器贴图像素的透明通道自动计算包围盒，统一将视觉中心反向平移对齐至节点坐标原点，确保碰撞体中心、物理位置与拾取判定圆心完全重合。
- **拾取交互规则**：
  - 按下交互键（默认为 F）一次仅拾取距离最近的一把武器。
  - 若背包容量或数量已满，则自动替换当前手持武器，被替换的武器自动掉落至角色脚下（剩余弹药随枪保留）。
  - 长按丢弃键（默认为 Q，持续时间不小于 2.0s）主动将手持武器掷出。

## 四、 武器注册表单一来源 (`data/weapons.json`)

### 1. 配置格式规范
所有武器定义集中声明于 `data/weapons.json` 的 `weapons` 数组中：
```json
{
  "weapons": [
    {
      "id": 1,
      "name": "手枪",
      "tier": "light",
      "scene": "res://scenes/weapons/pistol_test.tscn"
    }
  ]
}
```
- `id`：全局唯一的正整数类型 ID。
- `name`：界面显示的武器名称。
- `tier`：武器量级，取值为 `"light"`、`"medium"` 或 `"heavy"`。
- `scene`：武器预制体场景路径。

### 2. 运行时注册中心 (`core/sim/weapon_registry.gd`)
- `WeaponRegistry` 为纯静态无状态类，对外提供 `all_ids()`、`has()`、`scene_of()`、`name_of()` 与 `tier_of()` 等查询接口。
- 新增武器仅需在 `data/weapons.json` 中配置并创建对应 `.tscn` 场景，无需修改业务逻辑代码。自动化测试 `tests/smoke/enemy_logic_smoke.gd` 与 `tests/probe/menu_weapon_grid_probe.tscn` 会自动对注册表格式与场景存在性进行双向完整性校验。
