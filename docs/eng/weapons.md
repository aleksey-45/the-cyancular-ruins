# 武器、弹药与背包系统

单人和多人 Beta 的弹丸回溯共用 `BulletBase.rewind_state()/apply_rewind_state()`，运动、行程和引信复用 `motion_state()/restore_motion()`；额外保存重建所需的射程、重力、外观与伤害参数。单人管理器按稳定历史 ID 创建/回收对象，多人管理器只恢复当前存活且目标帧有记录的自身弹丸，状态接口本身不负责改变对象集合。详见[回溯统一记录](player.md)。

本文档介绍武器基类架构、即时光束检测、投射物弹道与伤害判定、背包容量与地面拾取交互，以及配置驱动的武器注册表。

---

## 一、 武器基类与派生体系

### 1. 实体射击武器 (`WeaponBase`)
- **模拟与场景边界**：`WeaponBase` 继承 `NativeWeaponBody : Node2D`。弹药、冷却、换弹、瞄准、缓冲开火、后坐力和稳定弹丸初态在原生，场景继续配置数值；脚本保留实例装配、声音、精灵与预瞄表现。详见[原生战斗与历史](native_combat_simulation.md)。
- **属性配置**：通过 `@export` 导出完整的武器数值：开火冷却时间（`fire_cooldown`）、子弹飞行速度、射程、尺寸、颜色、单发弹丸数量（`pellet_count`）、散射半角（`spread_deg`）、基础伤害与冲击力、后坐力位移、枪口上跳角度、镜头震颤及开火减速惩罚。
- **瞄准方向推导**：开火方向与角色的移动朝向相互解耦。原生开火核读取该 tick 的输入方向，执行俯仰与朝向规则，确保角色后退走位时子弹仍能准确射向准星方向。
- **抛物线预瞄轨迹**：启用 `preview_arc` 的武器（如榴弹发射器）在准备开火时，会自动在界面上绘制受重力影响的抛物线弹道及预期落点标记。

### 2. 即时光束武器 (`LaserWeaponBase`)
- **光束检测与判定**：继承自 `WeaponBase`。开火时不生成实体子弹，而是通过虚函数 `_spawn_projectiles()` 接管为即时射线追踪与伤害结算。
- **网格反射检测 (`core/sim/beam_trace.gd`)**：
  - 基于 DDA 算法在 32px/16px 子格网格中快速步进，穿透水体与梯子，仅被实体墙壁阻挡。
  - 支持镜面反射计算（激光枪 `laser_gun` 支持最多 5 次反射），返回光束折线顶点列表及命中瓦片。
- **相交判定**：光束线段与目标的包围盒（AABB，乘以判定系数 `HIT_MULT = 1.75`）采用 Liang-Barsky 算法进行线段与矩形相交检测。
- **网络表现同步**：服务端权威判定开火与命中后，通过可靠的 EVENT 通道广播 BEAM 事件，由远端客户端生成视觉光束（`laser_beam.tscn`）；开火者本地由客户端即时预测渲染，避免出现双重光束。

## 二、 弹药与伤害判定

### 1. 子弹基类 (`BulletBase`)
- **常规直射子弹**：开火时由武器注入伤害（`hit_damage`）与冲击力（`hit_impact`）。
- **爆炸类投射物（如榴弹）**：
  - 设置 `explodes = true`。碰撞实体或墙壁后反弹；触碰实体或引信到期（`fuse_time` / `hit_fuse_time`）后触发范围爆炸。
  - **PvP 触碰判定**：与敌方玩家距离小于 `PLAYER_HIT_RADIUS = 40` 时触发 0.15 秒短引信，服务端同时结算直接触碰伤害，子弹保留至引信到期后爆炸。
- **范围爆炸伤害 (`core/sim/explosion.gd`)**：
  - 爆炸核心区域（40% 半径内）造成满额伤害，外圈按二次方平缓衰减。
  - 视线遮挡：掩体后方目标保留 75% 伤害；爆炸中心近距离区域不受视线遮挡影响，避免因掩体边缘判定导致贴脸伤害异常衰减。
- **客户端投射物表现**：
  - 本地预测生成的投射物 `apply_damage` 设为 `false`，使用物理碰撞表现飞行与反弹；远端投射物按可靠出生事件创建并独立推进。伤害由服务端权威结算。
- **爆炸处理与碎屑**：
  - 专用服务端执行范围伤害与地形结算。爆炸动画、弹道轨迹和受击碎屑在客户端与单人场景生成。
  - 爆炸查询只返回仍存活的可破坏子格；每次爆炸使用一个 `CPUParticles2D`，以子格中心和对应材质色作为发射点与颜色，每个子格生成 10 个粒子。粒子结束时释放节点。

## 三、 背包管理与地面拾取

### 1. 背包容量与数量限制 (`WeaponInventory`)
- **双重限制机制**：背包同时受到容量预算（默认 8 格）与武器数量上限（默认 4 把）双重约束：
  - 轻型武器（`light`）占用 2 格容量；
  - 中型武器（`medium`）占用 3 格容量；
  - 重型武器（`heavy`）占用 4 格容量。
  - 默认容量 `DEFAULT_CAPACITY = 8`，默认数量上限 `DEFAULT_MAX_WEAPONS = 4`。
- **武器实例追踪 (`inst`)**：
  - 背包持有列表内部结构为 `Array[Dictionary]`，每项包含 `{type, inst, mag}`。
  - 弹药量按武器实例 ID（`inst`）独立存储，避免丢弃空弹武器后重新拾取同类武器导致免费刷新弹药。
- **寻址标识区分**：
  - `type_id`：整数标识，表示武器类型（1-6）。
  - `inst`：单把武器唯一的自增实例 ID，网络输入包与状态快照中通过 `winst` 传递。
  - `index`：本地背包槽位下标（0 起始），仅用于本地快捷键与 HUD 界面展示。

### 2. 地面武器掉落与显示 (`WeaponPickup`)
- **地面掉落物表现**：
  - 独立物理场景（`CharacterBody2D`），将对应武器预制体作为子节点用于静态展示。
  - 碰撞多边形根据武器贴图的透明通道自动计算包围盒（`SpriteBounds.from_sprite`），并将视觉中心对齐至节点原点，保证碰撞盒中心与拾取判定圆心重合。
- **拾取交互规则**：
  - 按下交互键（默认 F）拾取距离最近的一把武器。
  - 若背包容量或数量已满，自动替换当前手持武器，被替换的武器掉落至角色脚下（剩余弹药随枪保留）。
  - 长按丢弃键（默认 Q，持续 2.0 秒）可主动将当前手持武器掷出。

## 四、 联机弹丸表现

射手在输入生效时立即生成视觉弹丸。服务端向全部客户端可靠发送一次出生初态与出生 tick；射手按稳定弹丸 ID 合并本地表现，预测使用权威初态。客户端根据武器注册表创建相同弹丸场景，模拟飞行、重力、水阻力、反弹与引信。视觉弹丸的 `apply_damage` 为 `false`；生命值、地形与胜负由服务端结算。

`CombatPrediction` 在角色预测时间线上推进独立弹丸，普通弹丸、霰弹和榴弹直接触碰共用服务端的连续检测；本地开火和重放共用散射初态生成函数。激光将本地射击或已知光束放到对应射手的模拟 tick，共用路径与 AABB 相交判定。全部命中通过同一冲量入口推进，权威命中 ID、tick 与向量用于确认；完整 STATE 已包含的击退只作确认。远端瞬发攻击在开火信息到达之前无法提前预测。

服务端榴弹启动引信后，可靠发送一次 `BULLET_FUSE`，包含当前 tick、位置、速度、已飞行距离与引信进度。客户端复用同一弹丸场景的步进，预报爆点和模拟 tick，并在角色步进后推进预测冲量、HP、倒地状态及临时地形碰撞。范围、掩体、水体和径向冲量算法与权威结算共用，最终结果由服务端确认。`EXPLOSION` 确认爆炸结果，表现按弹丸 ID 合并，重放保持静默。

普通视觉子弹命中对手时销毁；团队模式穿过队友，榴弹接触队友不启动短引信。弹丸基线保留引信进度、已飞行距离和已发生直接触碰的标记，后者与引信共用一个状态字节。Beta 回溯期间取消该射手的弹丸预测与未确认爆点；恢复时按带 tick 的弹丸状态重建预测。单人模式由本地爆炸结算直接触发表现。

## 五、 武器注册表与配置规范 (`data/weapons.json`)

### 1. 配置格式
全部武器集中声明于 `data/weapons.json`：
```json
{
  "weapons": [
    {
      "id": 1,
      "name": "手枪",
      "tier": "light",
      "scene": "res://scenes/weapons/pistol_test.tscn"
    }
  ]
}
```
- `id`：全局唯一的正整数类型 ID。
- `name`：界面显示的武器名称。
- `tier`：武器量级，可选 `"light"`、`"medium"` 或 `"heavy"`。
- `scene`：武器预制体场景路径。

### 2. 运行时注册中心 (`core/sim/weapon_registry.gd`)
- `WeaponRegistry` 为静态工具类，提供 `all_ids()`、`has()`、`scene_of()`、`name_of()` 与 `tier_of()` 等查询接口。
- 新增武器仅需在 `data/weapons.json` 中配置并创建对应 `.tscn` 场景。
