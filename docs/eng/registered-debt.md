## 三、 网络通信协议技术债与重构演进计划

现行网络协议基于动态字典序列化，缺乏形式化时钟与前向冗余，列为核心架构技术债：

| 技术债项目 | 当前缺陷分析 | 影响面与风险 | 下一代重构处置方案 |
|---|---|---|---|
| **动态字典序列化** | 60Hz 快照与输入包全面采用 GDScript `Dictionary` 传递，包含数十个字符串键名。 | 序列化开销大，字符串哈希与内存颠簸频繁，引发高频垃圾回收停顿与带宽膨胀。 | 迁移至定长紧凑二进制封包（`PackedByteArray`），使用位域压缩与定点数量化。 |
| **无量纲序列计数** | 客户端依靠 `input_seq`，服务端依靠 `snap_tick`，未建立严格物理 Tick 时钟。 | 丢包重传时时间基准缺乏形式化对齐，容易引发输入饥饿或追帧堆积。 | 建立全局 60Hz 确定性物理 Tick 标尺，所有报文绑定固定 Tick 寻址。 |
| **输入包缺乏前向冗余** | `send_input` 强依赖可靠信道传输，无滑动窗口冗余备份。 | 网络抖动时可靠重传会阻塞后续输入，服务端物理模拟队列瞬间饥饿。 | 输入包改走不可靠信道，每次携带当前 Tick 及最近 3 个历史 Tick 的冗余输入掩码。 |
| **延时避让竞态** | 房间状态广播多处依赖 `await process_frame` 避让信道清零竞态。 | 时序逻辑脆弱，无法从根本上消除异步状态切换中的网络丢包。 | 引入形式化有限状态机与双向明确握手确认。 |

详细重构架构设计蓝图请参见 [`docs/eng/netplay.md`](netplay.md#七-协议设计分析与后续重构方案)。

## 四、 缺陷关闭准则

1. **缺陷修复验证**：修复完成后，需在相同测试参数下连续运行至少 2 次并全部通过。
2. **文档同步更新**：问题解决后及时从本清单中移除，并在对应模块的架构文档中补充最新的边界与行为保证。
