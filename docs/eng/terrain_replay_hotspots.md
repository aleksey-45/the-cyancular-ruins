# 地形恢复与代理轨迹的卡顿热点

2026-10-27，承接[整帧记录中的正常战斗峰值](motion_frame_trace_validation.md)。修复以已保存的原始地形补丁与角色状态作对照，没有修改输入调度、重放窗口或帧率。

## 查实的原因

`match_8_relay_final_trace` 的 client4 / frame 2402、client5 / frame 2395 处于相邻地形变化阶段。原日志的“弹丸阶段”包含地形碰撞提交，因此约 10 ms 不能全部解释为弹道计算。拆分代码路径与原始补丁复现后，有两项可重复的工作：

1. `CollisionBuilder._instantiate()` 在每次恢复或破坏时删除整个分块实体和所有 CollisionShape2D，然后重新创建九份环面形状。回滚中的 A→B→A 地形切换反复承担节点生命周期和物理形状提交成本。
2. 任意分块变化都增加全局 `geometry_revision`。`PlayerReplica` 只检查版本号是否相等，因而连远处、实际查询区域没有变化的角色轨迹也会清空。3–4 个本地重放 tick 可以累计生成 77–91 个远端运动步。

这些是局部更新粒度和对象生命周期的问题，不能归到本地角色的共享步进或一概归到网络。

## 修复

[CollisionBuilder](../../core/sim/collision_builder.gd)保留分块 StaticBody2D 和仍然需要的 CollisionShape2D，只更新不同的尺寸、位置与数量。矩形形状资源按尺寸只读共享，每块最多缓存 64 种尺寸。相同布局不重新提交，也不推进几何版本。

[Level0](../../scenes/level_0.gd)按实际改变的 16px 子格累计每块变化包围盒；不知道变化范围的完整/手工标记仍按整个分块处理。几何构建维护最多 128 项变化区域记录，完整建图使用全域标记。

[运动代理](../../scenes/player/player_replica.gd)缓存生成轨迹时覆盖的实际轴向扫掠区域；另保守覆盖攀爬脚点、下方格、水体与姿态读取。几何版本变化时，只在变化区域与查询区域相交时废弃轨迹。相交判断包含九个环面映射；历史不足、全图重建、外部直接改变版本时保守失效。未来未查询到的部分仍在实际请求时生成，因此新障碍进入原先空的路径不能漏检。

同一 PhysicsServer 查询缓存仍按全局版本清理；本轮缩小的是已经生成的运动轨迹失效范围，没有放松其原生碰撞查询键或强行复用接触结果。

新增细分记录 `combat_simulation` 和 `terrain_collision_commit`，并记录实际新生成运动步、保留/失效轨迹和提交分块数量。嵌套阶段保持原有墙钟口径。

## 使用原始数据的离线对照

数据来自 client4 的完整原始报文记录：保留 tick 2330 的 128 个实际改变子格及此前 14 个地形补丁。地形对照交替写入补丁前、后的 HP，再完成同样的两块碰撞更新；预热后每版 60 个切换样本。不是把整个 31 ms 墙钟峰值原样重现。

| 两块地形切换，中位耗时 | 修改前 | 修改后 |

矩形分解算法没有改变，表中该项的时间差包含运行环境与资源缓存差异；节点/形状提交才是本轮直接修改的路径。没有据此承诺整帧提升倍数。

## 验证与证据

全量回归 73/76；失败仍是原有的精英掉落退出崩溃、预瞄探针空节点、设置页旧文案。收窄到实际子格范围后，另复核全脚本、本地预测域、播放/碰撞生命周期、地形历史、预测历史复用和地形回溯，六项通过。弹丸迟到 23 个场景通过。
