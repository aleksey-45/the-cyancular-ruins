# 事件影响检查

2026-10-26。前轮错误地把新 TIME_REWARD 直接当成整组重放理由，虽然命中与爆炸确认已经检查，奖励入口仍绕过了影响判定。本轮补齐这一缺口，并审计所有请求重放的入口。

2026-10-27 的预测范围改为[本地完整预测与只读运动代理](local_prediction_design.md)：账户历史仅覆盖本地，远端输入提示不再触发重放。下文对局与耗时仍为 10 月 26 日的历史记录。

## 判定原则与入口审计

收到消息不等于预测结果失效。先检查消息是否已覆盖/重复，再验证它改变了哪些模拟数据或已使用的依赖。能够只修正独立数据且证明后续行为不变时，保留已算结果；只从首个行为变化的 tick 重放。缺失历史或依赖时明确回退，不假定没有影响。

| 入口 | 重放前检查 |
|---|---|
| STATE | 同 tick 角色、弹丸、地形、边界和后续有效命令；仅账户不同先重算账户依赖 |
| 远端输入 | 不进入本地预测域，不建立远端输入回滚历史；等待权威运动代理更新并检查实际依赖 |
| 弹丸出生/引信 | 出生身份或历史完整运动状态是否不同；已覆盖结果只补元数据 |
| HIT / BULLET_END | 实际受击结果与接触是否不同；源位置变化但结果一致时保留；结束 tick 相同仍须核对 HIT |
| BEAM | 参数相同直接确认；路径/宽度变化时用原阶段目标矩形检查接触结果，不为未命中的几何变化重放 |
| EXPLOSION | 原爆炸 tick、类型、位置；命中与地形依赖分别检查 |
| TIME_REWARD | 账户轻量重算，验证实际加速倍率及回溯许可，而非只按新 serial 排队 |
| BULLET_REWIND | 过期/重复、同 tick 弹丸状态及未来已模拟的回溯模式；一致时不删除节点 |
| 地形补丁 | 只写不同子格 HP，保留历史供同 tick 校验；未记录足够查询依赖、不能证明安全的真实历史地形差异仍回退 |
| FIRE / KILL / 房间/UI 事件 | 表现、结算或生命周期处理，不直接要求物理重放 |

“参数不同”并不自动证明整个世界需要重放；但不同运动锚点、未知攻击历史或几何依赖不完整时，仍需要保守恢复。没有使用最终位置差为 0 来推断所有中间依赖一致。

## 账户检查的实现

[PredictionEconomy](../../core/net/prediction_economy.gd) 使用纯数据账户副本，复用正式 [TimeEconomy](../../server/time_economy.gd) 的加速判定和 [GrainAccount](../../core/sim/grain_account.gd) 的消耗、回复、上限裁剪。它不步进角色或弹丸，不查询物理空间，不恢复地形，不创建音画节点。

实际步进为每 tick 保留加速读取时的控制锁与倍率、回溯阶段依赖、真正已应用的奖励。检查从最近有效账户检查点开始，分别重算旧账本和加入新确认后的账本：

1. 按角色顺序检查加速倍率，随后应用该角色阶段的奖励。
2. 检查回溯许可与实际回溯消耗。
3. 回复账户，再依次应用攻击阶段和规则阶段的奖励；同阶段按服务端 serial 排序。
4. 验证旧账本重算与原历史完全一致，避免漏记操作后错误复用。
5. 新旧行为相同时提交账户和对应历史；新旧行为首次不同在 T 时，只提交 T 之前的账户前缀，并从 T 重放世界。

例如 tick 546 末奖励 20 颗粒，窗口内资源始终充足时不会请求世界重放；若它让 tick 549 的加速首次可用，就保留到 548，从 549 开始重放。不能仅给当前余额加 20：后续消耗、锁定解除、其他奖励的上限裁剪和重复确认都需要遵守原时序。

STATE 账户差异使用同一检查器，复用资格查询保持只读，提交复用时才改写已验证的历史。新输入或其他事件使更早结果失效时，仍采用更早的失效 tick。

## 验证范围

[event_impact_probe](../../tests/probe/event_impact_probe.gd) 对照完整恢复，检查每 tick 的账户、角色、弹丸与地形。覆盖资源充足、资源耗尽、透支锁延迟解除、控制锁、回溯许可、各奖励阶段、不同角色、收入上限、改写奖励、当前/未来/已覆盖收入、STATE 仅账户不同及依赖历史缺失。

[prediction_reuse_probe](../../tests/probe/prediction_reuse_probe.gd) 额外检查受击源位置改变而结果不变、光束几何改变而接触不变，以及真实接触变化。跨 lane 探针增加匹配及重复回溯确认，保留原有过期事件、相等锚点及较新 STATE 优先断言。

本轮验证记录位于 `.test_logs/event_impact_20261026_155531/`：

- 241 个脚本加载通过；事件影响和状态复用对照通过；7 项联机回归通过，其中跨帧回溯覆盖 23 个场景。
- 单元回归 64/68。4 项失败分别是精英掉落用例退出时原生崩溃、路径检查依赖临时截图、旧预瞄节点断言、旧设置标签断言，均为此前已记录的问题；没有把全套回归标为通过。
- 只运行一局八人 Beta 大乱斗，GNS 经本地 EasyTier 中继，禁用 P2P，战斗 90.025 秒。1,352 批奖励检查保留世界结果，另有 2 批收入尚未消费；本局没有奖励检查的历史缺失回退。192 次爆炸确认、2,468 次命中确认和 13 次回溯确认保留模拟。八个客户端最终位置误差均为 0，无脚本或解析错误。
- **性能项未通过**：战斗期间共有 650 条超过 50 ms 的帧间隔记录，客户端最大 231.236 ms，服务端最大 148.091 ms。普通校正记录 18 次，另有 4 次时钟重置伴随的位置变化；其中仍有超过 32 px 的变化。最终收敛不能证明中途流畅。

峰值附近，客户端日志显示 STATE 排队 602～657 ms，收包间隔约 37～43 ms、轮询间隔约 82～100 ms；连续回调分别重放 17～22 tick，各耗时约 52～76 ms。对应 `effect_review` 为空，不是这次奖励检查要求重放；服务端同期也有卡顿。日志记录和后台刷盘的耗时明显小于该峰值，但没有捕获最初阻塞点，也没有单独测量新历史记录的开销，因此不能把初始原因确定为网络、系统负载或某个函数。

本轮证明影响检查实际生效，并未证明整体性能问题解决。没有再追加对局或修改调度，也不把不同消息到达顺序的两局结果作为严格 A/B 性能对照。对局使用现有诊断日志，关闭脚本 profiler、外部采样器和额外逐函数计时；引擎标准输出通过持续排空的管道写入文件，避免直接重定向触发同步刷盘。
