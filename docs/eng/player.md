# 玩家角色系统

本文档介绍玩家角色的运动学控制、姿态碰撞管理、组件化架构、输入源抽象及弹药预测同步机制。

2026-10-27 起，高频运动与武器推进由 `NativeActorBody : CharacterBody2D` 和 `NativeWeaponBody : Node2D` 执行，`Player` 脚本与组件提供场景、背包和表现接口；当前边界见[场景内原生模拟](native_scene_simulation.md)与[战斗/历史迁移](native_combat_simulation.md)。

---

## 一、 角色运动与操作手感 (`CharacterBody2D`)

### 1. 移动与跳跃机制
- **水平移动**：采用平滑插值加速与减速，提供灵敏的急停与启步操控感。
- **跳跃系统**：集成土狼时间（离开平台边缘后的短暂窗口内仍允许起跳）、跳跃输入缓冲（落地前预按起跳键）以及可变跳跃高度机制（中途松开跳跃键可提前截断上升速度）。
- **冲刺技能**：持续 0.4 秒，沿移动朝向快速位移；空中冲刺期间垂直重力大幅降低（乘以系数 `charge_air_gravity_mult = 0.35`）。
- **碰撞移动**：`ActorStep` 在边界准备输入、武器倍率和共享地图上下文，调用 `NativeActorBody`。原生运动核将普通速度与击退速度相加，按 X、Y 轴依次移动。地形通过 Godot `move_and_collide` 查询，角色之间计算矩形阻挡；碰撞轴同时裁掉普通速度和击退速度。接地状态随移动结果保存到快照。
- **联机角色阻挡**：`ActorCollider` 是关联角色与碰撞层的 `RefCounted` 数据对象，缓存姿态和变换基底对应的矩形。每次移动先读取其他角色的当前位置，将边界映射到最近的环面副本；X、Y 两轴共用这份边界列表。按阵营筛选阻挡对象，倒地矩形随朝向旋转。
- **步进中的几何准备**：一次 `move_by` 只读取一次活动形状、局部变换、形状矩形和查询 RID；每轴重新读取实际全局变换，保持先 X 后 Y 的计算顺序。数据不跨角色阶段或 tick 复用，蹲伏、倒地、回滚恢复仍选择当时的形状。矩形裁剪预先提取本角色不变的边界，避免在每个对手上重复计算。
- **地形查询缓存**：保留完整键比较、地形版本失效和最多 256 条的原有策略；FIFO 使用键的环形队列，淘汰时不再复制全部字典键。此处缓存原生地形行程与接触结果，角色阻挡不进入该缓存。

### 2. 下蹲与下冲
- **下蹲姿态**：在地面且按住下蹲键（默认 S）时进入下蹲姿态，支持蹲伏移动；空中松开按键落地后不会误触发下蹲锁定。
- **空中下冲**：在空中按住下蹲键可触发下冲，快速向下俯冲砸向地面。

### 3. 逻辑碰撞箱与动画
- 玩家场景定义站立与蹲伏两个矩形；站立、移动、跳跃和冲刺共用站立矩形。单人、服务端和预测共用这两个定义。
- 两个矩形宽度、水平中心和脚底相同，蹲伏只降低顶部。起身时检查地形和角色净空，空间不足时保持蹲伏。
- `Pose` 和姿态锁控制动画，碰撞箱根据 `is_squat` 与倒地状态选择。倒地使用旋转后的站立矩形。

### 4. 受击、无敌帧与倒地状态
- **受击与击退**：显式武器冲量保存在 `knock_velocity`，与普通速度一起结算移动、碰撞和接地，随后指数衰减。单人受击使用无敌帧，PvP 的弹丸伤害由服务端逐次结算。
- **倒地状态**：生命值归零时进入倒地状态，旋转碰撞体并清除接地状态。共享步进继续处理重力与击退，停止操作动作。
- **单人模式原地重置**：按 R 键调用 `Level0.restart_single()`，还原破坏的瓦片、重置敌人与弹药，并将满状态角色放回初始出生点。

## 二、 组件化架构设计

为了降低玩家主脚本（[`scenes/player/player.gd`](../../scenes/player/player.gd)）的代码复杂度，角色业务拆分为独立的子组件节点。各子组件不自行运行 `_physics_process`，完全由玩家根节点统一调度：

```text
Player (NativeActorBody，继承 CharacterBody2D；物理根节点)
 ├─ Visuals (角色与武器的视觉表现偏移节点)
 │   ├─ AnimatedSprite2D
 │   └─ WeaponSlot
 ├─ ClimbComponent (原生攀爬状态的兼容接口)
 ├─ CombatComponent (原生受击/击退入口与复活、表现适配)
 ├─ WeaponComponent (背包武器管理与原生武器装配)
 └─ SwimComponent (原生水体状态的兼容接口)
```

- **物理与表现分离**：
  - 输入数据交由共享的 `ActorStep` 进行物理步进，依次推进武器、游泳、攀爬、移动与碰撞检测，并返回触发的动作列表。
  - 联机手动模拟通过 `Player.enable_manual_simulation` 使用即时位姿的原生查询体。每个 tick 提交变换，再执行运动查询；服务端、本地预测及远端运动体共用此生命周期。
  - 在首次预测、单人模式或服务端权威模拟时执行这些动作。
  - 预测回滚与重放期间仅推进逻辑状态，重放完成后由 `Player.present_tick` 统一更新动画、预瞄线、受击闪烁与 HUD 界面。
  - Beta 加速随固定模拟 tick 的输入和颗粒账户推进；权威校正先恢复账户，再重放输入、消耗与回复。渲染只读取结果。
  - 网络权威消息在每个显示帧首次物理回调或表现回调接纳；后续到达的模拟消息保留到下一帧。按最新 STATE 覆盖和实际影响审核后合并最早失效点，一个显示帧最多一轮网络触发重放。
  - 远端只执行受地形约束的运动代理；输入提示不触发本地重放。仅当运动阻挡、弹丸接触或其他本地依赖变化时审核本地失效后缀。
  - 战斗预测同时推进受力、生命值和倒地碰撞；致死后使用尸体运动与碰撞，停止接收后续预测命中。权威 HIT 给出命中后 HP 与死亡朝向，STATE 提供完整恢复基线。
  - 已知爆炸的子格破坏参与同 tick 的临时碰撞预测；重放先恢复权威 HP，再推进爆炸。权威地形更新按 tick 覆盖临时结果。
- **视觉平滑校正**：
  - `CharacterBody2D` 物理根节点始终位于实际逻辑位置。
  - 预测偏差通过 `Visuals` 节点的视觉偏移在 50ms 内平滑衰减，角色精灵与武器共同平滑。
  - `shot_origin` 开火原点剔除了该视觉偏移，确保网络预测的视觉平滑不会影响弹道发射方向。
- **受击与伤害结算**：
  - 生命值、倒地状态、击退速度与无敌帧保存在原生角色中，`CombatComponent` 的属性转发到同一份状态；受击、冲量与倒地核由原生执行，组件保留无敌/回溯入口适配及复活等管理。
  - `simulate_hit` 为权威模拟与已知攻击预测提供同一个状态更新入口；预测倒地后停止动作并切换碰撞，权威恢复和重放可以撤销该分支。战绩、掉落和复活仍由服务端执行。
  - `Player.play_hit_feedback` 为单人受击与联机 HIT 事件提供音效、精灵缩放挤压、全屏暗角与镜头震颤。重放历史输入时不重复触发死亡或受击音画表现。
- **对外接口规范**：对外统一暴露 `take_hit()`、`is_downed()`、`apply_recoil()` 等方法及 `hp_changed` 信号，接口契约由测试用例 已移除的 player_contract_smoke 验证。

## 三、 输入抽象接口与网络注入

### 1. 输入源统一抽象 (`core/net/player_input.gd`)
- 抽象基类 `PlayerInput` 定义了 `get_axis()`、`is_held()`、`is_just_pressed()`、`is_just_released()` 等标准输入方法。
- 具体派生类通过 `source_kind()` 区分来源：
  - `LocalInputSource`：本地玩家输入，直接采集键盘与鼠标操作。
  - `PacketInputSource`：服务端使用，解析客户端上传的网络输入数据包。
  - `AIInputSource`：人机 AI 行为驱动源。

### 2. 输入冻结与瞄准覆盖
- 开局倒计时（`COUNTDOWN`）阶段将 `frozen` 设为 `true`，所有移动与开火输入返回中性零值，锁定角色行动。
- 通过 `get_aim_dir_override()` 钩子支持网络同步瞄准方向。
- 共享 `ActorStep` 每 tick 把记录解码到复用的 `ActorInput`，控制锁在解码时应用一次。移动、游泳、攀爬和武器直接读取轴及按键位，不经过输入源的字符串映射、虚方法或逐次冻结检查。原始持续轴／按键单独保留，权威快照仍能在下一步解锁后延续原始输入；瞄准不受锁影响。
- 按键位定义在 `ActorInput`，`PacketInputSource` 保留原有常量名作为别名，网络编码保持一致。切枪仍由输入记录的实例 ID 驱动，本地数字键在打包时已转换为实例请求。
- 游泳、攀爬和战斗组件明确持有 `Player`，直接访问角色属性；武器公开的 `Node2D` 装配契约保持兼容。相同瞄准角度和缩放不重复写入武器节点，开火继续读取原生枪口变换。

## 四、 弹药权威状态与预测回滚同步

单人 `WorldRewind` 与多人 `BetaHistory` 都记录 `Player.capture_state()` 格式。武器部分统一由 `_apply_weapon_state()` 恢复，包括完整背包 `inv`、手持实例 `winst`、实际弹量 `mag`、换弹状态/进度及开火冷却。单人旧的 `widx/wmags/wlive` 格式与专用武器恢复循环已删除；单人记录时复用只读历史背包，后续修改不能覆盖旧快照。

单人 `rewind_restore()` 与多人 `restore_state()` 保留各自的运动和生命处理入口，武器恢复调用同一个函数。恢复自身背包不代表回溯地面掉落物；多人个人回溯的世界范围保持原规则。

1. **弹药赋值机制 (`WeaponComponent.apply_mag`)**：
   - 武器节点已在场景树中时，直接写入 `mag_ammo`；未进入场景树时暂存至 `pending_mag`，待武器节点的 `_ready()` 触发时消费应用。
   - 弹药变化直接同步写回背包库存。
2. **武器就绪标记 (`WeaponBase._mag_ready`)**：
   - 武器节点初始化完成时将 `_mag_ready` 置为 `true`。开火逻辑中的空弹判定依赖该标记，确保弹药数据初始化完成前不会误触发换弹动作与音效。
3. **背包状态恢复与事件合并**：
   - 切换权威手持武器前先卸下旧武器，再写入新库存，避免旧弹药回写污染新背包。
   - `inventory_changed` 在表现更新时比较最终的武器实例、类型、选中项与容量；布局变化时刷新 HUD 节点，弹药数字按当前武器直接更新。
