# 地形

`GDScript → 指令 → Terrain → 事件 / 快照 → GDScript`

`Terrain` 独占宏观网格、子格材质、HP、版本、预测差分、权威基线、单人回溯和碰撞布局。单人、服务端与客户端预测共用伤害、爆炸扫描和碰撞查询，按用途启用不同历史与输出。

## 指令与读取

`load_terrain()` 装载地图及材质配置。接触伤害、爆炸、权威补丁、检查点恢复和时间回溯通过领域方法同步执行。脚本负责地图解析、场景装配、AI 策略、会话、账户结算和表现；角色、弹丸及预测战斗直接访问地形。

网格和子格 getter 返回缓存的只读视图；HP 打包快照在数据版本变化时更新。调用方不得修改这些视图，也不能把持有视图理解成一份独立可写地图。

## 局部提交与输出

16px 子格变化只标记受影响的碰撞分块。正 HP 之间的伤害和恢复只更新 HP；子格存亡改变才标记碰撞分块和显示。每个碰撞块覆盖 12×12 个宏观格，布局缓存保留 4 份，形状句柄按尺寸共享。

碰撞变化在下一次依赖查询前由 `flush_collisions` 提交，显示由 `flush_visuals` 按最终状态提交到 TileMapLayer。几何直接写入物理空间：每个分块一个静态体，形状槽位按索引更新，场景树不参与。静态体改动形状后必须重设自身变换，否则同一物理帧的宽相仍是旧几何；`submit()` 在写入形状的同时完成这一步，因此恢复后立刻查询就能看到新碰撞。

## 接缝与物理拓扑

物理地形只补接缝附近的必要镜像：中部孤立墙只有一份形状，贴边形状向对面补一份，贴角形状再补一份角落副本。判定范围是 `CollisionWorld.SEAM_REACH`，覆盖一次最大位移、形状半径与 safe margin。完整 3×3 平铺只是 TileMapLayer 的可视副本，不是物理世界；接缝带之外没有副本，因此角色、弹丸与光束的物理坐标必须保持在规范区间。

接触结果通过碰撞 RID 查询地形层，不要求关联场景节点。相同占用布局不重复改动物理形状。

## 光束与视线

`trace_beam()` 用引擎射线求几何：命中点与法线来自物理空间，反射按法线折返并保留剩余总长度。光线在接缝处分段：查询位置回绕到规范区间，返回的折线保持视觉连续，因此长光束不需要为内部墙创建镜像。返回的接触坐标仍是宏观格，供武器结算瓦片伤害；16px 子格的孔洞直接体现为形状缺口。

`line_of_sight()` 也使用引擎射线，但按环面最短位移分段：每段都在规范世界内查询，跨接缝的连线只检查真实存在的那段路径，不会退化成穿过整张地图的直线。

## 网络与历史

网络输出按子格合并最终 HP，每 tick 取出；破坏收益按角色汇总。通知为一次批量变化，恢复不生成新伤害或收益。碰撞块按占用签名复用布局，爆炸核缓存子格候选；两者都不保存角色轨迹依赖。

单人历史在记录边界保存变化宏观格的首个改前值，二分定位时间区间后逆序恢复，保留残血与混合材质；结束回溯时裁剪未来。

联机预测保存按 tick 分组的稀疏差分和历史代号。权威确认平移基线、保留尚未覆盖的未来预测，并裁剪确认历史和爆炸核；完整契约见[预测复用](prediction_reuse.md)。
