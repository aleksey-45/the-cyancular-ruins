# 爆炸与预测验证

2026-10-22，Windows x64、Godot 4.7.1、GNS 工作区。本文记录爆炸处理性能；角色碰撞实现与校正数据见 [角色校正与碰撞验证](correction_validation.md)。正式实现使用每 tick 地形批量消息、物理帧碰撞提交及共享 Beta 加速步进。

## 实现

- 专用服务端结算爆炸伤害和地形。客户端与单人场景播放动画、轨迹及碎屑。
- 碎屑查询存活子格，每次爆炸创建一个点发射器，每个子格 10 个粒子，发射点按环面最短位移定位，颜色按材质设置。
- 服务端每 tick 合并子格最终 HP，发送一条 TERRAIN。客户端先应用本批 HP，在下一物理帧按块更新碰撞，然后应用版本一致的 STATE。
- 同一权威帧中的远端碰撞体位置、姿态和倒地旋转先于本地重放更新。
- Beta 加速在服务端、预测和重放中共用账户消耗逻辑。重放先恢复权威账户，逐 tick 推进消耗和回复。
- 视觉校正为 50 ms。≥128 px 的校正逐次记录；计数阈值为 8、32、128 px，排除控制阶段切换和 Beta 回溯。

1024×768 合成地图、1508 个存活树干子格、350 px 爆炸半径；两组均生成 15080 个粒子。计时覆盖子格查询与发射器创建，不包含完整生命周期 CPU 或 GPU 绘制耗时。

| 创建方式 | 节点 | 三次耗时（ms） | 中位数（ms） |
|---|---:|---|---:|
| 逐子格发射器对照 | 1508 | 21.859、18.973、26.797 | 21.859 |
| 当前点发射器 | 1 | 4.817、5.293、7.431 | 5.293 |

本机该固定负载的创建耗时中位数减少约 76%。原始脚本和输出为 `.test_logs/explosion_cost.gd`、`.test_logs/explosion_cost.log`。真实渲染截图为 `.test_logs/explosion_particles.png`，测试检查粒子自动释放和服务端实际地形伤害。

## 八人公网中继

120 秒真实 Beta 大乱斗，三台公网 UDP 中继候选，禁用 P2P，各客户端轮换候选顺序；一次 token 重连。八客户端以无头模式运行，测试开局使用各自分配的武器，覆盖榴弹。八端自然结束、返回原房间，停止输入后位置误差均为 0 px。碎屑渲染另用 OpenGL 场景探针检查截图。

| 指标 | 结果 |

| 权威榴弹爆炸 | 36 次 |
| 爆炸处理平均 / 最大 | 2.675 / 6.204 ms |
| 权威模拟 tick 最大值（整局） | 26.713 ms |
| >50 ms 的权威 tick 采样窗口 | 0 |

到房主的 200 条路由采样均为 `relay(2)`，450 条直接邻居协议采样均为 UDP。每秒传输统计中，可靠队列积压为 0，发包队列最大采样为 1.48 ms。

## 校正与限制

本页爆炸负载对局的 ≥8 / ≥32 / ≥128 px 校正为 963 / 248 / 36 次；其中 28 条大幅校正的权威击退长度超过 100 px/s，其余 8 条没有明显击退。当前碰撞实现的两轮八人结果及逐次记录见 [角色校正与碰撞验证](correction_validation.md)。

独立行为测试验证加速启停、账户耗尽及带击退状态的首次预测和重放与逐 tick 参考结果一致；测试也验证未来地形等待、批量碰撞提交和倒地碰撞体。实际多人接触仍取决于远端权威状态，本局结果不等同于所有场景均无校正。

另一场流程对局没有产生榴弹爆炸，其数据位于 `.test_logs/network/gns_explosion_prediction_fix_relay_8/`，不用于爆炸性能结论。
