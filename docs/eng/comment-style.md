# 代码注释规范（`.gd` / `.tscn` / `.sh`）

> 本规范只管代码注释的**形式**与**内容边界**,不管"该不该写注释"。`.md` 文档照常用 Markdown —— 那里会被渲染。

## 1. 不写 Markdown

Godot 内置帮助面板渲染 **BBCode**(`[b]` / `[code]` / `[param x]` / `[method foo]`),不渲染 Markdown;代码在 GitHub 上也按代码渲染。`**加粗**` 与反引号在代码注释里都是字面字符。

- 注释里只用两个标记:**`★`**(值得注意的不变量或陷阱)与 **`⚠`**(已知边界 / 已登记的债)。要强调就换行、分段、或把结论前置。
- 反引号包标识符(`` `TOP_OFFSET` ``)允许保留,不再新增;同一段里出现 3 个以上反引号,改成成句的中文。

```gdscript
# 反例：README 里能渲染，这里不能
# 这个数**不是**随手取的：记分条**实测高 52px**
# 正例
# 这个数不是随手取的：1v1 记分条实测高 52px（见 docs/eng/ui.md）。
```

## 2. public API 用 `##` + BBCode

- `class_name` / `signal` / `func` / `@export` / `const` 之上用 **`##`**;只有 `##` 会进编辑器的 F1 帮助与 Inspector 提示。
- 需要格式化时用 BBCode:`## 命中时把 [param damage] 交给 [method take_hit]。`

## 3. 读者模型:只读这一个文件的人

- 新克隆里只打开这一个文件的人,必须**不打开第二个文件**就能看懂这句注释。
- 代号就地展开成 `别名(= 路径)`,例如 `回局凭据表(= docs/eng/netplay-rooms.md)`。
- 不可只指向 gitignore 的目录(`.superpowers/`),也不可指向仓库里不存在的文件。
- 反面形态:`相③` / `Task N` / `B2 甲案` 这类内部编号 —— 定义不在仓库里,读者无从查。

## 4. 只写不变量 / 边界,不写过程

- 注释里**不写**:任务编号与批次记录、评审过程、版本之间的差异、改动文件清单。那些属于 commit message。
- 可以写:不变量、反直觉的引擎行为、边界与已知缺口、单一真相源指针。
- 一条规则最多带一句约束:"不可 X,否则 Y"。

## 5. 单点注释 > 5 行 ⇒ 拆

- 一个声明 / 一个分支之上的连续注释超过 **5 行**时:过程与实测记录搬进 `docs/eng/<域>.md`,原处只留**一行指针**;不变量压到 5 行内,先写结论再写约束。

## 6. 被推翻的结论直接删

- 同一段注释里同时存在"已被推翻的结论"与"现行结论"时,读者无法分辨哪句算数。版本差异在 `git log` 里,不留"原句在上"。

## 7. 引用守卫的注释必须写清"它还是不是守卫"

- 写成"有守卫:`X` 会钉住"之前,先确认 `X` 存在;没有守卫就写 **"零守卫"**。
- 守卫被删时,注释与守卫同批改;跨文件引用一起改,不留死指针。

## 8. 注释额度:>100 行的 `.gd` ≤ 15%

**口径**:`整行注释行 ÷ 非空行(代码行 + 整行注释行)≤ 15%`。空行不计;`.gd` 之外的文件不受此限。

### 8.1 五步

1. **先分三类**:必须活下来(防回归的一句话不变量 / 反直觉陷阱 / 单一真相源指针)、搬走(成套实测读数 → `docs/eng/<域>.md`,原处留一行指针)、直接删(任务编号 / 日期 / 评审记录 / 版本差异 / 重复事实 / 能从代码一行读出的)。
2. **不许动代码**:只改整行注释;行尾注释可以删短,但**不许碰字符串字面量里的 `#`**。
3. **不许重排声明**:注释删完后代码语句必须逐字节同一。
4. **Markdown 一律去掉**;内部编号按 §3 展开或删。
5. **压到 ≤15% 就停**,不要顺手把上层逻辑也重写。

### 8.2 与 §5 的关系

§5 是**质量**规则(别把注释写成小作文),§8 是**额度**规则(总量上限)。两者冲突时先满足 §8,再按 §5 组织剩下的注释:留最关键的几条、每条一行。
