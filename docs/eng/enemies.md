# 敌人系统

本文档说明游戏中敌人实体的继承结构、行为状态机、物理模拟、时间回溯兼容机制及数据配置规范。

---

## 一、 继承结构

敌人体系基于 Godot 的 `CharacterBody2D` 构建，继承关系如下：

```text
CharacterBody2D
 └─ EnemyBase (基础属性、状态机、物理模拟、受击与死亡闪烁)
     ├─ EnemyJumpBird (近战跳跃敌人)
     ├─ EnemyBlackBird (乌鸫，瞬移精英敌人)
     └─ EnemyFlyBase (飞行与 A* 寻路基类)
         └─ EnemyFlyBird (巡逻飞行与抛物线投弹敌人)
```

---

## 二、 核心机制 (`EnemyBase`)

### 1. 基础属性与状态机
- **导出参数**：包括生命值（`hp`）、碰撞伤害（`contact_damage`）、击退力度（`knockback_strength`）与击退衰减率（`knock_decay_rate`）。
- **状态机**：基类使用整数 `state` 管理当前行为状态，各派生类定义各自的 `enum State`，并在每物理帧覆写 `_ai(delta)` 与 `_anim_update()`。
- **转向防抖**：通过 `_set_facing()` 限制转身频率，两次转身之间至少间隔 0.5 秒（`turn_min_interval`），防止玩家在临界距离徘徊时怪物频繁来回掉头。

### 2. 受击与死亡表现
- **受击闪白与死亡闪烁**：
  - 受击时触发 0.1 秒受击白闪（`_hit_flash_time`）。
  - 生命值归零时进入死亡流程，播放 0.5 秒死亡闪烁（`death_flash_time`）。
  - 渲染通过 `_flash_update()` 调节材质颜色；乌鸫（`EnemyBlackBird`）使用自定义轮廓 Shader，通过重写着色器参数实现等效反馈。

### 3. 死亡物理与尸体处理
- **尸体物理模拟**：敌人死亡后不会立即销毁节点，而是禁用 AI 决策逻辑，保留 `CharacterBody2D` 的常规重力、摩擦力与碰撞检测。尸体在空中会自然下落，滑行时受击退衰减逐渐停下。再次被攻击时仅结算击退推力，不再重复扣血。
- **单人模式时间回溯兼容**：
  - 在单人模式启用回溯录制时（`WorldRewind.hold_corpses == true`），死亡闪烁结束后的尸体不会直接销毁，而是暂时隐藏（`visible = false`）并将其碰撞层置为 0（`collision_layer = 0`），避免在场上留下看不见的空气墙。
  - 当玩家发动时间回溯，倒流回该敌人死亡前的时刻时，系统会重新恢复该敌人的可见性与物理碰撞层。测试用例参见 `tests/probe/rewind_phantom_probe.gd`。

## 三、 各类敌人行为特征

### 1. 飞行鸟 (`EnemyFlyBird`)
- **状态机**：包含沉睡（`SLEEP`）、起飞（`TAKE_OFF`）、巡逻飞行（`FLY`）、投弹（`SHOOT`）、自爆冲撞（`CHARGE`）与返航（`RETURN`）。
- **攻击逻辑**：
  - 飞行巡逻时，根据玩家移动速度计算提前量，发射受重力影响的抛物线炸弹。
  - 生命值低于 25% 时，单向切换至 `CHARGE` 状态，朝玩家发起直线自杀式冲撞，该攻击无视玩家无敌帧，撞击地形或玩家后自毁。
- **寻路与避障 (`EnemyFlyBase`)**：
  - 基于飞行碰撞盒在环面网格上执行 A* 寻路。
  - 遇到悬空障碍卡住时，自动沿水平方向脱困。
  - 支持站立与飞行两种碰撞体尺寸的动态切换。

### 2. 跳跃怪 (`EnemyJumpBird`)
- **行为模式**：地面巡逻、蓄力前跳接近玩家、后撤步调整距离，并在适当时机发起空中扑击。
- 死亡后保留地面物理碰撞。

### 3. 精英敌人：乌鸫 (`EnemyBlackBird`)
- **精英属性**：
  - 节点准备时设置元数据 `set_meta("elite", true)`。
  - **免疫时间回溯**：单人模式下玩家发动回溯时，乌鸫不受影响，依然能自由移动和攻击。
  - **同步时间加速**：玩家发动时间加速时，乌鸫获得与玩家相同的加速倍率。
  - 击败后掉落 300 点时间颗粒结晶（`GrainCrystal`）。
- **行为循环**：
  - 沉睡待机 → 随机巡逻游走 → 周期性检索玩家身后 2~4 格的地板落点（结合视线检测）→ 蓄力瞬移起跳 → 隐身传送至目标点上方 → 现身下落落地 → 快速前冲穿刺攻击（无视普通无敌帧）→ 后跳拉开距离 → 重新进入游走。

## 四、 数据驱动配置规范

### 1. 统一敌人配置源 (`data/enemies.json`)
- 新增敌人需在 `data/enemies.json` 的 `enemies` 列表中登记：
  ```json
  {
    "id": 1,
    "name": "jump_bird",
    "scene": "res://scenes/enemies/enemy_jump_bird.tscn",
    "color": "#e06060"
  }
  ```
- **关卡编辑器数据同步**：网页关卡编辑器内嵌的敌人列表由 `node level_editor/sync-enemies.js` 自动从 `data/enemies.json` 生成。执行 `node level_editor/sync-enemies.js --check` 可在不写盘的情况下校验前后端数据是否一致。

### 2. 运行时生成规则 (`EnemySpawner`)
- 场景生成器 `EnemySpawner` 读取配置后，在地图网格中检索合格的地面格（当前格为空气，正下方为实体墙壁，且上方有足够站立空间）进行随机布点。
