# 历史校验与预测复用

2026-10-26 初版，2026-10-27 更新预测范围。完整 STATE 仍决定玩法结果；当前方案见[本地预测域设计](local_prediction_design.md)。下文验证数字保留各自历史日期。

## 采用的资料方案

| 一手资料 | 采用方式 |
|---|---|
| [Source SDK：ComputeFirstCommandToExecute](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/prediction.cpp#L1329) | 比较已确认命令对应的历史预测字段；无误差时平移确认边界，保留已经计算的未来结果 |
| [GGPO：InputQueue](https://github.com/pond3r/ggpo/blob/master/src/lib/ggpo/input_queue.cpp#L201)、[Sync](https://github.com/pond3r/ggpo/blob/master/src/lib/ggpo/sync.cpp#L118) | 比较实际执行的命令，定位最早失效 tick；从它之前的有效检查点恢复，只重放后缀 |
| [Backroll 开发指南](https://github.com/provencher/Backroll/blob/master/Documentation/DevelopmentGuide.md) | 明确可保存、恢复和重放的数据边界；恢复不能遗漏下一步模拟的依赖 |
| [Rocket League：It IS Rocket Science](https://media.gdcvault.com/gdc2018/presentations/Cone_Jared_It_Is_Rocket.pdf) | 碰撞查询的时间和阶段必须明确；当前只读代理是有界估计，不宣称等同于整体物理预测 |

GGPO 检查的是输入，不是服务端 STATE。这里采用其首个错误输入与后缀重放的方法，仍保留本项目的权威状态比较。不同网络模型没有直接混用。Backroll 的完全数据化模拟是设计目标，当前角色和弹丸仍使用 Godot 节点，本改动没有宣称完成整个场景树的隔离。

## STATE 的处理顺序

1. 等待可靠事件屏障和对应的地形版本，拒绝旧 STATE。
2. 比较同 tick 的本地完整玩法状态、弹丸、本地账户与历史地形。远端快照更新只读代理，不比较其完整武器、账户或输入游标。
3. 从新 ACK 重建本地输入队列，比较实际有效命令，并用新代理复核实际阻挡、起身、弹丸接触和射手回溯依赖；包含原先为空的查询。已知新事件限制可保留的前缀。
4. 全部相同时只更新确认信息。首个后续 tick 就不同时，也可以保留已验证的锚点；后续存在有效前缀时，从更近的检查点恢复。
5. 历史缺失、epoch 改变、状态不同或无法恢复检查点时，恢复权威锚点并重算必要的未来。

比较的是“历史 tick 3436 对权威 tick 3436”。现在 tick 3438 已经预测出爆炸，不能据此判定 tick 3436 的地形不一致。最终位置校正为 0 也不能代替历史状态比较。

## 地形历史

[NativeTerrain](../../native/simulation/terrain.cpp) 以原生稀疏记录保存窗口基线、最新权威 HP 和按 tick 分组的子格改前/改后值。每个角色历史只保存地形历史代号；不会每 tick 复制地图、场景树或物理空间。

收到补丁时保留原预测历史，用于随后校验。当前子格以权威 HP 加上补丁之后的预测伤害更新；只写入实际不同的 HP。相同确认不先恢复地形，再重演同一次爆炸，因此不会为这次确认重复创建碰撞体。补丁覆盖到的历史确实不同时，禁止从这段历史复用检查点，等待对应 STATE 恢复完整世界。期间输入与预测时钟照常推进；不因补丁与 STATE 分批到达而停走、再追赶未来 tick。

检查点恢复按同 tick 的增量历史写回子格，并在下一步碰撞查询前提交脏块。正值 HP 之间的恢复不重建碰撞；子格存亡改变才更新碰撞与待提交表现。确认后平移基线、移除已覆盖历史和不再需要的子格，未确认历史受 64 tick 窗口限制。

## 可靠事件确认

[CombatPrediction](../../core/net/combat_prediction.gd) 保存实际执行过的阶段结果，保留窗口与角色历史一致：

- 爆炸比较 tick、类型、位置；一致只确认，改变时间时同时使旧爆炸 tick 和新 tick 之间的结果失效。
- HIT 按攻击 ID、tick、来源、目标比较实际 HP、击退和朝向；仅源位置不同而受击效果一致时保留模拟。基础速度变化无法从 HIT 完整证明时不跳过重放。同一确认不重复入账。
- 光束先比较实际执行的 tick、角色、武器、路径和宽度；几何不同则用原阶段目标矩形复核接触结果，未改变接触时只更新确认。弹丸引信确认比较历史中的完整运动状态。
- 普通弹丸结束还要核对对应的权威 HIT；单凭结束 tick 相同不能证明预测命中正确。拒绝预测接触时同时覆盖原接触 tick。
- 时间奖励保留服务端 serial；新消息先登记，整批收齐后只重算受影响账户，按原角色阶段、回溯消耗、回复、攻击/规则奖励顺序检查加速倍率和回溯许可。行为相同时只修正账户及历史；行为改变时从首个不同 tick 重放。未来收入自然应用，已被 STATE 覆盖的收入不重复入账。
- 弹丸回溯先检查重复/过期事件、同 tick 弹丸锚点和后续回溯模式；匹配时保留弹丸节点及预测。真实变化从锚点的下一 tick 失效。

这些判断不取消其他依赖的失效。例如爆炸时间和位置相同，但该爆炸的某个 HIT 结果不同，仍须按 HIT 的最早失效 tick 重算。缺少实际执行记录时不会假定确认正确。

STATE 中只有账户不同也先执行同样的轻量检查。比较接口只生成方案，确认复用后才提交账户历史；不为检查提前修改现场。完整操作审计和本轮验证见[事件影响检查](event_impact_validation.md)。下文 31.809 ms 的对局是补齐该检查之前的历史结果，不代表本轮改动的测量。

音效、动画和爆炸特效仍由首次预测/确认去重的表现路径处理。重放重新计算玩法结果，不重复播放一次性效果。

## 2026-10-26 方案的历史验证

[prediction_reuse_probe](../../tests/probe/prediction_reuse_probe.gd) 对照检查点重放与完整恢复后的角色和地形，覆盖未来爆炸不阻止旧状态校验、相同地形版本更新、同 tick 分批补丁、首 tick 失效、真实地形分歧与事件结果确认。

新探针、六项网络回归均通过；最后修改后复核 `prediction_reuse_probe`、`authority_probe`、`playback_lifecycle_probe` 和 `bullet_rewind_order_probe`，四项通过。全量逻辑回归 **62/67**，239 个脚本加载通过。五项失败保留：精英掉落探针打印 OK 后以 `0xC0000005` 退出；路径探针检查临时产物是否已经存在；预瞄探针访问尚未创建的 `_laser`；设置页探针断言旧标签；拾取提示探针等待后，角色距武器 69.1 px，已超过 64 px 判定半径。这些单人/UI 路径本轮未改，没有把失败算作通过。

最终八人 Beta 大乱斗使用 GNS、官方 EasyTier 本机中继、禁用 P2P，正式战斗 **90.014 秒**，含断线重连、自然结算及返回原房间。路由检查通过，八人最终位置收敛误差均为 0。

两次普通校正均为 **13.7715 px**，触发源为 `input`，从 tick 4862 的检查点重放 4863–4865；没有据此推断网络抖动或大幅校正回归。原始最大位移包含 Beta 回溯、死亡/复活等重置，不能作为普通校正距离。每秒性能摘要只纳入整个采样区间均位于正式战斗内的记录；其最大值不是单一函数耗时，也不代表所有帧满足 16.667 ms。GNS RTT 的 722 个毫秒级样本均报告 0；本轮是本机中继，不代表公网条件。

首场八人检查发现一个本轮引入的问题：地形补丁先于 STATE 时暂停预测，会停走后再追赶，额外产生小幅校正。已移除暂停，只限制失效历史复用，并增加“预测时钟持续推进”的断言。首场与最终场证据分别保留在 `match_8_relay` 和 `match_8_relay_fixed`，没有混合统计；也不把两场非固定消息到达序列当作严格性能 A/B。此前的 33.078 ms 峰值仍是原对局结果。

性能对局未启用脚本 profiler、外部 CPU 采样或逐函数插桩。stdout 使用持续排空的管道，结构化日志沿用后台写入。测试副本仅将 RenderWatch 观察器优先级设为 3，使其晚于游戏 1 和副本 2 观察；游戏代码、移动断言及正式调度均保持待测版本。

证据目录：`.test_logs/state_validation_20261026_144049/`。`verify_unit`、`verify_network` 和 `verify_selected` 保存回归结果；两份 `match_8_relay*` 保存逐条对局日志、路由与退出状态；`analysis.json` 汇总最终数据。本轮相对既有工作区的独立补丁与源码备份在工作区 `work/state_validation_20261026/`。
