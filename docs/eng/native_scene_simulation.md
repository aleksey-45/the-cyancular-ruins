# 场景内原生模拟实施方案

2026-10-27。承接[纯数据调研](pure_data_simulation_research.md)，实施边界调整为：保留 Godot 场景和物理节点，由原生类保存高频模拟状态并执行运动，GDScript 负责边界适配和表现。状态与函数迁移一起进行，避免 C++ 通过反射访问旧脚本状态。

## 状态与调用归属

- Godot 管理节点树、物理对象、形状、资源和生命周期。当前位置与实际移动继续使用 Godot 物理节点。
- C++ 原生节点保存角色运动状态、运动输入和查询缓存，直接调用类型明确的物理 API。本地角色和远端运动代理共用同一运动核。
- 原生状态只保留一个写入位置。原脚本 API 需要兼容时，组件属性转发到原生成员，不维护第二份可修改状态。
- 数值仍从现有 PlayerParams、GameParameters、WeaponRegistry、TileDefs 等统一来源加载。原生代码定义协议字段与状态枚举，不另建一套武器、瓦片参数。
- 正常推进和重放共用同一核。会影响后续 tick 的形状、地形与碰撞结果立即提交；显示和一次性音画在外层消费。

## 迁移顺序与完成判据

1. 原生扩展构建、角色运动状态、输入、角色阻挡和地形运动查询；覆盖游泳、攀爬、蹲伏、冲刺、击退、环面和弹性材质。生产调用接入并完成相同输入的状态对照。
2. 弹丸与地形已验证热点迁入正式模块，去掉实验原型中的反射和脚本回调；加入构建与打包流程。
3. 批量推进代理轨迹，继续将武器、攻击结算和历史等依赖逐项收口到原生执行链，统一导出表现状态和有身份的事件。
4. 接纳批次冻结、状态覆盖与影响审核、最早失效点合并，统一执行入口；一个显示帧最多一轮网络触发的本地历史重放。

只有一整轮恢复、重放与推进不再回调脚本执行模拟，才能称高频调用链完全原生化。迁移中的剩余脚本阶段必须明确记录，不以“用了 C++”代替完成情况。

## 验证

变更涉及角色运动和预测核心，属于三级改动。沿用现有 tick 546～550 固定数据对照，在计时外比较每 tick 的角色、弹丸、地形、账户、输入游标和实际形状；再执行相关运动、回滚、时间机制与联机回归。已有与变更无关的失败单独记录。性能样本使用 Release 原生库、持续排空 stdout 的 PIPE，原始计时为 us，展示 ms 时只除以 1000 一次。

## 当前进度

第一批生产接入与代理轨迹批量推进后，第二批继续完成武器、预测战斗与完整检查点捕获，详见[武器、战斗与预测历史的原生迁移](native_combat_simulation.md)。当前归属如下：

| 范围 | 当前实现 |
|---|---|
| 角色运动与输入 | `NativeActorBody` / `NativeActorInput` 保存输入、运动计时器、姿态、HP、氧气、击退等高频状态；普通推进、本地重放和代理共用运动核 |
| 场景与物理 | `Player` 继承原生 `CharacterBody2D` 子类，保留场景子节点、形状、Godot 运动查询与生命周期；没有另建物理引擎或手写节点所有权 |
| 代理轨迹 | `NativeMotionTrack` 用连续原生状态保存有界轨迹，批量生成并应用样本；内部逐 tick 调用同一运动核，保留实际扫掠范围；轨迹选择与失效审核仍在 `PlayerReplica`，详见[后续存储优化](proxy_state_storage_optimization.md) |
| 弹丸 | `NativeBulletBody` 保存运动/引信状态并处理重力、阻尼、Godot 运动查询与反弹；玩家接触查询直接读取原生角色。视觉弹丸仍按最近的环面副本显示 |
| 地形 | `NativeTerrain` 独占网格与 HP，统一单人、权威和预测的伤害计算、历史、查询与碰撞提交；GDScript 消费事件和快照，详见[迁移记录](native_terrain_migration.md) |
| 历史 | `NativePredictionHistory` 批量捕获完整检查点和碰撞箱；保持 Dictionary/Array 格式，低频远端元数据按变化生成并只读共享。历史恢复、审核与重放外层仍在 `PredictionRollback` |
| 武器与战斗 | `NativeWeaponBody` 保存武器状态、推进冷却/换弹/开火，角色与武器在一次原生调用中推进；`NativeCombatKernel` 处理预测弹丸、接触、命中、爆炸与追赶，直接调用原生地形。背包管理和服务端外围仍在脚本 |
| 构建 | Windows 与 macOS 构建入口均加入模拟扩展，打包和产物检查包含对应动态库；本机已编译 Windows Release，未声称完成 macOS 或正式导出验证 |

`native/simulation/` 的运动、弹丸与地形循环不通过 `Object.get/set/call` 回调 GDScript。边界的属性适配、Godot 容器操作和类型明确的引擎 API 调用仍有成本。兼容属性的原生访问器使用私有前缀，避免覆盖 Godot 自带的 `get_gravity()` 等接口；运行状态也不作为编辑器导出属性保存。

旧的脚本游泳、攀爬和氧气更新算法已移除，组件只转发状态；敌方弹丸场景也改用原生弹丸基类。原生水面查询对全列都是水的环形地图增加了遍历上限，避免原先无限寻找水面的循环。

## 每显示帧的权威批次

物理与表现回调共用 `_apply_frame_authority`。首个接纳点处理目前可用的消息，合并最新 STATE 与最早失效 tick，再按既有覆盖和依赖审核决定是否重放。后续模拟消息按接收顺序留到下一显示帧；期间不会提前修改弹丸、地形或伤害记录。没有物理 tick 的显示帧由表现回调接纳。

本地预测产生的地形碰撞仍逐 tick 提交；连接/房间生命周期和新基线仍立即处理，新基线清除旧批次。远端输入提示不触发本地重放。`_apply_pending_authority` 保留为可显式调用的内部入口，固定夹具可直接处理一个人为构造的批次。

运动域探针增加了迟到消息用例：本帧接纳后到达的两份 STATE 和一个影响本地的弹丸事件先保持不变，下一帧只应用一次最新锚点，并仅重放受影响的 1 tick；重新建立基线时丢弃旧队列。

## 第一批固定旧局对照

工作产物位于工作区的 `work/native_scene_simulation_20261027/`，保留本轮开始的源码备份、A/B 源码哈希、原始计时和逐步比较结果。固定输入来自先前八人对局的 frame 623：锚点 546、重放 547～549、随后正常推进 550；包含七发迟到 S686 弹丸、tick 548 的榴弹爆炸和 172 个地形子格变化。

这是强制执行相同 3 tick 重放的成本比较；正式接纳流程仍会审核影响，无依赖的弹丸出生不必重放本地角色。

恢复锚点及四个后续 tick 的五个边界均与旧生产实现严格相等：角色、弹丸、代理状态、HP、宏观网格、碰撞网格、实际碰撞形状与布局、输入游标、账户、历史、命令和依赖查询。代理批量推进加入后也重新通过此对照。

同轮 A/B/B/A，每个进程预热 3 次、测量 30 次，两侧各 60 个样本；使用 Release 扩展和持续排空的 stdout PIPE。第二轮中位数如下（底层原始字段均为 us，这里统一除以 1000）：

| 项目 | 旧脚本实现 ms | 当前原生接入 ms |
|---|---:|---:|
| 完整 3 tick 重放 | 8.832 | 6.041 |
| 随后一次正常推进 | 1.417 | 1.164 |
| 重放内本地角色阶段累计 | 0.517 | 0.386 |
| 重放内弹丸阶段累计 | 4.182 | 2.548 |
| 重放内历史保存累计 | 0.363 | 0.487 |

完整重放的中位耗时下降约 31.6%，p95 为 10.998 → 7.471 ms。第一轮接入的同轮对照为 8.855 → 5.619 ms；不同轮次存在波动，不用两个轮次的差异推断代理批量调用的单独收益。采样后的属性访问器命名调整不改变运动或重放算法。

历史保存没有改善，说明把小型 Godot 容器的构造逐项搬到 GDExtension，并不等于减少跨接口和容器成本。后续需要批量状态布局与整体执行链，不能据此宣称整套回滚已经原生化。

## 回归与实战边界

全脚本加载 244/244。逻辑/场景回归 67/70，三项原有失败分别为 `elite_drop_probe` 成功后退出崩溃、`preview_visibility_probe` 空预瞄节点、`settings_display_section_probe` 旧文案断言。本次发现并修复了敌方弹丸场景基类遗漏；回归中途更新扩展接口造成的旧 DLL 加载结果作废，编译后已补跑受影响项。最终访问器和轨迹改动通过角色接口、运动域和固定边界复核。命名、改动空白与 Python 构建脚本解析检查通过。

首场成功对局 `match_8_relay_local` 为 90.032 秒八人 Beta 大乱斗、本机 EasyTier UDP 中继、禁用 P2P。八人正常结算并回到原房间，最终位置误差均为 0。沙箱内的首次连接因本机回环 TCP 被 `10013` 拒绝而没有开局，不计为成功实战。

首场的 43,034 个客户端战斗区间中，≥30 ms 为 3,479 个、≥50 ms 为 2 个，最大 56.438 ms，不能说卡顿已解决。这些是相邻 `process_frame` 信号的墙钟间隔，包含帧率等待和 OS 调度；各层 span 有嵌套，不能直接相加。

- `client6` frame 4182：9 tick 重放、一次权威应用。物理节点区间 39.554 ms，代理轨迹采样 11.838 ms、弹丸阶段 10.019 ms、本地角色 1.413 ms、历史保存 2.824 ms；回调覆盖外还有 14.995 ms。
- `client4` frame 4611：8 tick 重放、一次权威应用和两次正常推进。物理节点区间 46.191 ms，代理采样 10.023 ms、弹丸阶段 13.607 ms、角色 1.456 ms、历史保存 3.307 ms。

因此补入了上述代理轨迹原生批处理。首场数据也说明剩余开销仍在代理采样、弹丸/攻击和历史链，不能将其全部归于调度或角色运动。单一场次和固定成本夹具不能替代同消息时序下的整局性能 A/B；测量的观察器耗时也只是记录成本的一个子集。

第一批之后的武器、预测伤害和完整历史捕获已继续迁移；下文保留第一批验证记录。整轮恢复/重放/推进的原生批次入口尚未完成，GDScript 仍承担部分模拟边界。

## 第一批最终复核

代理批量推进与兼容访问器命名完成后，`match_8_relay_final` 再运行 90.026 秒八人 Beta 大乱斗，禁用 P2P、本机 EasyTier 中继。runner 无失败，八人正常结算、回到原房间，最终位置误差均为 0；路由检查全部为 `relay(2)`。测试结束后 Godot 与 EasyTier 子进程均已退出。

42,986 个客户端战斗区间中，≥30 ms 为 3,441 个、≥50 ms 为 5 个，最大 **64.359 ms**。最大区间是 `client4` frame 4664：一次权威应用、10 tick 重放和三次正常推进，累计生成 91 个代理运动样本。物理节点区间 58.811 ms，其中代理采样 13.909 ms、弹丸阶段 9.757 ms、角色 1.371 ms、历史保存 3.499 ms；回调覆盖外为 3.613 ms。权威接纳准备也有额外开销，不能只看内部 `authority_apply` 的 28.509 ms。以上子阶段包含于外层区间，禁止重复相加。

这轮证明原生接入能够完成真实对局，并未证明实战卡顿已经消失。两场的输入到达顺序、交互和重放量不同，不能用最大间隔变化评判代理批量接口的独立收益。上述为第一批结果；第二批迁移的状态、同轮性能对照与实战边界见[后续报告](native_combat_simulation.md)。
