## 1. 分片与加载顺序

- 19 片按**文件名字典序**加载，`NN_` 前缀就是顺序。**顺序的真相源是 `level_editor/editor.html` 的 `<script src>` 列表**；
  `parts_check.js` 守「目录 ↔ 页面」一致，`loader.js` 在 node 侧按同一份清单拼进**一个** Function 体。
- 分片共享**同一个作用域**，所以「一次求值、跨片可见」的代价是**顶层名不许重名**，而 `var` 的重名会 hoist 成整段局部名。
  ⇒ `00_head.js` 里 `globalThis.Core` 被就地取名 **`RenderCore`**（不是 `Core`）：`level_editor/ui/00_head.js` 有一个顶层 `var Core`，
  node 侧拼接后它会把裸 `Core` 遮成 `undefined`，而各片的**加载期**（如 `var SUB = Core.SUB_PER_CELL`）正是裸读。
  `parts_check.js --ratio` 同一次运行的「全局影子」闸就是防它长回来。
- ★ **本层顶层一行都不碰 DOM**：DOM 只出现在 `mount()` 一族里。于是 node 能加载它，把「错了也不报错、只在屏幕上看出来」的那几层
  （③ 的失效、空层、空气短路、环面命中、画笔几何、单帧预算）逐条断言 —— 见 `level_editor/render_smoke.js`。
- 末片恒为 `99_exports.js`：公开 API 表只在它里面。

## 2. 四层缓存（规格 §4.2）

| | 是什么 | 谁持有 | 失效事件 |
|---|---|---|---|
| ① | 地图**缩略图**（每层一张，2px/子格，或降为 1px） | `mount` 闭包（`S.thumbs`） | 换图、改尺寸、整片 invalidation |
| ② | **视口离屏层**（每层一张，像素系 = 屏幕系） | `mount` 闭包（`S.layerCv`） | 换图、视图变动、尺寸变动 |
| ③ | **格位图缓存**（一格的 16 个 tile 引用） | 模块层（`30_cell_cache.js`），由 `attachCells` 交上来 | 内容版本号（`touch`）+ 代际（`setSource`） |
| ④ | **tinted-tile**（真正的像素） | `tint.js`（自带 8192 张上限） | `Tint.setSource` |

- ★★ **换图（`setAtlas`）必须让四层一起作废**。③ 靠 `attachCells` 那条接缝交上来、④ 由 `Tint.setSource` 自己清；
  ①② 的 state 住在 `mount` 闭包里，模块层看不见 ⇒ 挂载侧用 `attachViewInvalidator` **只登记、不回调**一个作废器
  （`20_atlas.js` 收成一张表而不是单槽位：第二个 `mount` 不该把前一个的作废悄悄吞掉），`setAtlas` 提交完 ③④ 之后再调它。
- ★ 作废器**只做同步的丢弃/记账，不做重画**：①② 的重画是几十万次 `drawImage`，必须经 `createSlicer` 分帧（闸 2），
  那是挂载侧在下一次 `render()` 里安排的事。
- ★ 漏了这条接缝的症状**两条路各一个、且都不报错**：
  - ① 那条路（默认 fit 视图走的就是它，大图必然 < 8 px/子格）继续画**旧图集**的砖，直到某次 `invalidateAll` / `setMap`；
  - ② 那条路更糟：它的 `layersClean` 不被碰，于是 ≥8 下平移时 `panBy` 判「这一层是干净的」⇒ 自拷贝旧像素、
    只把新露出的边条按**新**图集补上 ⇒ 屏幕上是**新旧混着**，连「慢慢重画」那种退化都没有。
- ★ `setAtlas` 的顺序是「**先把新 ④ 建出来、让它校验形状，校验过了才提交**」：形状非法时 `Tint.setSource` 抛错，
  此时 `tiles` / `atlasPixels` / ③ 的代际**一个字都没动**。注入 `opts.backend` 那条路尤其要这样写 ——
  先 `tiles = 新缓存` 再 `setSource` 会留下一个**没有贴图源的新 ④**，而 `atlasInfo()` 仍报旧图集、③ 也没作废。
- ★ ③ 的条目 = **16 个 tile 引用**（约 128 字节），不是 64×64 的 canvas；8192 条 ≈ 1MB。
  若把「合成好的 64×64 canvas」存进来，一屏 925 格就是 15MB —— 缓存比工作集还小 = 没缓存。像素只存在 ④ 里。

### 2.1 ③ 的两条独立失效轴

- ① **内容版本号**（`touch`）：编辑某格 → 该格版本 +1 → 下次只重建这一格；
- ② **代际**（`gen`，`setSource` 递增）：换贴图源之后，即便内容一个字没改，旧的 tile 也已作废。

只判 ① 会交出**上一张图集**算出来的 tile，症状与审计 A2 一模一样（整张图是色块，「有时好有时坏」，不报错）。
`setSource` **刻意不清表**：陈旧条目靠 `gen` 不等**恒 miss**、被重建覆盖。清了表的话 `get` 里那句 `e.gen === gen`
就成了死代码（表里不可能有旧代际条目），删掉 gen 比较再也杀不掉任何东西 —— 而它正是这条轴唯一抓得住的地方。
重建路径同样要先 `delete` 再 `set`：`Map.set` 对**已存在**的键保留原插入位置，刚重建的条目可能还蹲在最冷端、下一次淘汰就被扔。

### 2.2 图集容量

- 图纸容量 = 列 × 行（320×320 的图集 = 100 块），**不是**描述符位宽 4095 —— `tint` 的越界判据就是「图集里有没有这一块」。
- ★ `atlasCapacity` 里的 `Math.max(0, …)` 不是装饰：`w` 由 `Tint.setSource` 校验，**`h` 从来没被任何人校验过**
  （`setAtlas` 原样 `h | 0` 存下），畸形的 `h`（如负数）会让 `Math.floor(h / BLOCK_PX)` 为负 ⇒ 容量算出**负数**；
  而游戏侧计划里的 `clampTexture` 把任何 **< 1** 的容量都当「没有信息」、**静默**放宽到 `TEXTURE_MAX` ——
  负数于是伪装成「没信息」穿过那道闸。钳到 0 = 明确的「一块都放不下」。

## 3. 环面

- `wrapIdx(v, n)` 用 `v - Math.floor(v / n) * n`，因为 **`%` 对负数返回负数**，而负数在这里是常态
  （视图越过接缝、选区拖动、3×3 副本的 `cx = -1`）。
- `quadOf(v) = wrapIdx(v, SUB)` 恒在 `0..SUB-1`，否则 `Tint` 会抛。
- **缺席层 = 全空气**：`layer_flags` 允许某个层不存在 ⇒ 解码出来的 `layers[L]` 可以是 `null`（`null` 不是错误）。
  渲染路径上任何地方直接摸 `layers[L].desc` 都会在「打开一个缺层的文件」时当场炸 ⇒ 一律经 `layerArray`。
- **3×3 副本**：只返回「与视口相交」的副本偏移（最多 9 份，通常 1 份）。
  ★★ 但别把「多份副本」读成承重：离屏层的像素系 **= 屏幕系**，它上面已经按**可见范围本身**把每一处应有的内容都铺好了 ——
  越出主网格的那些像素由 `paintLayerRect` 的**环面折算**补上。所以 `±subCols/±subRows` 那几份副本画的是**同一批像素**，
  在当前坐标系下是**冗余**的；「屏幕每一处都有一份盖上去」这个保证来自 `paintLayerRect` 的折算，**不是**来自这里。
  留着它们的两个理由：① 环面 N×N 铺贴是计划明列的交付面；② `setTorus` 开关的可见行为就是它（⑩d 钉住的 `[8,4]`）。
  真要省这几笔全画布 `drawImage`／层／帧，把 `offs` 收成 `[[0,0]]` 即可（⑩d 的期望值要同改）—— 那是省冗余，不是拆保证。
- **屏幕 → 子格**（`hitTest`）折算回主网格：副本上落笔靠的就是这一步，无论点在哪个副本上，结果都落在 `[0, subCols)` 里。
- 常数量级（用来判断「3×3 副本到底进不进屏幕」）：视口 **12.5 格宽**、地图 **500 格** 是常态 ⇒ 隔壁副本被平移
  **−8000px**、整个落在画布外。反过来说，**可见范围内落在主网格之外的像素必须用折算后的格去填**，
  绝不许按主网格裁剪 —— 裁了就是视图拖过边界时的一整条空白，而副本**填不上**它。

## 4. 脏区与平移

- 编辑 → 标脏（`editCells` → ③ 的 `touch` + ② 的脏矩形 + ① 的缩略图块）；切层/开关 → **只合成**；
  平移 → **像素级自拷贝搬移 + 只补新露出的边条**。
- 跨层的脏矩形合成用**一个包围盒**就够：合成时按层拆是在 ② 的离屏层上做的，而「这一帧要不要重画」只需要一个上界
  （包围盒偏大只会多画一点，不会画错）。它**没有容量上限**是因为**有界**：只装调用方交上来的那几个格/矩形，用完即 `clear`。
- ★ `panStrips` 的参数是**视图/世界**的位移方向（`view.x` 增加 `dxPx/zoom`）：画面内容是**反向**走的，
  所以「向右看 10px」新露出来的是**右边**那 10px；调用方那里的自拷贝偏移是它的**相反数**。
- ★★ 位移**先量化到整像素**：自拷贝是 `drawImage`，而插值关掉之后光栅器会把偏移吸附到整像素，`s.view` 却按**精确值**前进
  ⇒ 每次平移最多差 0.5px，而且**会累积** —— 边条只补「新露出来的那一条」，永远不去纠正已经攒下的偏差 ⇒
  内容是「慢慢从网格/覆盖层上漂走」（改窗口大小或拖久了才看得出来，不报错）。
  只量化自拷贝的偏移不够：`view` / `panStrips` / 自拷贝三者必须**同源**，所以一次量化、后面三处全用这个值。
  代价照实说：不足 1px 的平移被**丢弃**（0.4px 走十次 = 一步都不动）—— 刻意的，「不动」比「越拖越歪」好，且与闸 1 口径一致。
- ★★ 视图一动（平移/缩放/换图/改尺寸）⇒ 在飞的那一轮重建**整个作废**（`layerGen`）：分帧重建的条带矩形是按**旧视图**
  算的，而 `paintLayerRect` 又按**当前视图**换算像素 ⇒ 剩下的条带画到了别处；更糟的是它会与「自拷贝搬移」混在一起
  （搬移的前提是整张图属于**同一次**视图的产物），而脏标记此刻已经清干净了 —— 谁都不会再补那几块。
  ⇒ 纪律：**视图不干净时平移一律改走整片重建**。
- ★ 尺寸一变，② 的旧画布必须**丢掉**（不是「只标脏」）：它的像素是按旧画布尺寸铺的，留着会被按新目标框画出去（整层错位），
  而「只标脏」只补一小块、其余留白。丢掉之后由 `buildLayers` 分帧重来。
  `drawLayerPath` 里另有一道兜底：**尺寸对不上的离屏层一路都不许画**（改窗口之后、重建还没跑到时）。

## 5. 闸 2：单帧预算（`40_slicer.js`）

- `DEFAULT_BUDGET_MS = 8`。分帧是「慢慢画出来」，不是「页面死掉」；注入 `now` / `nextFrame` 是为了在 node 里
  **确定性地**断言「确实切了、且单帧真的没超预算」（真 `requestAnimationFrame` 在 node 里不存在）。
- ★ 「**每帧至少做一项**」是必须的：否则 `budgetMs = 0` 时循环会一项不做就让出、让出之后又一项不做 —— **死循环**
  （而 `0` 是合法的注入值，测试就在用它）。
- ★ 预算必须是**有限的数**：`now() - s0 >= NaN` 恒为 `false`，负预算同理永远不成立 —— 两者都会让 `while` 一口气做完整批，
  而那正是闸 2 要防的事，并且**不报错**（症状是「分帧器装了等于没装」，只能靠量单帧耗时才发现）。
  非法值一律：非有限数 → 回落默认；负数 → 钳到 0。
- ★ 判在**做完之后**：预算是软的（到手一项就做完它），但一格都不许超。
- ★ 时间基准在**让出之后**重新取：让出一帧自己也花时间，把那段算进下一帧的预算里会让「下一帧刚做一项就又超预算」
  —— 分帧退化成逐项让出。
- ★★ 抛错必须**落到 `run()` 返回的那个 promise 上**。第 2 帧起 `step` 是在 `nextFrame().then(step)` 这条**没人观察**的链上跑的：
  裸抛会变成 unhandled rejection，`run()` 于是**永远不 settle**（调用方 `await` 到天荒地老），而第一帧抛却能正常 reject
  （那时 `step` 还在 promise 执行器里同步跑，执行器自己会接住）。两条路径症状不同，所以只测「第一帧抛」是**区分不了**的。
- ★★ 第二个实参（`nextFrame().then(step, reject)`）同样是承重的：它堵的是「**让出的那一帧**抛」
  （注入的 `nextFrame()` 交回 rejected promise，例如帧回调里出了错 / 分帧被中止）。只写 `.then(step)` 的话，
  这个 rejection 落在**没人观察**的派生链上 —— `step` 一次都不会被调到，症状与上一条一模一样。

## 6. 图层种类：描述符 vs RGBA（`70_layer_kind.js`）

- 绘制顺序 `DRAW_ORDER = [3, 2, 1, 0]`：前景（0）是「从外到内」的第一层 ⇒ **最后**画（盖在最上面），背景（3）最先画。
- ★★ 纹理层是**描述符**（走 `Core.texOf` / `Tint`），背景层是 **RGBA `0xRRGGBBAA`**（走 `cssOfRGBA` / `fillRect`）。
  两者都是 32 位无符号数，长得一模一样、含义完全不同 —— 把 RGBA 喂给 `Core.texOf` **不抛**，只是结论毫无意义，
  而两种颜色各有一种**静默**症状：
  - 不透明红 `#FF0000FF`（背景色输入框里随手就有）：`(0xFF0000FF >>> 12) & 0xFFF = 0` ⇒ 被当成**空气** ⇒ 整层看不见；
  - 不透明青 `#00FFFFFF`（输入框的默认值）：`texOf = 4095` = 「图集里没有的那块砖」⇒ 任何一处漏掉「先判层、再判纹理」
    的地方都当场抛 `Tint` 的越界错（闸门越少越容易漏）。
- 判据取 `core` 的单一来源 `LAYER_KINDS`，**别**在渲染层再抄一份 `[0,0,0,1]` —— 那就是第二份实现，两份迟早漂、且漂了不报错。

## 7. 挂载与闭包分解

- `mount(canvas, opts)` = `createMountState` 建共享状态 `S`，再按序装上六簇：
  `installErrors` / `installThumbs` / `installLayerPath` / `installDraw` / `installDrag` / `installEdit`。
- ★★ `S` 是安装器之间**唯一**的共享通道：会被**重新赋值**的标量（`thumbPx` / `atlasSync` / `errorSink` / `cellCache` /
  `layersClean`）一律挂在这里，跨簇读写只能走 `S.xxx`。**不许**把它们当安装器的参数传 —— 函数在安装那一刻就捕获了一份旧值，
  之后别的簇重赋值它，读到的还是旧的。安装期各簇**只登记**自己的函数，不许互调。
  只改属性/元素的对象与数组（`ctx` / `s` / `thumbs` / `layerCv` / `stat` / `stat2`）引用本身不会换，故各安装器开头就地取别名即可。
- ★★ **晚绑定**是这条纪律的必然产物：`torusList` 由 `installDraw` 产出，`installLayerPath` 的 `drawLayerPath` 经
  `S.torusList` 取用它（首轮漏了它，`render_smoke` 当场红）。
- `stat2` 里两个名字相近、**量的不是一件事**（评审发现 9），人眼清单两个都要读：
  `layerRebuilds` = `flushDirty` 的**脏区重画次数**（编辑一格 = 该层 +1，单位是「块」）；
  `layerRebuildMs` = **一次整片 `buildLayers` 的耗时**（单位是毫秒）。计划把这两个键名钉死了，故只标注、不改名。
- ★ ② 的像素坐标系定义（整个 ② 靠它）：离屏层像素 `(px,py)` ↔ 世界子格 `(view.x + px/zoom, view.y + py/zoom)`
  —— 与屏幕**同一套**坐标。于是「平移 = 像素级自拷贝 + 只补边条」「3×3 副本 = 把**同一张**图按副本世界偏移 × zoom 再画一次」。
  绝不建全图离屏：**500×300 子格按 16px 是 8000×4800 = 153MB**，浏览器会直接拒绝。

## 8. 选区拖动：偏移查询与「去烤」（`90_install_drag.js`）

- 拖动**只记偏移**（`s.selDrag = {sel, dx, dy}`），渲染时对选区内的格做**偏移查询**（纯读），松手才提交一次 `moveRegion`。
  老实现每次 `pointermove` 都深拷贝三份全图。
- ★★ 三种目标格，必须与「松手后 `moveRegion` 真正写出来的结果」**逐格一致**（预览必须等于落笔）：
  ① 源格在选区内 ⇒ 读源格；② 源格在外、目标在选区内 ⇒ 那是**被腾空的源区** ⇒ `hit:false`（不画）；
  ③ 两边都在选区外 ⇒ 原样读它自己（没被动过的底）。
  ★ 少了 ③ 的后果不是「少画一点」：drag 的偏移一动，除选区外的**整整一张图**都判成腾空 ⇒ 拖动时地图整体消失、只剩一个框在飘。
- ★★ 一律传 `W`/`H`（环面折算）：拖动跨过接缝时目标格落到图的另一头（24 → 0），非折算的查询会在那里读到
  「目标格**自己**的内容」，而落笔（`moveRegion` 走 `idxOf`）搬过去的是**源格的内容** ⇒ 预览与落笔在接缝那一侧分岔。
  旧的非折算 5 实参调用点都在主网格内（折算与非折算在那里是恒等），故口径保留 —— `inSel` 只有一处判据，不是第二份实现。
- ★★ `W`/`H` 可选：不给 = 不折算，拖动查询**必须**给。
- ★★ **选区没了，偏移就不再生效** —— 判据里必须有 `s.selection`（不是只有 `s.selDrag`）。Esc 取消选区时「左键还按着」
  是合法状态，而框没了就**没有可搬的东西**：此时若还照 `s.selDrag` 读偏移，画面上的内容会留在「被搬过去」的位置上
  —— 用户看到的是「框没了、内容却在别处」，而且它会一直留到下一次 `pointermove`/`pointerup` 才被擦掉。
  `markDragDirty` 里那句 `s.selDrag && s.selection` 是**同一个判据**：一处说偏移生效、另一处说不生效，去烤就会记错账。
- ★★ **去烤**：② 的离屏层是**烤**进去的。拖动中滚轮缩放（`setZoomAt` → `viewChanged()` + `buildLayers()`）或任何整片重建，
  都会把 `dragSource` 的偏移结果**画死在 ② 上**，而 `buildLayers` 结尾还把 `layersClean` 抬成 `true`。
  此后用户拖到**第二个**偏移、松手 —— 提交只按最终偏移结算（`moveRegion` 的 源 ∪ 目标）⇒ 在更早的偏移上被烤过、
  而最终偏移没碰到的那些格**永远留着别人的内容**。框会回到正确位置 ⇒ 用户看到的是「地图上凭空多了一块错的内容」，没有任何报错。
  修法：偏移一变（**以及清除时**）把「源区 ∪ 目标区」重画一遍，于是烤痕的寿命不长于这一次拖动。
  ★ 重画的是**规范化**后的两块（`canonRects`，与 `dragSource` 同一套折算）：跨接缝拖动时目标落在图的另一头，
  照未折算的坐标重画会漏掉那一头。★ 上一次那两块也要一起重画：清除时 `s.selDrag` 已经没了，只有 `dragBake` 记得它烤在哪。
- ★★ **只在活动层**：落笔 `moveRegion` 只搬 `app.r.layer()` 那一层，其余三层的像素在提交时**一个都不动**。
  四层一起偏移的话，那三层的内容会在拖动时跟着光标走、松手又弹回去（预览 ≠ 落笔，而且**看得见** —— BG 层从不被压暗，
  它跟着动最显眼），代价还翻四倍。相应地，「记它烤在哪」必须连**层号**一起记：用户可以在拖动途中切层（数字键 1-4），
  那时旧层上那批偏移像素必须擦掉、新层上则要烤出偏移。
- ★★ ① 缩略图那条路同样要去烤，**判据与 ② 同源**（同一批规范块）：`paintThumbRect` 也读 `dragSource`，
  而**撤销/重做一条 `kind='whole'` 的差量**会走 `invalidateAll` → `buildThumbs`（`Ctrl+Z` 在按住左键时照样按得下去）。
  不重画的话偏移会被烤进 ①，而 < 8px/子格 那条路合成的正是 ① ⇒ 症状与 ② 那个一字不差，只是换了一条路。
  成本 = 块面积 × 缩略图刻度（每子格 1~2px），比 ② 那侧小得多。
- ★★ 逐块重画，**不取包围盒**：跨接缝时源与目标分居图的两头，包围盒是**整行**（目标横跨两半时甚至是整幅图）——
  高倍 + 大选区下那是全屏 `clearRect` 加每层数千次 `drawImage`，**每次 `pointermove`** 都付，远超 ~8ms 的单帧预算，
  而且**没有**走 `createSlicer`（去烤是同步路径）。`canonRects` 本来就把正确的两块算出来了。
- ★★ `dedupRects`：源块在「当前」与「上一次」两组里**各有一份**（选区没变时必然如此）⇒ 不去重就会把它连画两遍
  —— 而它偏偏是**最大**的那一块。`now` 自己也要过一遍：`dx=dy=0` 时源与目标是**同一个矩形**。
- ★★ **按当前路径分派**（评审发现 I1，闸 2 的成本形状）：① 缩略图与 ② 视口离屏层是**两份**数据，同一时刻只有一份在屏幕上，
  而两条路的成本形状**恰好相反**：
  - ② 的成本 = 「与画布相交的格」数 × 每格 16 次 `drawImage` —— **低倍时最大**（整幅图都可能落在画布内），
    而低倍走的正是 ① 那条路 ⇒ 那份活一个字都看不见。**1600×1200 画布、z≈3、大选区 ⇒ 约 1.2 万格 × 16 次 `drawImage`**，
    每次 `pointermove` 几十到几百毫秒。
  - ① 的成本 = **选区面积** × 缩略图刻度（与缩放无关），高倍时同样看不见。旧实现是「源 ∪ 目标（∪ 上一次那两块）」与画布的交集 × 每格 16 次。
  - `render_smoke` 相位 ⑬i 实测（拖动一步）：≥8 那条路上 ① 侧 **0 个 op**、② 侧 **1154 个 op**（≤ 可见格数 475 × 16 = 7600）；
    <8 那条路上 ② 侧 **0 个 op**、① 侧 **7680 个 op**（≤ 选区 3840 子格 × 2 = 7680）。
  - 另一条路的像素**不会被留在半旧状态**：换回 ≥8 一定经过 `setZoomAt`/`setView`/`fit`/`resize`，它们都走 `viewChanged()`
    ⇒ `layersClean=false` ⇒ `buildLayers()` 整片重建 ②（按**当前**偏移）。① 侧见 `dragBakedThumb`。

## 9. 缩略图（①）与它的两条复用坑

- 默认图的一整轮缩略图 ≈ **15 万次**逐子格 `drawImage`/`fillRect`，所以 ① **总是**经分帧器建（闸 2）。
- ★★ **复用条件必须逐轴判**（宽 **与** 高）：`thumbScale` 只看**总字节数**，所以「同宽更高」的两张图可以拿到同一个刻度
  （**500×300 子格 → 1000×600** 与 **500×400 子格 → 1000×800**，刻度都是 2）。这时宽度那条对得上 ⇒ 复用了那张**矮**画布，
  而 `drawThumbPath` 用五实参 `drawImage` 把它整张缩进 `subRows*px*scale` 的目标框里 ⇒ 画面纵向被拉伸/截断。
  默认视图 `fitZoom` 之后 `zoom < 8`，走的正是缩略图这条路，所以**默认视图就是错的**。
- ★★ 复用尺寸相同的旧缩略图之前，先把**新图里缺席的层**清掉：缺席层不进 `thumbTasks`（省一次全图扫描）⇒ 它**不会**被重画，
  留着旧像素的话，换到一张少层的图之后那一层会继续显示**上一张图的内容**。只判「尺寸变了没」是抓不住的。
- ★ `THUMB_MAX_BYTES = 24MB`：超过就降到 1px/子格（**400×300 格 @2px = 30MB**，偏大）。
- ★ 隐藏层**也照画**：离屏内容与可见性无关（与 ② 同一条纪律）。反过来（「隐藏就不画」）会让「隐藏 → 编辑 → 显示」看到一片旧内容。
- ★ 子格线只在 **zoom ≥ 4** 时画。阈值 4 是渲染层**自己的选择**（4px 时一个子格还有 4 个屏幕像素、线还分得开；
  再稀就只是给画面加噪点），规格 C15 只要求「有子格开关 + 子格级命中」，**没有**规定这个数。

## 10. 报错通道（`82_install_errors.js`）

- ★★ 视图入口（`resize` / `fit` / `setView` / `setZoomAt` / `panBy` / `setMap` / `invalidateAll`）返回的是**由分帧器派生出来的
  promise**（全屏重建是分帧的）。而 ≥8 那条路上的抛错（`tileFor` 的「图集里没有纹理 N」—— 改图集/换图之后就够得着）
  发生在**任务回调**里，于是它变成 `run()` 的**拒绝**，不再是 `render()` 里那次同步抛出：
  - 页面侧唯一的消费者（`ui.js` 的 `guard`）是**同步** `try/catch` ⇒ 接不住；
  - `render()` 这一次根本没执行 ⇒ 画布**默默停在上一帧**，只在控制台留一行错。
  这正是本仓最防的那类「按了没反应」。⇒ 在**返回之前**给链子挂一个观察者。
- ★ 两条契约同时成立，缺一不可：① 想 `await` / 想自己 `catch` 的调用方**照样拿到那次拒绝**（这里只挂观察者，
  不改、不吞、也不替换返回的那个 promise）；② 完全不管返回值的调用方，也能在**屏幕上的同一条通道**里看到原因（状态栏）。
- ★ 副作用（正是要的）：它把这条拒绝从全局 `unhandledrejection` 那张网里摘了出来（窗口有了拒绝处理函数，
  引擎就不再报「未处理」）⇒ 用户收到的是一条**指名道姓**的消息，而不是「未处理的 promise 拒绝」。
  两条都出现才是坏味道（`catch` 写在 `then` 链末端）。
- ★ `defaultErrorSink` 走**页面已经在用的那条通道**（`ui.js` 的 `status()` = `#status-msg`），且是**运行时查找**：
  依赖顺序是 core → tint → render → io → ui，加载期 `ui.js` 还不存在（顶层引 = node 冒烟当场炸）。
- ★ 报错通道自己坏了也不许把异常扔回调用方（那就成了第二处「看得见才怪」）。
