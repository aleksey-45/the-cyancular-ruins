# 角色运动与输入预测验证

日期：2026-10-24。本文记录输入提示重放阶段的实测目录 `.test_logs/network/gns_late_input_replay_relay_8/`；当前受击与死亡实现的实测见[完整受击预测验证](combat_outcome_validation.md)。

## 当前实现

- `Player` 定义站立、蹲伏两个矩形，保持相同宽度与脚底。动画姿态独立；起身需要地形和角色净空。
- `ActorStep` 合并普通速度和击退速度，按 X/Y 轴结算一次移动、接地与速度裁剪，随后衰减击退。地形由 Godot 查询，角色由逻辑矩形阻挡。
- 服务端、本地预测和远端运动体按相同角色顺序使用共享步进。还原状态包含接地、计时器、攀爬、蹲伏和击退。
- `RoomSession` 在 INPUT 流按 tick 合批转发已经收到的输入变化。远端使用服务端接收 tick、目标 tick、移动 ACK、动作 ACK 和输入年龄重建 `InputBuffer`。
- 已预测区间收到新的未确认提示时，在下一物理更新开始从完整 STATE 还原全部角色与时间账户，再逐 tick 重放。同批新 STATE 和提示共用一次重放，地图版本需要一致。
- 持续输入与单次动作最早在 `max(target_tick, receipt_tick + 1)` 可用。重复记录保留最早接收时刻，过期根据原始目标 tick 判断。

设计依据与源码链接见[架构参考](architecture_references.md)。[DDNet 客户端](https://github.com/ddnet/ddnet/blob/master/src/game/client/gameclient.cpp#L2413)按 intended tick 保存预输入，复制权威世界后逐 tick 应用输入并模拟；[Unity 预测交互文档](https://docs.unity.cn/Packages/com.unity.netcode@1.3/manual/prediction-details.html)说明相互碰撞的预测实体需要一致的回滚时间线。正常移动速度维持 700 px/s。

## 输入时序的因果验证

上一场 `gns_motor_rebuild_relay_8` 的三个接触片段已有输入提示，但提示涉及的 tick 已预测；旧路径需要等下一份 STATE 才重算。本轮使用保存的输入、动作、角色状态和提示，构造旧权威帧、旧帧加提示、新权威帧，以及先预测后通过正式 `PvpMatchClient` 接收提示四个分支。最后一个分支没有提供新 STATE。

| 角色 / tick | 原日志校正 | 晚到提示重放终点与新权威帧预测终点之差 |
|---|---:|---:|
| 2 / 2588 | 49.062 px | <0.001 px |
| 7 / 2468 | 33.943 px | <0.001 px |
| 3 / 2768 | 57.526 px | <0.001 px |

前两条无提示分支的端点也与原日志吻合。第三条原现场已部分应用提示，无提示分支比原位置低约 9.675 px。离线使用原始 arena 地图与默认时间账户，缺少现场毁后地形和完整账户历史；它验证输入时序及正式重放入口，不是完整逐帧复刻。

对应行为断言修改前失败（`.test_logs/late_input_before.log`），修改后通过；另覆盖重复提示、未来输入、地图版本等待、STATE 与提示合批重放、迟到跳跃动作的接收时间。

## 剩余校正

11 条 ≥32 px 记录全部保留完整上下文，见 `input_replay_analysis.json` 与 `combat_analysis.json`：

| 角色 / tick | 误差 | 日志事实 |
|---|---:|---|
| 2 / 1718 | 103.954 px | 爆炸冲量在正确 tick 提前预测，Y 分量随后被预测接触裁掉 |
| 4 / 1718 | 36.240 px | 同一爆炸；冲量已预测，接触后的位移不同 |
| 6 / 1718 | 41.238 px | 同一爆炸；冲量已预测，接触后的位移不同 |
| 8 / 2118 | 59.981 px | 爆炸冲量与权威一致，后续预测中 X 分量被裁掉 |
| 4 / 2919 | 43.194 px | 爆炸已预测；预测窗口还包含 tick 2922 的普通命中，确认在校正后 29 ms 到达 |
| 4 / 2920 | 41.508 px | 同一普通命中涉及的未来路径差异；命中确认在本次校正后 13 ms 到达 |
| 2 / 3424，INPUT 触发 | 100.285 px | 输入重放改变了 tick 3425 的预测接触，命中确认在校正后 9 ms 到达 |
| 3 / 588 | 35.388 px | 致死命中，冲量已预测；权威倒地状态改变运动和碰撞 |
| 6 / 1868 | 150.384 px | tick 1864 致死命中，冲量已预测；死亡确认有明显到达延迟 |
| 6 / 2909 | 63.955 px | 致死命中，没有提前命中预测记录 |
| 2 / 3426 | 109.622 px | 收到 tick 3425 的致死命中与倒地权威状态 |

150 px 样本附近，原生 STATE 接收间隔 **107.639 ms**，主线程轮询间隔 **16.669 ms**，本条收包后的队列等待 **11.115 ms**。致死 HIT 的服务端记录至客户端收到相隔 **119 ms**；附近 RTT 采样为 58 ms。到达延迟参与了该次分歧，死亡碰撞变化也仍然存在。

爆炸样本表明，提前预测到正确冲量并不足以保证接触后的轨迹一致。地形破坏、其他角色运动及死亡状态共同影响碰撞；日志没有保存每个预测 tick 的完整毁后地形，不能将这些样本唯一归因为地形，也不能宣称剩余校正都来自网络波动。

本场没有独立于战斗命中的 ≥32 px 接触样本，但保留上述剩余分歧。该场没有独立网络卡顿计量窗口；无头客户端结果不代表八个可见窗口的 GPU 性能。不同战局之间的计数不用于计算改善百分比。
