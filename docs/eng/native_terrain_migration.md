# 原生地形迁移

2026-10-28。依据[前期调研](native_terrain_boundary_research.md)实施。

## 边界

`GDScript → 指令 → NativeTerrain → 事件 / 快照 → GDScript`

原生核心独占宏观网格、子格材质、两级 HP、版本、预测差分、权威基线和单人回溯记录。运行时使用连续原生数组；脚本得到只读网格或独立 HP 快照，不再把可写容器反复传入原生函数。

单人、权威和预测共用伤害、爆炸扫描、碰撞布局与查询。差别仅是启用的历史和输出：单人记录时间历史，服务端收集网络增量与收益，客户端维护预测差分和权威基线。地图格式和网络协议没有另起一套。

地图解析、AI 寻路策略、场景装配、网络会话、账户结算和表现仍由现有脚本管理。地形热路径不再通过反射读取脚本数据；这不表示整场游戏已迁入 C++。

## 执行与输出

- `load_terrain()` 一次装载宏观网格、子格和 JSON 材质定义；每个场景保留自己的原生引用。
- 子弹接触、单格伤害、区域爆炸、权威补丁和历史恢复都通过领域方法提交。爆炸核首次计算也在原生层，预测恢复后复用有界缓存。
- 角色、弹丸和预测战斗直接访问原生地形。爆炸产生的碰撞变化在后续依赖查询前提交，预测战斗不再为每次爆炸返回脚本接力。
- 网络变化按子格合并，每 tick 统一取出；破坏收益按角色汇总。原生核心输出一次变更通知，避免逐子格脚本回调。
- 显示变化按最终子格存亡合并，再提交给 TileMapLayer。恢复不产生新的伤害或收益；纯 HP 改动不重建碰撞。

Godot 继续拥有 StaticBody2D、CollisionShape2D 和场景生命周期。永久墙、可破坏分块、攀爬承托板与 3×3 环面副本沿用现有结构；布局、形状和几何区域历史由原生核心维护。相同占用布局不重复改动物理节点。

单人历史每个记录边界只保留改动宏观格的首个改前值。回溯通过二分定位时间区间，按逆序恢复，保留残血和混合材质；松手裁剪未来。预测历史按 tick 保存稀疏差分，确认与裁剪同步释放爆炸核。

移除旧 PredictionTerrain、TileLedger、NativeTerrainOps 和 NativeMotionGeometry。清除旧地形回调、两阶段 HP 初始化、脚本脏块与碰撞算法、可写网格暂存、节点 metadata 缓存和爆炸往返循环。TileDefs、Water、BeamTrace 与 TileQuery 保留薄适配入口。

## 验证

Windows Release 扩展编译、工程导入、177 个脚本加载和命名/路径检查通过。保留行为集首轮 23/24，清理遗留启动脚本后默认核心检查 9/9；网络探针经夹具更新后为 6/6。未进行 macOS 构建。

最终只运行一局八人、禁用 P2P、90 秒大乱斗，使用指定的两条公网中继并固定分组。总耗时 105.750 秒，8 个客户端正常结算，无运行错误、路由违规和日志丢失，最终收敛误差均为 0。原始日志和汇总位于工作区 work/native_terrain_migration_20261028。

这次验证仍有性能峰值，不能据此宣称卡顿全部解决：

| 记录 | 结果 |
|---|---:|
| 客户端战斗期记录 | 43,184 个主循环区间 |
| 客户端最大主循环间隔 | 57.808 ms |
| 该区间的物理节点回调累计 | 41.728 ms |
| 该区间的历史重放 | 31 tick，prediction_step 累计 33.030 ms |
| 该区间的原生地形碰撞提交累计 | 1.477 ms，4 个脏块 |
| 所有客户端的单区间地形碰撞提交最大累计 | 2.381 ms |
| 有碰撞提交区间的各客户端中位数 | 0.305～0.352 ms |

57.808 ms 是包含等待和调度的主循环间隔；该区间还有 13.601 ms 未落入外层记录范围。上述阶段相互嵌套，不相加。原生碰撞统计包含角色或弹丸内部提前完成的提交，避免只看最终 flush 漏算；它不包含全部爆炸计算、表现和历史审核成本。

这不是固定数据 A/B，不能与上局最大值直接计算迁移收益。当前结果证明了实际对局接线与状态收敛，仍保留了重放和主循环峰值的后续调查空间。本轮未继续扩大测试或分析校正。
