# 代理、弹丸和历史构造的 C++ 隔离验证

2026-10-27。承接[地形原生原型](native_replay_validation.md)，继续验证三个热路径。结论是：弹丸循环适合迁移；代理采样和历史构造直接通过 Godot 对象接口照搬到 C++，本例没有获得收益。

## 计时单位

所有方案由同一段 GDScript 使用 `Time.get_ticks_usec()` 围住完整恢复与 3 tick 重放。原始 `replay_us`、`forward_us` 和 `step_profile.*_us` 的单位均为微秒，展示毫秒时除以 1000。已有的 `restore_ms`、`combat_ms`、`replay_ms` 在生产代码中已经除过 1000，分析时不再次换算。C++ 原型没有使用另一套计时单位。

例如初轮弹丸组排序后的中间两条是 4703 us、4710 us，中位数为 4706.5 us，即 4.7065 ms。换算没有出错；旧的部分派生汇总文件曾在已经转换的值上保留 `_us` 内层键名，已改为 `_ms`。原始样本的字段和值没有改变。

## 实际迁移范围

原型位于工作区 `work/native_hot_replay_20261027/`，没有接入生产代码。

- 代理：缓存时效、历史帧选择、采样、运动状态恢复、姿态/碰撞层恢复和边界标记在 C++ 执行。缓存缺失时，新运动轨迹仍调用共享 `ActorStep.simulate_motion`，未另写一套攀爬、游泳和碰撞规则。
- 弹丸：C++ 保存弹丸运动/引信状态，执行重力、水阻力、实际 `move_and_collide`、反弹、射程、环面包装、连续玩家接触、攻击排序与历史查询记录；变更的兼容字段写回原节点。HP 命中效果、爆炸效果和地形阶段沿用既有回调，执行顺序保留。
- 历史：本地完整状态和输入游标的构造、远端查询数据、弹丸快照及历史字典写入在 C++ 执行。背包和账户仍调用现有共享快照接口。

这些迁移都保留实际引擎调用和兼容性写回成本。代理与历史仍访问 GDScript 对象及 Godot Dictionary/Array，没有改为全程由 C++ 拥有的紧凑模拟状态。因此不能把本实验写成“全部角色玩法和完整回滚管线已迁到 C++”。

## 同轮对照

沿用 tick 546 锚点、原输入、七枚远端霰弹、tick 548 爆炸和随后正常推进的数据。每组预热 3 次、记录 30 次，主对照顺序为地形 A1 → 弹丸 B1 → 组合 C1 → 组合 C2 → 弹丸 B2 → 地形 A2。使用同一引擎、同一适配脚本和 Release DLL，不启用 FrameTrace、脚本 profiler 或外部采样器；stdout 经持续排空的 PIPE 写入。区间包含恢复和 3 tick 重放，不含随后正常推进。

| 方案 | 第一组原始中位数 | 第二组原始中位数 | 两组中位数平均，换算后 |
|---|---:|---:|---:|
| 仅地形 C++ | 5881.5 us | 6064.5 us | 5.973 ms |
| 地形 + 弹丸 C++ | 4585 us | 4710.5 us | 4.648 ms |
| 再加代理采样与历史构造 C++ | 5128.5 us | 4891.5 us | 5.010 ms |

弹丸迁移使本轮基线减少约 1.325 ms、22.2%。组合版本相对基线仍减少约 16.1%，但比只增加弹丸迁移多约 0.362 ms。上一轮“仅地形约 5.67 ms”是另一轮进程测量，当前收益百分比只使用本轮两侧基线。

单项诊断也显示同一方向：仅增加代理采样原生实现时，代理/攻击准备粗阶段为约 1.679 ms；参考 A1 组为约 1.532 ms。仅增加原生历史构造时，历史保存阶段约 0.393 ms；参考 A1 组约 0.310 ms。单项诊断是独立运行，用于判断方向，不与主对照拼成一份精确预算。

主对照中，3 tick 战斗/弹丸/地形粗阶段从约 2.684 ms 降至 1.493 ms；本地角色运动保持原实现。阶段数字为独立中位数，不能直接相加重建完整区间。

## 一致性与限制

每个性能样本都在计时外与原生产参考比较本地完整预测状态、全部存活弹丸、地形 HP、宏观网格、碰撞子格、账户、输入游标，以及各 tick 的角色/弹丸/账户历史，全部一致。

另用独立进程捕获五个边界：恢复地形后、三个重放 tick 提交后、正常推进 550 提交后。除上述内容，还比较完整代理运动状态、姿态/HP/碰撞层、代理年龄/过期标记/生成与命中计数、弹丸引信/结束/爆炸标记与变换、实际地形碰撞形状、全部历史字典、命令、远端接触查询、射手模式和攻击结果，全部一致。这些较重的捕获没有进入性能样本。

只验证了一个固定 PvP 案例和 Windows x64，尚不能作为通用联机迁移完成或八人实机帧间隔改善的证明。

## 取舍

优先保留原生地形和弹丸批处理的方向。代理与历史在本次实现里依然频繁通过 `Object.get/set` 访问 GDScript 成员，这些反射边界没有被原生编译消除；[Godot 的静态类型文档](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/static_typing.html)说明现有类型已知的 GDScript 本身也有优化字节码。实测结果支持先改变数据归属、减少跨对象读写，再评估这两项迁移，而不是只更换外层循环语言。

原型保留在工作区供继续研究，生产源文件的 316 项哈希与本轮开始时一致。`summary.json` 同时保留明确标注的 us/ms 中位数；`capture.gd` 与 `checks/` 保存中间状态验证；`manifest.json` 保存范围、顺序和代码/DLL 哈希。
