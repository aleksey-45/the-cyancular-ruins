# 联机恢复与重放改造（协议 v3）

日期：2026-10-24；输入完整性与预算修订：2026-10-25。基于 `siri_v0.5.0` 的源码审计和[大型游戏技术资料](netcode_industry_reading.md)实施。初次改造按用户要求仅做静态检查；随后获准执行八人中继对局，发现并继续修复重放成本与非网络校正。本文描述当前代码，运行结果与限制见[实测记录](netcode_test_results.md)。

## 1. 改动目标与恢复单元

本轮保留专用服务端权威、60 Hz 模拟、30 Hz 常规 STATE、环面硬阻挡和独立视觉时间线。改造集中在三件事：同一输入所需的状态与规则保持一致，按同一 tick 恢复交互依赖，以及避免每次收包都重复整个预测窗口。

| 恢复内容 | 实现 |
|---|---|
| 角色运动、HP、倒地及计时器 | `Player.capture_state/restore_state` |
| 远端运动驱动 | `driver` 提供背包、装备、射击序号、武器冷却/蓄力/装填、氧气计时与下一步控制锁 |
| 输入游标 | 各角色的 epoch、移动 ACK、动作 ACK 和未经表现过滤的持续输入 |
| 逻辑弹丸 | STATE 的 `world.projectiles` 提供该 tick 的位置、速度、距离、引信和直接命中标记 |
| Beta 账户 | 所有角色共用同一 `TimeEconomy`，从同一 STATE 恢复 |
| 地形 | 按权威 `map_revision` 门控；保存预测子格增量，比较与恢复同 tick 的地形，物理碰撞在 tick 末提交 |

权威锚点来自完整解码的 STATE。逐 tick 历史保存角色驱动、输入游标、碰撞参与层、弹丸、账户和地形历史代号，可以作为整组玩法检查点恢复。先比较同 tick 的完整世界，再检查后续命令和事件；未来的预测爆炸不阻止历史状态比较，相同地形补丁也不强制重放。场景树、物理空间和表现资源不逐帧复制，输入队列由游标和保留的命令重建。具体规则见[历史校验与预测复用](prediction_reuse.md)。

## 2. 运动与战斗阶段

入口为 [PredictionRollback](../../core/net/prediction_rollback.gd)、[PlayerReplica](../../scenes/player/player_replica.gd) 和 [AuthorityWorld](../../server/authority_world.gd)。

远端预测从只调用 `simulate_motion` 改为调用完整 `ActorStep.step`。冷却、蓄力、切枪、装填和反冲现在与服务端走相同代码。隐藏角色只生成逻辑攻击，不执行其动作列表中的声音、动画和视觉弹丸。

每个预测 tick 的顺序为：

1. 更新复活阻挡边界，建立按角色 ID 排序的参与者列表。
2. 依次消费各角色输入、扣除加速消耗、推进完整角色逻辑、处理该射手的光束与已知角色阶段收益。
3. 全部角色完成后，账户统一回复一次，记录供光束历史查询使用的碰撞框。
4. 按攻击 ID 推进弹丸；对应爆炸立即作用于角色和地形 HP，再推进后续弹丸。
5. 全部弹丸运动结束后结算直接命中，应用已知弹丸阶段及规则阶段收益。
6. 提交地形碰撞，保存比较历史。首次预测才执行本地动作表现。

逻辑角色和逻辑弹丸使用规范坐标，不读取视觉锚点或场景树中第一个玩家的当前坐标。最近环面副本由 `ActorCollider` 和表现层各自计算。榴弹移动前的点接触使用共享目标过滤，排除倒地/回溯和友方目标；等距直接命中按角色 ID 决定，避免数组插入顺序影响结果。

光束预测按射手 `view_tick` 查询已有历史框，与服务端采用相同的 12 tick 限制。客户端没有对应历史框时回退到当前框，最终命中仍以服务端事件为准；本轮没有把未获得的历史几何视为已知。

## 3. 输入提示和失效范围

入口为 [RoomSession](../../server/room_session.gd)、[InputBuffer](../../core/net/input_buffer.gd) 和 [NetCodec](../../core/net/net_codec.gd)。

原先只转发当帧发生变化的角色，然后清空集合。由于 INPUT 发送队列只保留一条最新整包，另一角色的新提示可能覆盖尚未提交的旧包。

现在服务器保留各角色最近四条持续输入和动作时效内的记录，每次发送全角色有界集合。每条提示保存第一次在服务器可用的 `available_tick`，重复转发不会把它推迟到后一次到包时间。此字段只存在于服务器下行格式，上行不接受客户端指定该时间。

序号逐条写入，不再假设冗余集合一定连续。远端用 `(epoch, seq)` 索引去重，避免包列表之间的嵌套扫描。新信息记录最早和最晚受影响 tick；同批 STATE 已覆盖全部变化时，可以重新检查历史复用资格。未覆盖的变化从可用检查点或权威锚点重放。

收包时只把新增或更早可用的记录提交给输入队列，整份历史仅在恢复时重建。持续提示最多保留 128 条，动作提示最多 48 条；调度队列还检查 `available_tick` 是否在锚点后 32 tick 内，防止目标 tick 很旧但实际可用 tick 很远的提示堆积。STATE 长时间没有应用时，提示历史也不会无限增长。

容量淘汰先移除预测窗口以外的提示，保护从当前权威锚点恢复所需的记录。若窗口内输入仍超过容量，按帧/动作分别记录丢失序号；拒绝检查点重放与后缀复用，暂停正常预测。新 STATE 仍可恢复权威位置，但以 `remote_history` 标记不完整历史且不重放；直到移动/动作 ACK 覆盖缺口或 epoch 改变后才恢复预测。本地未确认输入和动作继续重发，按自身 ACK 与时效清理，不因远端缺口被清空。本地检查点也检查保留输入是否已越过其游标。

## 4. 弹丸锚点与资源生命周期

入口为 [CombatPrediction](../../core/net/combat_prediction.gd)。

- STATE 直接提供锚点 tick 的逻辑弹丸状态，恢复时不再用当前地形把出生初态追赶到该 tick。
- 出生初态、出生 tick、当前锚点及未来权威检查点分别保存。权威出生时间可以纠正先前的预测假设；确认的弹丸不因一次更早的预测开火而提前激活。
- 同 ID、同类型的弹丸复用节点；类型不同则重建，避免沿用错误的形状、伤害或引信配置。恢复运动状态同时恢复旋转。
- 重放生成同一未确认攻击时更新其初态，不把旧预测位置当作本次新起点。结束或拒绝的实体停止参与模拟；保留窗口结束后释放，复用成功时也执行清理。
- `BULLET_FUSE` 记录阶段检查点；爆点在正常 tick 推进时产生。线上收包和重放不再调用完整轨迹预演。旧 `plan` 接口暂供既有离线调用和夹具使用，不在 PvpMatchClient 热路径内。
- 已确认光束不会被重放时生成的同 ID 临时光束覆盖。命中确认继续按攻击、tick、阶段和受击者独立匹配。

## 5. 时间账户收益

[TimeEconomy](../../server/time_economy.gd) 在实际入账时报告金额。服务器按 tick、阶段、角色合批为可靠 `TIME_REWARD`，携带独立序号；一次爆炸破坏多个子格不会逐格发送可靠包。

客户端恢复账户后，在对应角色、弹丸或规则阶段重放已知收益。STATE 覆盖的收益被清除，不重复入账。收益保留服务器已经执行容量限制后的实际金额；未确认收益不额外猜测。这样，已经收到的伤害、击杀和地形收益可影响下一 tick 的加速许可。

Beta 回溯本身继续依赖权威状态和 BULLET_REWIND；本轮没有复制服务器的完整 Beta 历史或预测未知复活出生点。

## 6. 条件复用和性能边界

`reusable_tick` 位于 PvpMatchClient 恢复任何远端角色或账户之前。首先严格核对完整锚点，再寻找可保留的预测前缀；全部等价时保留整个后缀：

- epoch、时钟和输入历史仍有效；没有本地回溯。
- 角色集合、每个角色的完整驱动状态及远端回溯/复活边界一致。
- 从新权威输入游标重建调度后，被保留的每个 tick 消费的命令在玩法上等价，远端回溯阻挡轨迹一致。
- 同 tick 的逻辑弹丸和全部账户一致，权威地形版本一致。
- 没有临时预测地形；被保留的前缀不越过 STATE 尚未覆盖的新可靠事件。

角色、弹丸、账户和地形使用严格字段相等，不放宽位置阈值。输入 ACK 或序号不同不会单独否决复用：用临时 `InputBuffer` 重建后缀，逐 tick 比较轴、持续按键、动作边沿和武器上下文。全部等价时提交新队列、游标和命令历史；遇到不同命令时，只提交有效前缀的游标及命令历史，恢复其末尾的整组检查点，重建队列并重放失效后缀。部分复用仍执行视觉校正。锚点不等价、没有有效前缀或无法恢复检查点时，恢复整组权威锚点，最大重放窗口保持 32 tick。`diagnostics.reused_ticks`、`counts.history_reuses`、`counts.prefix_reuses` 分别记录保留 tick、整段复用与部分复用；`reuse_counts` 按首个拒绝条件分类，`reuse_totals` 记录累计跳过与重放量，不能把首个拒绝条件解释为全部差异。

远端输入提示先与已经消费的持续输入比较。瞄准变化在实际开火时比较精确向量；其他 tick 比较共享的朝向死区结果，涉及零向量回退时保守失效。`view_tick` 只在实际执行光束历史命中查询的 tick 参与比较，包括可靠光束到达后补做的查询。动作边沿仍单独处理。确有变化且本批没有新 STATE 时，尝试恢复 `dirty_tick - 1` 的检查点，只重放失效后缀；缺少历史、角色参与层发生变化、弹丸身份冲突或存在临时地形时使用完整权威恢复。已知可靠事件保留，失效后缀中的未确认光束与爆炸撤销后重新生成。`counts.checkpoint_replays`、`diagnostics.checkpoint_tick` 记录该路径。

这与 [Valve 的预测结果复用](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/prediction.cpp#L1329)和 [GGPO 的输入比较及最早错误帧](https://github.com/pond3r/ggpo/blob/master/src/lib/ggpo/input_queue.cpp#L201)对应；本项目的硬阻挡、弹丸和账户仍整组恢复，不能套用仅回退单个角色的优化。

此外，攻击 ID 集合按 tick、阶段和射手筛选；碰撞参与者列表在一段重放前准备；SnapshotBuffer 只保存表现所需的角色/掉落物，避免每个渲染帧深拷贝驱动状态和弹丸锚点。

初次八人公网测试暴露了低复用率和大量整窗重放，不能视为优化验收。针对性探针对照检查点与完整重放的角色、弹丸、账户结果相等；八人中继对局的卡顿、重放量和校正见实测记录，流程通过与性能达标分别判断。

服务端同次广播复用角色、拾取物、账户和弹丸公共编码；缓存同时核对当前世界、地图版本、角色表及各接收者的基线世界。序列号、ACK 与 `own` 保持各连接独立；公共历史从调用方深拷贝一次后只读，避免重复深拷贝或被后续调用方修改。

接收端只合并 STATE，保留同连接、同事件屏障内的最大序号；INPUT 有限冗余不保证覆盖旧包，保留每个收到的包，解码后由输入缓冲按记录去重。可靠事件、连接事件和异常协议包作为顺序屏障。STATE 只依赖已回传的 ACK，同批尚未派发的中间 STATE 不会成为新基线。合并量单列为 `rx_coalesced_state`，不能作为物理丢包计数。

原生每次轮询有 256 条、512 KiB 线上/解压字节及 2 ms 软接收预算；最多预取 64 条消息，未处理引用留到后续轮询，关闭时释放。脚本派发另有 512 KiB、2 ms 软预算，剩余批次保序保留。每帧最多新取 `256 - 待派发数量` 条，合并新旧 STATE；只有批次已满时才调用 `poll(0)`。这样排空旧批次时仍能获得新锚点，避免旧 STATE 留在脚本队列、新 STATE 留在原生队列的正反馈。两层预算均在完整消息之间让出，单条解压、解码或回调可以超过预算，不承诺整帧硬上限，也不按墙钟中断角色模拟。

GNS 每连接接收缓存限制为 4 MiB/1024 条，单条传输消息最多 128 KiB+4 字节；大型可靠事件仍按分片组装，检查声明长度一致且累计长度不越界。脚本待派发消息每连接限制为 64 MiB/1024 条，收到后排队超过 5 秒则关闭该连接，通过现有重连流程获取新 epoch/基线。上述数值是保护初值，不能代替对公网断流原因和实际性能的判断。

## 7. 协议与检查状态

NetBus 当前协议标识为 `[199, 3]`，增加远端回溯阻挡轨迹，客户端和服务端必须一起更新。v2 已增加 `driver`、原始输入游标、提示可用 tick、STATE 弹丸区块及 `TIME_REWARD`。不同版本在进入 NetCodec 解码前被拒绝，客户端显示版本错误或握手超时。现有协议夹具已随格式更新。GNS 原生发送只查询本次目标连接，轮询再重试全部连接；查询 lane 前仍先确认连接状态，避免关闭过程查询未配置的 lane。Windows x64 扩展已重新构建，本次 v3 脚本变更未修改原生 ABI。

积压修复前已完成 Godot 导入与网络六项回归，包括检查点后缀、六种武器、协议、基线、重连与本地服务进程回收；地形弹性探针通过。后续输入完整性、预算、回溯轨迹与查询缓存的定向检查，以及八人压测结果，见实测记录。十分钟公网对局流程通过，但卡顿和大幅校正未达标，不能作为 v3 的验证结果。各次八人测试的源码和原生二进制 SHA-256 保存在对应诊断分析中；原生修改尚未在 macOS 构建验证。

## 8. 卡缝时的速度累积

本机中继测试的权威角色曾在相近位置持续增加纵向速度。`move_and_collide` 的初始重叠接触可能返回侧向法线，而实际轴向行程已被截断。共享 `ActorStep.move_by` 现在同时检查实际行程，阻挡轴立即清零速度及相应击退分量；不通过限速或修改视觉平滑隐藏卡缝。普通缺口、残留子格、弹性表面及联机共用同一处理。

## 9. 远端回溯与重复地形查询

十分钟日志中，70 ms RTT 的 192.7 px 校正涉及相邻回溯者从阻挡位置离开；78 ms RTT 的 144.8 px 校正涉及回溯者移动到下落角色脚下。`BetaHistory` 在服务端推进历史位置，而客户端此前只保留回溯者的快照位置。收包正常时也会产生这类分歧。

v3 的角色字段 `rewind_path` 由服务端使用同一回溯游标函数生成，最多覆盖未来 32 tick，只保留位置、蹲伏、倒地和朝向发生变化的结点。每结点 13 字节，另有 1 字节数量；没有发送整份回溯历史或武器状态。预测在所有角色阶段之后、弹丸阶段之前更新这些阻挡体，与服务器的 Beta 阶段相同，并补扣回溯账户消耗。中途释放、耗尽或结束由后续 STATE/epoch 确认；此轨迹不代表已知未来输入，也不恢复整套远端回溯战斗历史。

角色步进的地形运动查询在同一几何版本内按完整变换、裁剪后运动、碰撞掩码、安全边距、碰撞形状及其变换缓存。每角色最多 256 条，哈希相同时仍比较完整参数；每次地形节点重建提高几何版本，清除旧缓存。远端角色矩形每次仍参与裁剪，变化后的运动不会命中旧查询。缓存仅由联机预测器开启，不用于服务端或单人模拟。保留的接触引用可安全复用的依据为 [Godot PhysicsBody2D 源码](https://github.com/godotengine/godot/blob/master/scene/2d/physics/physics_body_2d.cpp#L48)，脚本持有引用时引擎会为后续接触新建结果对象。

预测历史还复用未变化的只读背包快照，普通 `capture_state()` 仍返回可编辑的独立背包；玩家历史碰撞框直接读取当前启用姿态，避免逐个遍历表现子节点。`--prediction-profile` 可按需记录角色、攻击、弹丸与历史保存耗时，`motion_cache` 记录累计命中、未命中和占用。
