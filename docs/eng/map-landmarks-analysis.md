# 地图「没有记忆点」——只读分析稿(2026-11-01)

> 状态:**分析,未实施**。起因 = 用户反馈「地图没有记忆点怎么办」。方法 = 只读解析 `maps/*.cyrm`(v4)、
> `structure.png` 与相关源码,未运行游戏/编辑器/服务端。返回索引:[`README.md`](README.md)。

## 1. 一句话结论

不是"地图太大记不住",是**地图里没有任何可记的东西**;而且配色自由度实际为 0 —— 格式支持、编辑器关了 UI、
运行时读盘时把辅码丢掉,**三处断点同时断**。

## 2. 硬数据(只读解析得出,非推测)

1. **尺度**:世界 9600px 宽 / 玩家 700px/s ⇒ **13.7 秒绕世界一圈**;可见 40×30 格(viewport 2208×1728 +
   `cam_zoom 0.75` + PostProcess 中心裁切)⇒ 一屏 = 全图 **8%**,共 12.5 屏。
2. **颜色**:墙砖 1–10 两两最大 RGB 距离 **55.2**、亮度全在 107.6–137.2;纹理 1–5 是纯色块(逐像素标准差 0.0);
   19 与 20(树干竖/横)平均色距离 **0.0**。`newfactory` 填充面积 **59.6%** 由这一色带的 7 种墙砖构成。
3. **辅码**:两张图所有非空子格的 `(hue,bri,sat,alpha)` **只有 (4,4,4,7) 一种**(全中性)。而运行时
   `MapFormatV4.scene_to_subgrid()` 只取 `(d>>12)&0xFFF`,辅码整段丢弃;编辑器 `level_editor/ui/85_panels.js` 又把四个
   辅码控件在非背景层 `hideRow` 掉 ⇒ **三重断点**。
4. **空间单元**:`newfactory` 810 个地板格被切成 **294 个连通区**,最大 49 格(<一屏),**231 个区 ≤3 格**;
   横向平台宽度中位数 **2 格**,78% ≤3 格 ⇒ 地图是"纸屑地"不是房间。
5. **结构**:两张图都近似左右镜像(`newfactory` 非空子格 **57.9%** 与镜像位纹理完全相同);PvP 出生点
   P1(23,43)/P2(26,9)横向只差 3 格、都远离中心(75,50)⇒ "绕圈都像同一条路"近乎字面事实。
6. **小地图/HUD**:只有 3 色(空气/水/其它灰,`minimap.gd`),无名字、无方位;单机 `level_0`
   **根本没有小地图**;全仓 `compass`/罗盘/方位 grep = 0;全仓零 `Light2D`/`WorldEnvironment` ⇒ 无光照分区机制。
7. **数据模型没有"区域/地标"这一层**:scene 层只有纹理 id + 辅码;meta 只认 `player`/`player2`/`enemy`,
   其余行 `_: pass`;`region`/`landmark` grep 零命中(只有 `SpawnPicker` 连通区与编辑器选区)。

## 3. 结论性判断

- **可辨识性 = 差异度 × 记忆锚点 × 方位感**。现在三项全缺:颜色差异度几乎 0(且辅码被丢)、没有名字/地标、
  小地图无方位无名字;再叠加"近似镜像 + 13.7 秒一圈",人脑没有可编码的空间参照。
- 因此**先改"数据"比先加"系统"性价比高**:地图本身没有可记的结构,先加 UI/小地图标签也记不住。

## 4. 免费载体(不需要改格式、不需要改协议)

格式里已有、但没人用的三处:
- **(a) 每子格辅码** bit0–11(hue/bri/sat/alpha):已能存、已能画(编辑器有控件),**运行时读盘时被丢**
  (`scene_to_subgrid()`)。要恢复 = 在 `MapFormatV4` 读盘时保留辅码并传给渲染层(改一处 + 渲染消费一处)。
- **(b) 背景 RGBA 层**(`layer_flags` bit3,kind=2):`map_format_v4.gd` 明确写"游戏侧暂不消费",
  两张实盘图该 flags 都是 `0b0010`。可用于分区底色/氛围色。
- **(c) meta 注释行**:未知 `#` 行被忽略但 `load_meta_lines()` 原样读出,编辑器 `level_editor/core/40_meta.js` 往返保存
  ⇒ **零格式改动**地写「区域/地标」声明(例如 `# region <id> <x> <y> <w> <h> <name>`)。

## 6. 联机一致性(A/B 档全部成立,已逐条查证)

- 服务器 `MapCatalog.resolve_pvp_map()` 只认 `res://maps` + 双出生点,`match_start` 下发 `map_path`,
  客户端建世界前 `set_map_file` ⇒ 两端同字节,**按构造一致**。
- 地标做成**不可破坏纹理**(`type=wall`,`bullet/explosion_destroyable=false`):`damage_tile`/`damage_sub`
  早退 ⇒ 不发 `tile_destroyed`/`sub_destroyed`、不进 `_damaged_subs`、不进 `destroyed_subs` 补态、不进
  `TileLedger` ⇒ 协议/快照/回溯/换局复位全部不受影响。**强烈建议不要做可破坏地标**(要同时进 4 处,
  漏一处 = 幽灵砖 / 回溯不回来)。
- 唯一真实风险:**运行时随机**(无 seed)生成装饰会两端分叉;必须从文件派生。
- 碰撞不分叉:服务器 `MatchHost` 与客户端 `Level0` 都走 `WorldBuilder.build_sim()` 从同一 `current_grid` 建。
- 出生点会受影响:加实心砖减少地板格,`SpawnPicker.OPEN_AREA_MIN=20` 依赖最大连通区,该自适应分支今天零守卫。

## 7. 推荐路线

**先做一件事**:A1 —— 纯数据重画 `newfactory` 的宏观结构(中心厅 + 两条主干道 + 合并零散台)。
零代码、当天可见、可回滚,先把"一屏内有可记的块"这件事立住。
**1~2 天最小方案** = A1 + A3(meta 区域声明)+ B2(小地图按区域上色 + 区名):这时玩家能说出"我在东北的那片大平台",
小地图也有名字,记忆锚点才算成立。A2(地标砖)按 A1 完成后再挑点加。

## 8. 需要留意的既有隐患(建议登记)

1. **编辑器允许画到纹理 100,游戏只编译 22 行**(`TerrainAtlas.TEX_COUNT = 22` / `TileDefs.MAX_TEXTURE = 22`)
   ⇒ 今天就能画出"看不见的墙"(越界纹理被判 `TYPE_WALL` 但图集无该行)。加地标砖必须三处同改(两个常量 +
   `MapCatalog.PALETTE`,漏 PALETTE 则缩略图回落灰)。
2. **两份 `structure.png` 已经漂移**:像素差异在 (0,64)-(64,96) = 纹理 21/22(水),游戏侧
   (106,138,164)/a210 vs 编辑器侧 (102,128,153)/a200,零守卫。
3. `registered-debt.md` 已记:map_catalog / map_format_v4 **零守卫**;`levels_editor` 与 `minimap` 的色表是
   两套手写观感。
