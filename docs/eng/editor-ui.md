## 1. 分片与加载顺序

- 19 片按**文件名字典序**加载，`NN_` 前缀就是顺序。**顺序的真相源是 `level_editor/editor.html` 的 `<script src>` 列表** ——
  node 侧的 `level_editor/loader.js` 从同一个地方读，不另抄一份；`parts_check.js` 守「目录 ↔ 页面」一致。
- 分片在**一个共享作用域**里求值（经典 `<script>` 共享同一个顶层词法环境），所以分片之间能直接引用彼此的顶层声明；
  代价是**顶层名不许重名** —— 重名即静默覆盖，`var` / `function` 那条连错误都不报。
- 末片恒为 `99_exports.js`：公开 API 表只在它里面，`editor_smoke.js` 按它取名字。
- ★ **顶层一行都不碰 DOM**：DOM 只在 `boot()` 与它装上的回调里取。于是 node 能把「错了也不报错、只在屏幕上看出来」
  的那几层（工具内核 / 撤销差量 / 名字 / 尺寸钳制）逐条断言 —— 见 `editor_smoke.js`。
- ★ **页面里不许有第二份数学**：像素走 `Tint.*`，编解码与迁移走 `Core.*`，几何走 `Render.*`。

## 2. 尺寸闸只有一条路

```
applySize → resizeMap → createEmptyMap → Core.clampMapSize
```

- `Core.createMap` **不判** 400×300 上限（它只要求正整数）。所以第二个造图入口就等于审计 A8 原样复发：
  输入 99999 分配巨图、标签页卡死。`editor_smoke` 相位 ⑪ 数着 `Core.createMap` 的调用点（恰好两处）。
- 审计 A8 的原始形态：旧编辑器的 `clampMin` **第三参是「非数字时的默认值」**，根本没有上限 —— 名字看着像钳制，实际不是。
- 「这一格没有给一个数」的判据必须与 `Core.clampMapSize` **同一把尺子**（`parseInt(v,10)` + `isFinite`）：
  `<input type="number">` 里删光或填垃圾读回来是**空串**，而 `clampMapSize('')` 回落到 `DEFAULT_CELLS_W/H = 125×75` ——
  那是**造新图**的语义。在「改尺寸」这条路上它是一次**静默缩图**：400×300 的图里把宽那格删空、按「应用尺寸」，
  图变成 125×300，而用户以为自己什么都没输、什么都没改。
- ★ 钳制**不报错回滚**（闸 1）：NaN / 0 / 99999 一律落到合法区间，钳完照样回显到输入框。
- ★ **默认尺寸的唯一来源是 core 的 `DEFAULT_CELLS_W/H`**（同域可见，不在 ui/ 里重抄一份）。

## 3. 状态栏：`#st-save` 与 `#status-msg` 是并排的两件事

- `#st-save` 说「磁盘上那份是不是这一份」，`#status-msg` 说「刚刚发生了什么」。
- **没有这个标志时的症状**：`#st-save` 是一格**没有任何写入者**的静态文案（`editor.html` 写死「未保存」），
  于是 Ctrl+S 成功的那一刻同一条状态栏上同时出现「未保存 | 已保存 demo_copy.cyrm(1234 字节)」——
  两个相邻的 span 当场互相打脸。
- ★★ **一个写入者**：三种文案全在 `renderSaveState()` 里决定，别处只改 `dirty` / `lastAutoSaveAt` 两个变量。
  两个写入者（草稿盘直接写 DOM + 这里重画）会互相打脸。
- ★★ 它**只**在「保存真的成功」与「打开真的成功」两处清零，**绝不**挂在 `guard(...)` 的决议上：
  `guard` 失败时决议的是 `undefined`（见它的实现），把清零链在它上面会把一次**失败**的保存标成「已保存」，
  而磁盘上那份一个字都没变。
- 草稿盘接管这一格之后的措辞是「已自动保存 12:34」（规格 §4.5），「未保存 / 已保存」于是降级成
  **没有草稿盘时**的回落值。
- ★ **撤销/重做也是一次改动**：回到「保存时那一刻」的图上仍显示「未保存」是**刻意的** ——
  要判「撤销回去了没有」得比整份字节（那是草稿盘的事）。反过来（把撤销当「变干净」）会把
  「撤了两步、其实还脏着」标成已保存，那才是错的。

## 4. 编码出口与「压缩」开关（规格 §3.5）

- 规格 §3.5 的退路 `compression = 0`（裸 body）是一条**完整可用的路径**，不是半成品 ——
  浏览器 `CompressionStream('deflate')` 与 Godot `COMPRESSION_DEFLATE` 能不能对上，
  **设计期无法实跑验证**（要同时跑浏览器与 Godot），而这条分支的浏览器那一半至今也没验过。
- ★★ `optCompress()` 是**唯一**读这个开关的地方，而且是**一处对三处共用**的一条路：
  真文件（`saveCurrent`，Ctrl+S / 另存为）、草稿盘（`saveDraft`）、崩溃槽位（`installCrashFence` 的 snapshot）。
  **前两处必须同值**，否则 `offerDraft` 那道 `sameBytes(rec.bytes, app.raw)` 会比出「不同」——
  于是一次开机弹一次**假的**「发现一份还没写盘的草稿」，而两份内容其实一模一样
  （那种假提示能让用户按下去，把草稿盖回真文件）。
- ★ 长作业（油漆桶 / 渐变）分帧的**让出判据是时间预算**（`Render.createSlicer`，默认 8ms/帧），不是固定条数。
  实测取值：`JOB_QUANTUM = 2048`（一个量子的格数，小到慢机器上一帧也撑不爆 —— 它是超调的上界）、
  `JOB_QUANTA = 4096`（一轮的量子额度，取得**故意大**：一轮结束必须是因为预算到点，而不是因为「条数跑完了」，
  后者又变成固定条数节拍器；作业提前做完时剩下的条目是空转（立即返回），不花时间）。

## 5. v3 → v4 迁移与原文备份

- 仓库里 `maps/*.cyrm` **当时全是 v3 文本**，而 Ctrl+S 写回原文件（规格 §4.6）⇒ 一次 Ctrl+S 就把 v3 原文
  转成 v4 二进制，而迁移是**单向**的（规格 §3.6「迁移是一次性的」）。期 E 会专门做迁移并先提交一份 v3 原文留档。
- 确认框要说出的**决定性的那件事**：游戏今天**读不了** v4 —— 在 `core/sim/map_format.gd` 迁移过去之前，
  这个文件在游戏里会失效。
- ★★ **确认与备份是两条独立的门**：确认每会话一次（`v3Confirmed`），备份**每个文件**一次（`v3BackedUp`，键 = 保存目标文件名）。
  两半共用同一个会话级标记时，同一会话里保存**第二张** v3 图会两半都不发生 —— 那次单向转换既没有确认也没有备份，
  安全网只盖住第一张图。
- ★ `v3BackedUp` 用 `Set` 而不是普通对象：图名合法字符里含 `_`，`__proto__.cyrm` 这种名字在普通对象上
  赋值 `__proto__` 会被**静默忽略**、读回来是 `Object.prototype`（truthy）⇒ 那条分支永远不备份而**不报错**。
- ★ 记账**只在备份真的写成功之后**落：写失败时保存整个中止、`sourceFormat` 仍是 v3
  ⇒ 用户重试那一次**必须**再写一遍备份，否则第二遍就可能无备份落盘。

### 5.1 备份名的形状：`<基名>_<8 位十六进制>.v3.bak`

- ★★ 结尾**不是** `.cyrm`，于是游戏的 `MazeGenerator._random_cyrm`（`f.to_lower().ends_with(".cyrm")`）
  抽不到它 —— 备份不会混进随机地图池（实证确认）。
- 服务器 `editor_server.js` 的名字校验当时只放行 `<基名>.cyrm`；**2026-09-22 用户裁定唯一放宽一次**
  （只多接受 `.v3.bak` 这一个后缀），于是这里才能用回原本想要的名字。
- ★★ 哈希（FNV-1a 32 位，输出补到 8 位十六进制）是**必需的**：「收干净 + 截前 40 字」**不是单射** ——
  `图1.cyrm` 与 `1.cyrm` 收完都是 `1`；`图甲.cyrm` / `图乙.cyrm` 收完都是空（回落 `map`），
  而两个长名字截到同一个 40 字前缀的图会**共用同一份退路**。撞名的代价**不是报错**（不报错更糟）：
  第二张图的原文会把第一张的退路**静默覆盖**，而两张 v3 都已经转成 v4 了。
  输入取**完整原文件名**（截断前那一份），于是「截断」这条撞法也一并闭合。
  这里没有攻击者，要挡的是「两个看着不相干的名字落到同一格」这类意外，32 位足够。
- ★ 基名仍**只许** `[A-Za-z0-9_-]`（服务器的 `MAP_NAME_RE` 没有放宽）：种子名可能来自 `freshName`
  （它走 `Core.sanitizeName`，**放行汉字**），不过滤的话备份会被 400 拒掉，
  而「备份写不进去就不写盘」会把保存整个卡死。顺带 `.` 也收掉。
- 长度：整名最长 `24 + 1 + 8 + 7 = 40` < `MAX_MAP_NAME_LEN`（64，守卫在 `editor_smoke`）。
- ★ 哈希用 `Math.imul` 而不是 `h * 16777619`：后者在双精度里溢出，低位不可靠。
- ★★ 备份**不是地图**：它的内容是这张图**原文**的最后一手退路。把它当保存目标就地覆盖 = 退路换成 v4
  且名字漂成 `<名>v3bak.v3.bak`（不报错）。`isBackupName` 这个判据有两处消费者：库列表过滤显示
  （`refreshLibrary`）与 `saveCurrent` 的一道闸。★ 列表只管**点击**，`?p=xxx.v3.bak` 这条 URL 直接打开的路它管不到，
  故 `saveCurrent` 那道闸不可省。

## 6. PUT 只有一个出口：`putMapBytes`

- ★★ 纪律：PUT **必须显式带** `Content-Type: application/json`。服务器（`editor_server.js`）的写端点
  只收这一个类型，别的类型一律 **415** —— 而不写 `headers` 时浏览器按 body 的类型推，
  `new Blob([bytes])` 推出来的是 `application/octet-stream` ⇒ 415。症状是
  「点了保存、磁盘上那份没变、只有一行红字」，而且**不报错回滚**。
- ★ 因此**页面上发 PUT 的地方恰好一处**：真保存与原文备份都走它。再拼一份 `fetch` 就是第二个出口，
  迟早只改一处。
- ★ 备份**排在真保存之前**，而且走**同一个**出口；备份写不进去就**不写盘** —— 这次转换是单向的，
  备份是唯一的退路，先写盘再发现备份失败 = 原文与退路一起没了。
- ★ 不写 `method` 的都是只读（GET：`openMap` / `refreshLibrary`）。失败原样抛出（不是静默返回），
  由调用方把它变成状态栏上的一句话。

## 7. 持久化三层与崩溃栅栏（规格 §4.6 + 闸 4）

三层是**递进**的：

| 层 | 存什么 | 语义 |
|---|---|---|
| ① 真文件 `maps/*.cyrm` | 作品本体（Ctrl+S 写回） | **最高保真副本**永远是真文件 |
| ② IndexedDB 草稿盘（`cyrm-editor` / store `draft`） | 「还没写盘的活」 | 状态栏那一格由它接管 |
| ③ localStorage（键 `cyrm.ui.v1`） | 「下次打开时界面该长什么样」 | 小状态；读损坏值一律回落默认（编辑器要能开） |

### 7.1 库结构

- ★ 库版本 **2** = 给草稿盘加 `savedAt` 索引。它换来的是两条**不物化记录本体**的查询：
  「最新一条的 `savedAt`」（启动时的崩溃槽位比对，走 `openKeyCursor(null,'prev')` 的**键游标**）与
  「按时间升序挑淘汰对象」（闸 1 的清理，索引键序逐条走、凑够就停）。
  两条以前都靠 `getAll` 把整库读进主线程 —— 而**每张草稿带着编码后的整张图**（规格 §4.3 记的是每张 **2.4MB**）。
- ★ 主键 = `sanitizeName(文件名)`：库的身份就是**文件名**，另铸一套 id 必然与文件那一套漂。
  「当前这张图」的键只有 `currentDraftKey()` 一处：**写进去的与读出来的必须是同一个键**，
  否则症状是「草稿盘里明明有一条，恢复时说什么都没有」（而且不报错）。
- ★★ `onupgradeneeded` **两条路都要把索引建出来**：全新库走 `createObjectStore` 之后建索引；
  **已经在用的库**升上来时 store 已经在了（而且里面还有老记录），那时要经升级事务拿到它、补建索引。
  只建一条路的话，老库升上来之后那两条查询**读不到任何东西**（索引不存在 ⇒ 游标永远 null），
  而症状是「崩溃快照永远不提示 / 清理永远不生效」—— 一个字都不报。
  老记录不需要迁移：索引是 IDB 自己按 keyPath 从现有记录里抽建的（稀疏索引），它们的 `savedAt` 本来就有（三处写入点都写）。
- ★★ `onblocked` 必须接：另一个标签页还按**版本 1** 开着这张库 ⇒ 升级被**阻塞**
  （浏览器等它关闭，期间既不 success 也不 error）。不接这一下的话这条 promise **永远不 settle**，
  而 `bootLoad` 正 `await` 着它 —— 症状是「编辑器白屏 / 永远停在启动」，连面板都不建。
  同一条口径：交回 `null`（草稿盘这一局不可用，状态栏那句话照旧会说），编辑器照常打开。
  `selfTest()` 早就这么接了（它给的是 2 秒兜底）。

### 7.2 读失败与「没有这条记录」必须分得开

- ★★ `idbGetOne` 交回 `{ok, rec}`：`ok:false` = **读不到**（事务打不开 / 请求失败），`rec:null` = 读到了、那条不存在。
  把「读失败」折成「没有这条记录」会让「上次异常退出」那一次抢救**无声消失** ——
  那是这一层最后一次兜底，静默没了就等于作品丢了而没人知道。
- ★ `idbCount` 交回 `null` = 读不到（**不是**「0 条」）；`idbNewestSavedAt` 的 `savedAt: null` = 库里一条都没有。
- ★ 清理的两条失败路径都必须**说出来**（读不到条数 / 读不到记录列表 / 删除事务失败）：
  清理不生效若是静默，用户只会看到草稿盘悄悄涨过 60 条，直到配额炸掉才发现 ——
  而「读失败」与「没到上限」在静默实现里长得**一模一样**。★ 但**不拒绝这次写入**：
  最新的那份劳动正是这一层存在的理由，永远先保住它。
- ★ **草稿盘写入的配额失败要明确告知，不静默吞掉**（规格 §4.6）：作品还在（内存里），
  但用户必须知道「没有第二份」，该 Ctrl+S 了（`saveDraft` 的 `catch` 里那句状态栏文案）。
- ★ 淘汰口径**只有一处**（`evictPlan`：干净的排前面，同样干净时最老的先丢 ——
  脏的那份是用户还没写盘的劳动）。`pruneDrafts` 的 `cap` 取 `entries.length - need` 是同一口径的两种情形：
  走的这一批**要么**恰好含 `need` 条干净的（这时 `evictPlan` 丢掉的就是它们），
  **要么**就是全库（干净的凑不够 ⇒ 一直走完），那时 `entries.length - need` 正好还原成 `MAX_LIB`。

### 7.3 草稿的内容与该记的账

- ★★ **草稿以编码后的字节存**（`rec.bytes`），恢复时走同一条解码路（`Io.decodeMap`）。
- ★★ **一条记录的两半（它是谁 / 它是什么内容）必须在同一个瞬间取**：编码是**异步**的
  （codec 是 Worker；400×300 的图 × 4 层 ≈ **30MB** ⇒ 几百毫秒到几秒），而这段时间里用户完全可能**换一张图**
  （点库里的另一张 —— `openMap` **不问**有没有没写盘的活）。编码之后再读 `currentDraftKey()` / `app.name` 的话，
  写出来的是 `{key:'B', name:'B.cyrm', bytes: <A 的内容>}` —— 下次打开 B、字节比不过 B 的文件 ⇒ 弹一次恢复
  ⇒ 用户一按 Ctrl+S 就把 **A 的地形写进 maps/B.cyrm**。字节相等那道闸让这件事**更糟**，不是更好：
  它把「一次假提示」换成了「静默的内容掉包」。
- ★★ 编码期间可能**已经有了一次 Ctrl+S**：它把这一版（或更新的一版）写进了真文件，并把草稿标干净 ——
  这时再写回一份 `dirty` 的草稿，下次打开就会弹一次**假**的恢复提示（而且**不报错**）。
  故落盘前再看一眼 `rev <= draftSavedRev`。★ 这一条 `force` **也**要过（离开页面前那一刀同样不该
  把「已经进真文件的那一版」写回成脏草稿）。
- ★ `force` = 不因为「这一版写过」就跳过（离开页面前那一刀要的是**此刻**的一份）；不带 force 时那道判据挡的是：
  落了笔 → Ctrl+S（`markDraftSaved` 把 rev 记下）→ 那个还在飞的防抖定时器到点又把同内容写回**脏**草稿。
- ★ `markDraftSaved` 三件事一起做，缺一条都会留下症状：
  ① `draftSavedRev` 推到当前 rev（那个还在飞的防抖定时器到点时会走 `saveDraft` 顶部那道判据，
  从而**不会**把刚标干净的草稿重新写脏）；② `lastAutoSaveAt` 归零（`#st-save` 交回那对文案 ——
  磁盘上那份就是屏幕上这份了，再显示「已自动保存 12:34」是**误导**）；
  ③ 草稿记录本身标 `dirty:false`（启动时的 `offerDraft` **只问脏的**）。
- ★ `openMap` 成功时另两笔账也要归位：`draftSavedRev = draftRev`（否则**上一张图**留下的防抖定时器
  会给这张「刚从文件打开、一笔都没画过」的图写出一条 `dirty:true` 的草稿）与 `lastAutoSaveAt = 0`
  （否则状态栏显示的是**上一张图**的「已自动保存 12:34」）。
- ★★ `saveCurrent` 里那条草稿盘记录挂在**存盘前**那个键上（`draftAt = currentDraftKey()`）：
  「另存为」会换名字，存完再问键就找不到了 —— 于是**旧名字**下那条脏草稿会留着，
  下次打开那张旧图时弹一次**假**的恢复提示。
- ★ ★★ `app.raw` **只能**在解码**成功之后**认领。此前它写在「拿到字节」那一步，于是一次**失败**的打开会把
  **那个失败文件**的字节留在 `app.raw` 里，而 `app.map` / `app.name` / `app.sourceFormat` 仍是**上一张**图的
  （失败路径一个字段都不改，那是刻意的：屏幕上那张图没动过）。两个读者当场就错，而两处**都不报错**：
  ① `saveCurrent` 的原文备份取的就是 `app.raw` ⇒ 于是 `A.v3.bak` 里装的是 **B** 的字节，而紧接着
  `A.cyrm` 被写成 v4：**A 的原文没了，磁盘上那份「退路」还在、看着还挺像回事**；
  ② `offerDraft` 的 `sameBytes(rec.bytes, app.raw)` 拿草稿与**另一个文件**比字节 ⇒ 那道闸等于不存在（假恢复提示）。
  前提是**常态**：磁盘上有一张 v3 图开着，库列表里点到另一个损坏/截断/版本不支持的 `.cyrm`，
  解码失败（编辑器会照实报出来，于是用户接着干活），然后 Ctrl+S。

### 7.4 崩溃槽位与它的已知局限

- ★★ **`crashIsNewer` 只比「草稿盘里任意地图最新一份」的 `savedAt`**（`idbNewestSavedAt` 与
  `get('crash')` 两条**点读**），并把 `declined` 也当判据。⚠ **已知局限**：它不知道崩溃那份草稿是哪张图的 ——
  所以**用别的图刷新的草稿会把崩溃提示压下去**。这是这一层兜底能力的上限，不是实现漏写。
- ★ `declined` 记在记录本身上：不记的话一次偶发页面异常会把**每一次**打开都变成「上次异常退出」
  （直到用户碰巧 Ctrl+S 把草稿写新，才靠「比主草稿旧」压下去）—— 一次性的异常变成一个**永久的开机弹窗**。
  ★ 新的一次崩溃会**重写**这条记录（不带 `declined`）⇒ 照问，所以它挡不住真正的下一次。
  ★ 记录本身**留着** —— 那是没写盘的活，不能因为点了一次「不要」就删掉。
- ★ 它排在 `openFromUrl()` **之后**（`bootLoad` 的顺序）：恢复出来的图要**压住**文件里那份，
  否则用户点了「确定」、屏幕上却是刚从文件打开的那张。
- ★ **崩溃快照比草稿新时才轮到草稿盘**：两个都问一遍会连弹两个「要不要恢复」——
  而崩溃那份本来就是更新的那一份（`if (recovered) return false;`）。
- ★ 恢复/消费的静默清单：`consumeCrashSlot` 失败**不打扰用户**（下次打开还会问，而那时用户点「不要」
  会被 `declined` 记住）—— 有意的静默，退化方向是安全的。

### 7.5 UI 小状态（第 3 层）

- `UI_STATE_KEY = 'cyrm.ui.v1'` **带版本号**：将来换字段可以让老的那份自然失效。
- ★★ **逐字段校验**：一个坏字段不该把整份状态丢掉，也不该把坏值原样喂给渲染器。
  缩放那一处是**钳**不是「回落默认」：默认的 `0` 是「没存过缩放」的哨兵，而 `zoom:-1` 这种
  **存过但坏了**的值必须钳到合法区间 —— 回落成 `0` 的话那个坏值只是被静默换成另一个「没信息」的值，
  用户看到的还是「缩放没恢复」，查不出是坏数据。
- ★★ **`selectedTexture` 不许在 `readUiState` 里用图集派生的上界钳**。理由是一条真实的启动时序：
  `bootLoad` 在**图集存在之前**就读这份状态（`readUiState` 在前、`loadAtlas()` 在后），
  而 `setAtlas` 之前 `atlasCapacity()` 是 **0** ⇒ `clampTexture` 把「cap < 1」当「没有信息」、返回 **1**
  ⇒ 存进去的 7 每次开机变 1，下一次 `persistUi` 再把 1 写回 localStorage ——
  **每一次开机、永远、静默**地毁掉用户选中的纹理。
  ★ 当年那条冒烟看不见它：测试**直接注入 `app.uist`**（绕过了 `readUiState`）—— 一个不可能失败的守卫；
  新守卫走真序列 `readUiState → setAtlas → applyUiState`。
  ★ 钳制**没有**被删掉，只是挪到了它该在的地方：`applyUiState` 跑在 `loadAtlas()` **之后**。
- ★ `playerRef` 的位置**按格坐标**（`cx`/`cy`）存：按屏幕像素存的话，换窗口大小/换缩放之后语义就漂了（审计 A13）。
- ★ `localStore()`：**取 localStorage 这件事本身**在私密模式下就可能抛（不是只有 `setItem` 会），
  故读与写的调用方都不必各自 `try`。`writeUiState` 的写失败是静默的：UI 小状态丢了不影响作品。
- ★★ **压回 DOM 的两处**（凡是恢复出来的状态都必须同时搬回界面，否则「看到的与正在发生的」是两回事）：
  ① `applyUiState` 必须走**本文件**的 `setLayer`（它内部再调 `app.r.setLayer`）—— 直接调 `app.r.setLayer`
  只换渲染层，面板与图层行不会跟着动（`.layer-row.cur` 仍钉在 `editor.html` 写死的那一行，
  `syncPanelForLayer()` 也不会再跑），于是右侧摆着纹理调色板、图层行高亮「场景」，而刷子已经画到背景层上了；
  ② `selectToolButton()` —— 少了它，重载之后工具条高亮钉在写死的画笔上，而实际生效的是存下来的那个工具。
- ★★ 压缩开关**只在存过这个字段时**才动它：老存档（`cyrm.ui.v1`，没有 `compress`）里没有它，
  照 `!!u.compress` 写会把框**取消勾选**（页面上写死的默认是「勾上」），
  于是「没存过」被读成「用户不要压缩」—— 一次**静默的文件格式变更**。
- ★ 节流而不是逐帧：localStorage 是**同步**写，每帧写会掉帧；挂在几个明确的变更点上。

## 8. 启动顺序（`bootLoad` 的四段理由）

1. `installCrashFence()` **第一件事就装**：后面任何一步抛出都要能被它接住。
2. 草稿盘要在**打开地图之前**就绪（`offerDraft` 要用它；它打不开只影响「自动存」）。
3. 崩溃槽位 / 草稿盘的检查排在 `openFromUrl()` **之后** —— 恢复出来的那份必须**压住**刚从文件打开的那份：
   反过来的话用户点了「确定」，屏幕上却是文件里那张，而且**一个字都不报**。
4. `applyUiState()` 必须排在 `setMap` **之后**（`setMap` 自己会 `fit`，先设会被它覆盖）。

★ **面板必须建在打开之前**。早先它挂在「打开之后」，那条链是 `loadAtlas → openFromUrl → buildPanels`，
而 `.catch` 只有一个 ⇒ `openFromUrl()` 一旦拒绝（`?p=` 陈旧或写错 ⇒ `openMap` 抛 HTTP 404；`.cyrm` 解不开；
`structure.png` 拿不到），整条链**短路到 catch**，`buildPanels()` 一行都没跑：
工具条、图层行、调色板、出生点四个按钮**一个监听都没装上**，从此**没有重建路径**，
屏幕上只有一行「启动失败:…」。用户会以为编辑器坏了，而不是「这张图打不开」。
★ `buildPanels` 只读 `app.tileDefs`（`boot` 里就位）与 `app.r`（已 mount），对 `app.map` 只有**一处**引用
（清空出生点那个处理器）且不读任何地图尺寸 —— 所以「等图打开」没有任何理由，而它自己带 null 守卫，没图也能建。

★ **闸 3 没有降级路径** ⇒ 缺 Worker 时的**唯一**正确行为是把话说清楚（`#boot-error`），而不是静默退回主线程。

## 9. 异步入口与错误通道（一条纪律反复出现）

- ★ `guard` 是页面上**唯一的**报错收口：它既接同步 `try/catch`，也接**视图入口返回的分帧 promise 的拒绝**
  （`resize` / `fit` / `setView` / `setZoomAt` / `panBy` / `setMap` / `invalidateAll` —— 抛在任务回调里 =
  一次**拒绝**，同步 `try/catch` 接不住，画布默默停在上一帧，用户看到的就是「按了没反应」）。
  `Render.mount` 的 `onError` 指到同一个 sink。
- ★ 默认 sink = 状态栏；**有自定义 sink 时不再 `console.error`** —— node 冒烟会故意触发失败，
  否则 stderr 里恒有字节，「stderr 有字节 = 有东西红了」这个信号就废了。
  ★ **报错通道自己坏了也不许把异常扔回调用方**（`reportError` 的 `catch` 里只 `console.error`）——
  扔回去就成了第二处「看得见才怪」。
  ★ 自检探完 sink 必须**还原**（不是置 `null`）：自检交回的那条 promise 之后还会走 `guard` 的失败分支，
  那时 sink 若已被置 `null`，`reportError` 就会走默认那条（`status` **加** `console.error`）—— 冲掉那个信号
  等于把一条本来会红的断言洗白。
- ★★ **`runJob` 的 promise 必须交给 `guard`**（油漆桶 / 渐变，以及 `keydown` 里那些 `pend`）：
  丢掉它 = 拒绝逃到**全局围栏**，而围栏会 `snapshot()` ⇒ 一次普通的落笔/打开失败会把**当前这张图**
  写进崩溃槽位，下次开机弹**假的**「上次异常退出」。`guard` 是**终点**（它自己吞掉结果、只往状态栏写一行），
  故那些地方不是「第二处接住」，而是**唯一**该接住的地方。
  `openMap` 的失败是**常态**（点到陈旧/写错的名字 ⇒ 404），所以 `#lib-list` 的委托处理器同样必须包 `guard`。
- ★ `Promise.resolve(guard(...))` 不是装饰：`guard` 在**同步**抛时返回 `null`，直接 `.then` 会炸成 `TypeError`。
- ★ `guard(` 与那次调用**必须同一行**：`editor_smoke` 相位 ⑪ 的扫描口径就是按行看的 ——
  拆成两行的话它就是「没被收口的视图入口」。
- ★ `onWin` 的理由：node 冒烟里 `window` 是 `globalThis`，而 `globalThis` **没有** `addEventListener`
  （Node 24 实测），裸 `window.addEventListener(...)` 会在 `bootLoad()` 的第一行就抛 ——
  那会让「打开失败也要有面板」那条路一起红，而根因与面板毫无关系。

## 10. 交互与工具内核：搬走的实测与推导

- ★ **空格是修饰键，不进 `commandFor`**：那张表返回「按下即执行的一条命令」，而空格本身不执行任何东西。
  它是**按下/抬起**的状态：`keydown` 置位、`keyup` 与 `blur` 清位。
  ★ `blur` 那条不是装饰：按住空格去点别的窗口（或 Alt+Tab）时 `keyup` 根本到不了这个页面。
- ★★ `keyup` 的清位必须**无条件**做，只有 `preventDefault` 才走「输入控件里不拦」那道早退。
  把早退排在清位**之前**时，这条**极普通**的手顺能把修饰键**永久卡住**：按住空格（焦点在 body，
  `spaceDown = true`）→ 还按着的同时点进一个输入框 → 松手（`keyup` 的 target 是那个输入框 ⇒ 早退
  ⇒ `spaceDown` 仍是 `true`）→ 此后**每一次左键拖拽都变成平移**，而用户以为自己松开空格很久了。
- ★ 「空格」被 `preventDefault` 拦的是什么：空格是浏览器的**向下翻页**键，而 `#right` / `#lib-list` 都是
  `overflow:auto` ⇒ 不拦的话，按下空格准备拖拽时右边栏先滚一屏；`keyup` 那一半同样要拦 ——
  浏览器还会把空格当「按下当前聚焦的按钮」（点过「应用尺寸」之后那颗按钮仍带着焦点）。
- ★ ★★ **焦点在输入控件里时一个键都不许拦**：命令表里有 `Backspace/Delete → clear-selection`、
  `0-9 → 切层`、`b/e/g/l/m/i → 换工具`、方向键 → 平移。焦点在输入框里时这些键是**打字**：
  按 Backspace 会**先被 `preventDefault`**（数字删不掉）再**真去 erase 掉整个选区** ——
  数据被改，而用户以为自己只是在删一个字符。
  判据取 `tagName` 与 `isContentEditable`，**不取** `ev.target === document.activeElement`
  （合成事件 / 焦点在 body 时 target 就是 body，那样的判据会把「按在画布上」也判成输入，热键整个失灵）。
- ★ Esc **可能在拖动途中**按下去（左键还按着、`selDrag` 还在飞）而照样合法：要一起做三件事 ——
  ① 清**在飞的拖动记录**（它是「这一支拖动还算不算数」的**唯一**依据：松手时 `pointerup` 的拖动分支
  因此**根本不进**）；② `setSelDrag(null)` 让渲染侧当场把烤过的两块按内容归位；③ 清选区。
  ★ ②③ 谁先谁后都一样；① 必须排在最前，因为紧随其后的 `pointermove` / `pointerup` 判的正是它。
  ★ 拖动分支还要**先取局部变量再判**：取消之后 `sd` 是 `null`，少了这层判会去读它的 `dx`
  （在 `pointerup` 里抛 `TypeError` = 落笔路径整个断掉）。
- ★★ **存回去的选区必须折算**（`Render.wrapIdx`）：拖动跨过接缝时 `cur.x + sd.dx` 会落到
  `[0, subCols)` 之外，而 `regionCells` 是「先折算每一格、再 `inRect(clip, wx, wy)`」
  ⇒ `clip.x < 0` 时**一格都进不来**：框内所有画笔/矩形/直线/油漆桶都产出空集合，
  `paintCells` 回 `null`、`pushAndShow` 回 `false` —— 而且**一条状态栏消息都没有**。
- ★ **单击也要落一次笔**：按下与松开之间没有 `pointermove` 时，画笔/橡皮的落笔只在 `pointermove`
  那条路上发生 ⇒ 一次单击什么都不画。判据取 `painted` 而不是「`last` 是否等于 `from`」：
  `pointermove` 在**同一格**内也会落笔（`last` 仍等于 `from`），那时再落一次就会往历史里塞一条空差量。
- ★★ **两个颜色槽是渐变的全部**（规格 §4.4）：`rgba` = 起点、`rgba2` = 终点。
  只接一个的话「渐变」永远退化成一个纯色（两端同色），而且看不出来。背景层是不透明的真彩
  （`#RRGGBB → 0xRRGGBBFF`；alpha 由辅码那一路管不了它）。
- ★★ **渐变仅背景层**（规格 §4.4）：工具按钮只是压暗（视觉提示），真正的闸在 `pointerdown` ——
  少了它，在纹理层拖渐变会**悄悄改掉背景层**（屏幕上看不出，因为背景在最底下）。
- ★★ **选区成员的判据本体只有一处**（`Render.inSel`）：拖动预览的源格查询、`regionCells` 的 `clip`、
  `moveRegion` 的 `from` 集合、以及 `HitOf` 之后「按下算不算在选区里」转调的是同一个函数，
  所以「预览 / 落笔 / 框内落笔」三处**不可能**再分岔。此前它们是**三种**口径，各自在接缝那一侧
  给出不同答案 —— 最刺眼的一种是「框里画，一半画得进去、一半什么都没发生」。
- ★★ **`Render.inSel` 的环面折算**修掉的是「接缝另一侧的那半截静默漏掉」：`regionCells` 此前是
  「先把每一格折算回主网格、再用**非折算**的 `inRect` 比大小」—— 于是一个**自己跨着接缝**的选区
  （如 96 宽的图上 `{x:93,w:6}` 盖住 93..95 与 0..2）只在 93..95 上落笔，0..2 那半边**画不进去、也不报错**。
- ★★ **`Core.lineCells` 的坐标必须是整数**：非整数或 NaN 会让它的 `for(;;)` **死循环、挂住整个标签页**。
  **所有**调用点都在 `strokePoints` / `constrainLine` / `constrainSquare` 里 `floor`；
  `editor_smoke` 相位 ⑪ 会扫源码钉住「没有第二个没 floor 的调用点」。
  ★ 因此 `constrainLine` 上面那行注释**刻意不写成**带括号的调用形式：相位 ⑪ 按「同一行出现调用就必须出现
  `Math.floor`」这条**逐行**规则扫源码，注释里那半截会被它当成一个调用点。
- ★★ **"只改辅码"这一支不能少**：空气仍是空气（不能凭空长出纹理），有纹理的保留**原纹理**、只换辅码。
  少了它，整片墙「变暗」的操作会把墙**换成画笔当前选的那个纹理**。
- ★★ **`clampTexture` 的上界派生自图集**（列 × 行，换图集就变）：容量 < 1（图集还没加载 / 一块都放不下 /
  畸形图集算出的负数）一律当**「没有信息」** ⇒ 只给 1，**不是**放宽到描述符位宽那个上界 ——
  tint 的越界判据是「图集里有没有这一块」，放宽等于把越界号直接放进 `tileFor`（它抛，而且每帧同一处抛一屏）。
- ★ 纹理 **22（水面）** 在编辑器里可选、在**游戏里是自动派生**的（审计 A7）：做成可点选调色板只会产出
  「编辑器里画的、游戏里看到的」不一样的图（而且不报错），故排除，只在提示里点名（`#palette-hint`）。
  ★ 这个提示行是 `#palette` 的**派生行**，背景层上必须跟着一起藏。
- ★★ **油漆桶 / 渐变不预展开整张图**：旧版在作业开始时对全图调一次 `regionCells`
  （500×300 = 15 万条，外加一个同样大的 `Set`）—— 那一下是**同步**跑完的，作业还没开始分帧就先卡一帧。
  改成逐格推进：顺序仍是行主序（与「全图 `regionCells`」逐条相同 ⇒ `result()` 的次序不变），
  但第一块只算第一块。★ 唯一的语义差异：`scanned` 现在数的是**扫过的格**（含被选区挡掉的），
  与油漆桶那边的口径一致，而不再是「被收下的格」。
- ★★ **镜像的非法 `axis` 必须当场说人话**（抛一条带原因的中文错），不能靠「两个坐标算出来一样」退化成恒等、
  再静默回 `null` —— 那与「镜像了一圈、内容恰好没变」在返回值上**完全同形**，调用方分不出
  「轴写错了」和「这次镜像没改动任何格」。处理方式与 `createGradientJob` 对非法图层同款
  （调用方的**编程错误** ⇒ 抛），而不是回一个 `{ok:false, why}`：后者会把本函数文档化的返回类型
  `diff|null` 破成三种形状。抛出的错在上层被 `guard(...)` 接住 → 落进状态栏，用户看得见、程序不崩。
  ★ `mirrorSelection` 里 `if (out.threw) return;` 是**承重的**：少了它，紧接着的「没改动」文案会把刚写上去的
  错**覆盖掉**。★ 抛出的错**绝不许**进历史（历史只收 `diff|null`）。
- ★★ **选区移动没有「裁剪」这一步**：目标格 = 源格 + 偏移（两边都环面折算），源区里**没被目标覆盖**的格被清空。
  于是「拖到图外」在环面上就是恒等位移，结果是「什么都没变」而不是「内容被裁掉」。旧实现的病灶是
  `maxDX = 宽 − 选区宽` **漏了 − 选区.x**，拖动越界后 `moveRegion`（先清源区再贴目标区）把被裁掉的列静默删掉。
- ★ **跨图层粘贴只允许「纹理 ↔ 纹理」**（决定 ④）：两种数据类型不互相猜，拒绝时**给出原因**
  （状态栏要显示），不静默。
- ★★ **整图级差量必须原地装字段**（`adoptMapInto`）而不是 `app.map = out.map`：
  `wholeDiff(map, …)` 的 `seal()` 快照的是**它建时抓的那个对象**（闭包参数，不是「当时的 `app.map`」）。
  中间换了引用 ⇒ `after` 拿到的仍是**改前**那份（`before === after`）：撤销/重做双双无效，而**一个字都不报**。
  ★ `applyEntry` 的 `whole` 分支相反，必须**防御性拷贝** `map.layers`：直接 alias 快照数组的话，
  撤销之后地图与 `entry.before` **共用同一份 TypedArray** —— 用户再落一笔就写进了历史条目里，
  下一次撤销恢复的是被污染的 `before`（「撤销没撤干净」且一个字都不报；字节数也不变，字节闸发现不了）。
- ★★ **尺寸/换图这类操作没法差量**（table 级），故留一条整图快照的通道（`kind:'whole'`）并按**字节**记账 ——
  字节预算才是真闸（`MAX_UNDO_BYTES = 64MB`），步数只是廉价上界（`MAX_UNDO = 200`）。
  差量而不是整图快照的理由：一张 125×75 的图是 **2.4MB**，200 份就是 480MB。
- ★ **撤销栈至少留一条**：一条都留不住时「撤销」这个功能就整体失效了（比多占几 MB 更糟）。
- ★★ **改尺寸那条路的选区清理**：`invalidateAll` **不清选区**（只有 `setMap` 清）—— 留下的那个框于是
  ① 画在**图外**（render 按原坐标画框，而框已经没有对应的格了，它看上去贴在接缝那一侧）；
  ② 更要命的是**凡是消费选区**的工具都走 `idxOf` 的**取模**折算，静默把落在图外的格**折回图里**落笔：
  镜像线不在框画的那条线上、接缝附近凭空空出一片改动，**一个字都不报**。
  ★ **清掉**是**看得见**的（框当场消失）；**钳到边界**会让框画在一个它从来不占的位置上（用户以为镜像还是对称的）。
  ★ 撤销/重做**都要**判一遍（撤销把图放大 ⇒ 框还在；重做又缩小 ⇒ 那时才轮到清），
  所以只能**每次**整片重来时判一遍。
- ★★ **改尺寸的 before 快照必须在改动之前取**，并且改完还要把**不在画布上**的两处尺寸显示一起翻新：
  状态栏的 `#st-size` 与尺寸面板的两个框（`invalidateAll` 只管渲染，`statusLine` 只管工具/纹理/选区/撤销深度）。
  少了这一句，撤销一次改尺寸之后画布已经回到 4×3 而框里仍写着 400×75 —— 再按一次「应用尺寸」就把图又改回 400×75。
- ★★ **越界项要报出来**（审计 A10 要的是「提示并清理」而不是「静默清理」）：`resizeMap` **只丢不钳**
  （钳一个出生点到边界上是替用户做决定），静默清理等于「导出去游戏读到网格外坐标」。
  ★ 全部对齐同一套坐标口径：`spawnAt` 的「视图中心那一格」也必须 `Render.wrapIdx` 折算 ——
  `panBy` **不钳**视图 ⇒ 环面模式下把视图拖到图外时算出来是越界的，磁盘上就多出一条 `x/y` 出圈的出生点
  （只有 `Core.validateMap` 看得见它，而游戏侧读到的位置是另一回事）。
- ★★ **P1/P2 是位置语义、不是「第几条记录」**：游戏侧 `map_format.gd` 按顺序读 `player` / `player2`。
  故放 P1 = **写第 0 条**，放 P2 = **写第 1 条**；缺号一律**显式拒绝**并说明理由 —— 绝不 `push` 出一条位置不对的
  记录：在零出生点的图上放 P2 而 `push` 出去，磁盘上那条会被游戏读成 **P1**（状态栏刚说「P2 放到 …」，数据却是 P1），
  而且**一个字都不报**。同理，「放 P1」若也走 `push`，图上只有 P1 时再点一次就会长出第 2 条 ——
  那条位置正好是 **P2**，于是 P2 被**悄悄换掉**。
- ★★ **库列表里混进备份的后果**：`openFromUrl` 的兜底是「打开列表**第一行**」—— 列表里混进 `.v3.bak` 之后，
  开机就可能直接打开一份**退路**（用户以为自己打开的是地图）；打开一份备份再 Ctrl+S 会把 v4 写进那份退路里。
- ★ **面板监听只挂一份**（审计 A16）：旧实现同时挂了 **22 个独立监听**与一个容器委托，点一次跑两遍。
  `#lib-list` 那一处用**委托**一次，不给每行挂监听。
- ★ **背景层时面板要换一套控件**（规格 §4.5）：纹理调色板 + 辅码 ↔ 颜色选择器；工具条上「渐变」压暗到 0.45。
  ★ 藏的是**整行**而不是控件的直接父节点：四个档位 `select` 的父节点就是 `.desc-row`，
  而「只改辅码」那个 input 外面还包着一层 `<label>` ⇒ 直接写 `parentNode` 的话那一行仍占着位置。
  ★ 输入框里的回车也当「应用尺寸」（两个数字框 + 一颗按钮的版式里，按回车什么都不发生最容易被当成「坏了」）。
- ★ **没打开地图时的提示要一致**：同一个面板里四个出生点按钮、改尺寸面板都必须说「先打开一张地图」，
  而不是把 `clearSpawns(null)` / `resizeMap(null, …)` 的 `TypeError` 抛进 click 处理器
  （那会经 `window.onerror` 变成「页面异常:…」，同一个面板里两种说法）。
- ★ **导出的敌人类型清单来自页面注册表**（`globalThis.ENEMY_REGISTRY`），不写死；导出校验**只警告不阻止导出**
  （规格 §4.7）。★ 已知边界：第 3 个及以后的出生点游戏侧读不到（`map_format.gd` 只认 `player` / `player2`）。
- ★ **`editor_server.js` 不做删除动作**是**故意的**：删地图请直接在磁盘上删 `maps/` 下的文件。
- ★ **刷新库列表失败时的措辞**：`saveCurrent` 把库列表刷新排在**说结果之前** —— 那条 GET 失败时 `guard` 会往
  **同一条状态栏**写一行错误，先写「已保存 …」再被它盖掉的话，用户看到的是「刷新失败了」，而保存其实**成功了**。
  ★ 代价照实说：刷新失败那行于是只在控制台（`reportError` 的 `console.error`）里留痕、状态栏上是一句「已保存」。
  刷新只是「列表里的字节数/时间」，不影响落盘。
- ★ **`refreshStatus` 是几条换图路的公共收口**（打开 / 新建 / 复制 / 改尺寸 / 草稿恢复），
  尺寸面板那两个框的同步（`sizeInputsSync`）挂在它里面 —— 漏一处就是「框里写着上一张图的尺寸，
  一按应用尺寸把当前这张改了」。

## 11. 自检（浏览器侧唯一能跑的判据）

- 判据是文本 `SELFTEST OK`；失败逐条列出。人在浏览器里点「自检」按钮，把那行贴回报告。
- ★★ 自检是页面上的**异步入口**之一，必须与别的入口同一条纪律：经 `guard` 收口。它**会拒绝** ——
  `selfTest` 消费 `Io.ping()` / `Io.encodeMap` / `Io.decodeMap`，而 `io.js` 那个 30s 超时是新的拒绝源
  （codec 死了 / 被 `terminate` 掉 / 压缩路径抛），此外自检自己也会把 `indexedDB`、`localStorage`
  当成「可能失败」来探（那是它的本职）。丢掉那条 promise 就是一次**未处理的拒绝**：闸 4 的围栏会写一份
  崩溃快照 ⇒ 下次开机弹一个假的「上次异常退出」，而屏幕上那张图**一次都没崩过**。
- ★ **探的是真行为**：`probeIndexedDb` 真**开一次库**（只看 `typeof` 是查不出「被策略拦 / 隐私模式」的），
  且**超时也必须收口** —— `open` 被拦时**可能一个回调都不来**，那时自检那一行永远不出现、看着像按钮坏了，
  所以 2 秒没有回调就判失败并把原因写出来。顺手删掉自检建的库（不在用户机器上留垃圾）。
- ★ 「IndexedDB 可打开」与「草稿盘已打开（`app.db`）」**不是**同一件事：前者开的是自检自己那个临时库
  （证明「能开」），后者说的是**草稿盘这个库**有没有真开出来 —— 它打不开时编辑器照常能用，
  只是自动存那一层静默缺席，所以必须有一条能一行看到的读数。
- ★ 抽成具名函数（`runSelfTest`）是为了让它**可被 node 驱动**：判「有没有护栏」必须是**行为**断言
  （装一遍真的围栏、让一次真失败跑过去、看崩溃槽位有没有多一条），而不是源码里 `grep` 一个 `guard(`。
