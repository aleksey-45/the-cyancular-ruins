# 界面视觉检查方法

配合 [界面视觉验收](ui-visual-qa.md) 使用。用截图发现错位、遮挡和层级问题，再用场景树或源码确认字号、容器和锚点。

## 判断文字层级

按页面标题、主要操作、表单标签、正文、次级说明、状态与脚注区分文字用途。在至少两个界面中比较同类信息，再结合可用宽度和对比度选择字号。

| 字号 | 占 1440 像素视口高度 | 现有用途 |
| ---: | ---: | --- |
| 16 | 1.1% | 版本号、脚注与 HUD 小标签 |
| 24 | 1.7% | 卡片补充信息及 Beta 概述 |
| 28 | 1.9% | 次级正文、状态和提示 |
| 32 | 2.2% | 表单标签、按钮、列表正文 |
| 40 | 2.8% | 房间卡片的模式名称等主要信息 |
| 48 | 3.3% | 页面标题 |
| 128 / 160 | 8.9% / 11.1% | 主菜单标题 |

相邻层级先试 1.33 至 1.5 倍字号，再看实际画面。像素字体在 16、32、48 等档位通常更锐利。使用 24、28 或 40 时，以 1:1 截图确认中文笔画。卡片空间不足时优先保留完整信息，例如地图卡片和 Beta 概述可用 24 像素。

## 判断布局宽度

先看首屏内容区轮廓，再看标题、主要操作和状态的阅读顺序。在 1920 像素逻辑宽度下，1472 像素大厅内容区约占 77%。较窄的 1280 像素限宽会放大两侧空白，接近满宽时工具栏和筛选容易拉得太长。缩小窗口后再核对最小间距、按钮宽度和滚动容器。

## 复查步骤

1. 先看整体缩略图，检查内容是否明显偏向一侧，以及是否有大片空白或视觉层级混乱。
2. 看原尺寸截图，核对字形细节、对比度、裁切、重叠和光标反馈。
3. 在场景树或源码核对控件的容器、锚点、最小尺寸和字号，横向比较设置、Beta、信息页、大厅或 HUD 中的同类控件。
4. 调整对应层级或容器后，保持分辨率、页面状态和测试数据一致再截图。记录实际改动及验收结果。
