# 统一对局模拟、会话与表现重构计划

2026-11-25 · 实施记录 · 重构前源码基线 90cb4475

## 当前入口

| 层 | 接口 |
| --- | --- |
| 模拟 | MatchWorld.create(spec) 返回世界和初始 frame。advance(inputs, commands) 与 restore(checkpoint) 返回借用帧，capture() 按需采集完整状态。 |
| 会话 | MatchSession.open_local(spec, observing_role) 或 open_remote(baseline, ping_ms) 建立会话。fixed_step(seat_intents, ping_ms) 推进并返回展示端点，close() 释放世界。 |
| 表现 | MatchSampler.accept(update) 接纳端点，sample(render_time, alpha) 选择同刻状态，MatchPresenter.compose(sample, render_time, local_view) 返回 MatchFrame。MatchView.present(delta, frame) 提交画面和一次性提示。 |

协议 37 的 STATE 以确认过的基准编码。恢复检查点采用已装配的规则和可用地形版本，技能历史与展示采样分别保留有限窗口。时间技能记录按作用域保存实体数据，共享相同的记录，网络按字段和采样区间编码。PredictionRollback、CombatSnapshot、RewindHistory 等旧入口已退役。

本地校正每次采用最新可用权威锚点并有界重放，位置残差按 50 毫秒线性衰减。真实复活通过角色的生命实例区分。远端使用同一个延迟刻采样，倒地与本地血量采用权威状态。已提交帧足以派生的短提示在画面上产生一次。

以下保留原设计的推导、三种回溯的范围和验收条件。当前契约见 [模拟与战斗](../simulation.md) 和 [联机系统](../netplay.md)。

## 目标

单人、多人和编辑器试玩使用同一个权威主机、同一种世界状态和同一套画面生成接口。建局时通过 `WorldSpec` 装配对局规则，接入时选择同进程调用或网络传输。客户端的预测实例也使用同一个 `World` 实现和同一份规则配置。

重构前，单人与多人已共用 `CombatSimulator`，时间技能、复活和回合仍由不同调用方推进。联机预测每步重新采集角色、弹体与任务等战斗状态，放入固定大小的检查点环。收到 `STATE` 后还要拿旧预测、射击和弹体终止事件补齐弹体及待结算爆炸。地形日志和网络编码已经按差分工作。重构需分别处理检查点完整性、每步的采集成本和传输成本。 [单人推进](../../scenes/solo_level.gd) · [权威推进](../../core/sim/match_world.gd) · [预测检查点](../../core/net/match_session.gd) · [地形差分](../terrain.md#回溯与网络同步)

### 设计依据

- 以稳定的领域操作定义边界。世界提供创建、推进、保存与恢复，同一个操作可用于本机主机、服务端、客户端预测和测试。 [如何设计出一些优雅的 API 接口呢](https://www.zhihu.com/question/31363461/answer/1921481672)
- 将通用机制做好，再用出生、计分、时间规则组装玩法。时间模块调用同一套历史读取和恢复机制，编辑器与联机接入直接复用成品世界。 [开发一个业务逻辑复杂的系统，应该怎么样设计才能使项目的扩展性更好](https://www.zhihu.com/question/26731781/answer/1927755258186172253)
- 归一化的判断标准是调用方能否使用同一契约。本地与远程接入都输出可采样的帧，预测和权威调用同一个模拟接口，差异留在输入来源和表现采样策略。 [面向对象编程的弊端是什么](https://www.zhihu.com/question/20275578/answer/26577791)
- 用具体场景检验接口的完整性。已排帧的意图可重复推进，从一份检查点可继续结算，历史资源随窗口和检查点寿命回收。 [一直不理解什么样的代码是利于维护和更新的](https://www.zhihu.com/question/1982434503076094325/answer/2091114684682444900)

## 模块关系与数据归属

```mermaid

    I["本机、网络或测试输入"] --> S["会话排帧"]
    S --> H["权威主机"]
    H --> W["World.advance"]
    W --> F["已提交帧 / 完整检查点"]
    F --> V["帧源"]
    F --> R["远程会话恢复与重放"]
    R --> V
    V --> A["状态采样器"]
    A --> P["Presenter"]
    P --> M["MatchView / 声音"]
```

| 层 | 持有的数据与决策 |
| --- | --- |
| 模拟 | 实体、武器、地形版本、时钟、战绩、随机状态、计时任务、玩法历史和恢复规则 |
| 会话 | 连接与就绪、输入序号和目标帧、确认与重发、可用的权威锚点、预测实例、步进调度 |

本机权威主机可以和视图同进程，远程房主可以继续使用独立的无头进程。编辑器以当前地图和选定出生点创建临时会话，试玩的地形、实体和历史归该会话，预览光照时间作为视图参数。关闭会话即释放这些资源。单人暂停由外层暂停本机固定步，在线暂停菜单由本地界面接管操作，主机照常推进。 [现有试玩入口](../../ui/map_editor/map_editor.gd) · [当前房间与主机流程](../netplay.md#房间与对局)

## 模拟层

### 公开接口

```text
World.create(spec: WorldSpec)                     -> World, FrameView
world.advance(inputs: StepInputs)                 -> FrameView
world.capture()                                   -> Checkpoint
world.restore(checkpoint: Checkpoint)             -> FrameView
```

| 操作 | 契约 |
| --- | --- |
| `create` | 校验地图、规则配置和初始参与者，组装一份独立世界，返回第 0 帧。碰撞空间和可变规则状态随世界创建和释放。 |
| `advance` | 以固定步长推进一次。输入包含玩家操作意图，以及经过会话授权、确实改变世界的开局、重开或席位变更等意图。规则在本步执行状态写入。 |
| `capture` | 按需保存最近提交的帧末。检查点的内容在后续推进中保持稳定，可供相同配置的新实例恢复。 |
| `restore` | 安装一份完整检查点并返回帧末视图。恢复前验证配置、引用及状态结构，失败时保留原世界。成功后下一次推进从锚点的下一帧开始。 |

`FrameView` 是一次已提交状态的借用视图，可读至下一次 `advance` 或 `restore`。本机直接投影显示字段，保留相邻的精简帧供插值。完整检查点用于发送和实际恢复，按需采集。调用方通过操作返回的视图取帧，规则在内部使用限定用途的历史查询。这样启动、推进、显示和恢复都能由四个入口完成。

`Checkpoint` 以提交帧号和规则配置标识定位。它保存所有影响未来推进的动态数据，包括角色运动、姿态与计时器、生命与氧气、武器和分配器、弹体行程与引信、直击标记、已生成光束、待结算爆炸、地面武器、敌人、复活安排、回合与统计、颗粒和延迟奖励、随机状态、启用规则需要的历史及游标。地形字段只保存版本引用。可由完整状态重建的物理索引、RID 等属于实现缓存。明确保存仍被任务引用的实体身份与归因。 [当前角色记录](../../scenes/player/player.gd) · [当前服务器状态](../../core/sim/match_world.gd)

### 每步的执行顺序

1. 取本步席位与控制意图，应用当前对局阶段的输入限制。按稳定实体 ID 确定角色和结算顺序。
2. 时间规则读取同一份步前状态，确定回溯恢复范围、消耗、游标及各对象的推进倍率。批量应用恢复并同步碰撞，再进入运动阶段。
3. 更新地面武器，再按角色 ID 处理拾取、丢弃与角色运动。处理角色战斗请求和射击，依次推进敌人与在途弹丸，当步生成的弹丸参加当步运动。即时伤害在相应的命中阶段生效。
4. 按到期时间和稳定 ID 结算爆炸，收集本步的伤害与地形结果。直接调用归因与奖励规则，随后结算倒地、掉落、击杀奖励、计分、复活和回合转移。提交时完成地形版本和碰撞更新。
5. 记录启用规则需要的历史数据，提交帧末，发布可以观察的结果。Signal 可用于发布已提交结果和界面通知。

公式可写为 `S[t+1] = step(spec, S[t], inputs[t+1])`。同一份配置在权威、单人和预测实例中运行相同的伤害、地形、拾取和复活规则。可重现的推进依赖稳定顺序和可恢复的随机状态。把出生、选武器和掉落所需的随机选择绑定到世界实例，用可恢复的实体 ID 排序和去重。 [现有步进顺序](../simulation.md#每帧更新) · [当前归因及地形奖励回调](../../core/sim/match_world.gd)

### 规则装配

`WorldSpec` 在创建时固定，包含地图定义、初始参与者及队伍、种子、武器与碰撞配置、对局流程和时间规则。把这些差异绑定到实际调用点，推进热路径只调用选中的实现。

| 配方 | 对局流程 | 时间规则 |
| --- | --- | --- |
| 单人 | 地图生成敌人，单人出生与重开 | 世界回溯、单人加速与颗粒 |
| 1v1、团队 | 共用系列赛流程，配置出生、换边、复活、计分和团队规则 | 固定步长 |
| 大乱斗 | 合并出生点池，限时计分与复活 | 固定步长 |
| Beta 对战 | 沿用所选对战流程及地图 | 个人回溯、加速、颗粒账户和奖励 |
| 编辑器试玩 | 同一单人配方，传入编辑中的地图和起点 | 沿用单人时间规则 |

同一场大乱斗切换 Beta 时，换入时间规则和相应的颗粒结算即可。关卡、伤害、胜负和会话接口均由各自的契约提供。技能优先级也是规则的一部分，同时按住两键时，单人优先加速，Beta 优先回溯。 [单人规则](../player.md#单人时间技能) · [对战与 Beta 规则](../modes.md)

### 三种回溯的组合

```text
time_step = time_rules.resolve(inputs, time_context)
apply_time_step(time_step)
step_combat(inputs, time_step.rates)
```

`World.create()` 绑定 `spec.time`，为每个世界创建独立的规则运行状态。时间模块通过内部只读访问取得当步资格、颗粒及相关实体历史。它给出历史点、要恢复的对象和状态、推进倍率及账户和游标变更。模拟使用领域操作执行相应的实体恢复与地形撤销，扣费和恢复同一步提交。松键后从所选历史点继续记录。同帧有多名个人回溯使用者时，先从同一份步前状态选出范围，再按固定顺序应用。若玩法允许局中切换技能，选中的技能 ID 随角色状态保存，规则定义仍由同一份 `spec` 提供。

| 场景 | 组合 | 时间与状态范围 |
| --- | --- | --- |
| 网络校正 | 选定权威帧 `t`，`restore(STATE[t])`，从 `t+1` 用已排帧的操作重放到预测终点。 | 精确恢复该锚点的世界、随机状态、规则运行状态及地形版本。重放遇到技能意图时调用绑定的时间规则。 |
| Beta 个人回溯 | 按使用者和游标取历史数据，按当前归属和在场集合恢复。 | 恢复角色及氧气、仍持有武器的历史状态、仍在场的自有弹丸的运动与引信。武器归属与弹丸直击结果取当前值。颗粒在当前账户扣除，其他对象按各自步长运行。 |
| 单人世界回溯 | 选择历史世界时刻，按实体查询受范围影响的数据，恢复实体存续、相关计时和历史地形版本，再从该时刻续接。 | 恢复普通敌人、角色和适用的弹体状态，以及世界时钟、光束和待结算爆炸。精英继续行动，地面武器在原位暂停推进。角色氧气、武器归属和射击序号沿用当前值，相关去重与账户按原规则结算。 |

主机的提交帧号持续递增，用于传输、输入调度和呈现排序。世界时间与个人历史游标可以倒退。爆炸、光束等计时器使用其所属时钟保存的截止时间。世界回溯恢复了一个待结算爆炸时，它在恢复后的世界时间到期。区分这两个时钟也让重开、换回合与迟到快照有明确的顺序。

玩法历史提供按实体和历史位置读取字段、存续与世界计时的能力。沿用现有 20 Hz 采样节奏和窗口，在内部记录变化、构建实体索引与必要的起点值。历史分支可共享只读前缀，选择性恢复后只裁剪受影响的分支，仍被检查点引用的数据保留至释放。时间策略和游标归规则运行状态，`RewindHistory` 原先的整帧存档和作用域恢复由这一组合替代。 [单人时间规则](../player.md#单人时间技能) · [Beta 时间规则](../modes.md#beta-时间技能)

### 地形版本

检查点的地形字段只保存线性撤销日志的位置。每次修改提交时记录变化子格的旧耐久。模拟读取当前版本、查询和破坏地形，并可撤销到仍保留的历史点。地形按改变的子格更新碰撞，对实心占用没有变化的分块重用形状。

网络补丁沿可靠有序通道发布，携带结果版本和子格最终耐久。接收方先把补丁入队，采用检查点时撤销旧的预测尾巴，再按顺序应用所需补丁。预测从新锚点执行统一的地形破坏规则。

服务器发布后释放已经消费的日志。单人历史窗口推进时释放最早样本之前的记录。Beta 个人回溯只需要当前锚点的地形。联机接入暂存等待地形补丁的快照，继续使用最近可用锚点。 [当前地形记录与恢复](../../core/sim/terrain.gd) · [可靠通道](../netplay.md#消息与快照)

## 会话层

### 接入接口

```text
open_local(spec, seats)                           -> MatchSession, FrameUpdates
open_remote(connection, baseline)                 -> MatchSession, FrameUpdates
session.fixed_step(now, seat_intents)             -> FrameUpdates
session.close()
```

两个打开入口分别建立同进程主机或接入已握手的主机，完成后提供已接纳的初始帧。`fixed_step` 由一个外层固定步驱动调用。它按接入策略处理输入与消息，可推进零步或多步，世界每次 `advance` 的步长固定。会话持有未确认输入和所需的帧源，`close` 释放连接或本机主机以及自有的预测实例。

`FrameUpdates` 向观测方交付新接纳的权威帧、可选的预测帧与预测轨迹替换信息，以及会话状态变化。它只交付这轮可见的新结果，重放的中间步留在会话内部。本机直接交付借用视图，远程可重用已解码的状态或复制少量展示字段。一次调用推进多步时，驱动在借用失效前保留最终采样所需的精简端点。输入、权威确认和画面都使用同一会话世代内的提交帧号定位。

### 调度与输入

- **主机固定步**。轮询与收件 → 验证连接与控制意图 → 为目标步取出各席输入 → `World.advance()` → 发布已提交结果。轮询预算与快照发送节奏保留可调性。大厅准备好后入队开局意图，断线宽限到期入队离场意图。把所有进入同一对局的世界写入纳入这一顺序。 [当前 SceneTree 调度](../../core/net/net_bus.gd) · [房间固定步](../../server/room_session.gd)
- **远程客户端固定步**。轮询 → 处理基线和地形版本 → 选取最新可用的权威帧并处理输入确认 → 必要时恢复重放 → 排帧并提交本地新输入 → 推进到预测终点 → 发布可见结果。没有可用新锚点时，在现有锚点的预测窗口内继续推进。
- **输入存放**。`InputBuffer`、`InputScheduler`、`InputClock` 管理网络输入的收件、排帧、确认和目标窗口。`seq`、`epoch`、`target_tick` 首次排定后用于重发与重放。迟到、过期和持续输入沿用的规则由会话处理。远端输入推测默认只在有界窗口内沿用已知的移动操作。实际传给世界的是具体帧的意图和必要的中立输入。 [现有排帧协议](../netplay.md#输入与预测)
- **输入世代与本地采样**。复活或退出个人回溯时，世界产生相应的已提交变化，会话更新相应席位的输入世代。重连由会话切换该世代。技能退出所在帧的操作抑制由时间规则在该步处理。输入采集保存原始操作，是否能行动由目标帧模拟裁定，避免推测倒地时遗失原本可重放的按键。 [现有输入版本切换](../../core/sim/match_world.gd) · [双击采集](../../core/net/local_input_source.gd)

### 远程数据合同

| 消息 | 内容与使用条件 |
| --- | --- |
| `BASELINE` | 会话世代、地图定义或可复用标识、规则配置、当前完整检查点及可用地形基线。两端按相同的规则标识及参数创建 `WorldSpec`。启用个人回溯时，包含检查点可查询的历史窗口。完成安装后才交付初始帧并发送就绪。 |
| `STATE` | 解码后含 `capture()` 的完整动态状态，包含帧末已排定的未来结果。地形以版本引用表示。接收方的输入确认、反馈和传输基准属于消息封套。 |
| `INPUT` | 原排帧的持续与单次操作、输入世代和传输确认。保留现有冗余、窗口和确认语义。 |
| 可靠地形与会话消息 | 安装地形版本、建立房间及身份、就绪、离场和重连。会话从进入房间开始持有收件队列，可安全穿过场景加载。 |

`STATE[t]` 表示已提交的 `t` 帧末，覆盖此前战斗结算和已经创建的任务。生命、后坐速度、生成后的弹体和爆炸任务直接来自检查点。校正采用锚点后，从 `t+1` 重放仍有效的未确认输入。会话用锚点封套里的最近已确认持续输入恢复延用起点，已确认的单次操作由检查点覆盖。权威帧已到达或超过原预测终点时，直接以它作为新的预测起点。发现快照等待地形版本时先保留它，地形到齐后从实际可用的快照中选最新帧。新会话世代替换旧基线，输入世代切换只裁剪所对应角色的旧输入。

传输继续复用已确认基线和字段差分，必要时发送全量表示。Beta 历史从基线及后续差分还原为同一个逻辑检查点，按角色或分段编码可读窗口的新增、裁剪和分支变化。完整解码的结果可以供新实例继续执行技能。若基准丢失，沿用请求全量状态的机制。`STATE` 编码缓存、预测输入窗口和玩法历史各自有独立寿命。 [当前增量编码](../../core/net/net_codec.gd)

`FIRE`、`HIT`、`BULLET_END`、`EXPLOSION` 退出模拟补写路径。计分与回合状态来自 `STATE`，击杀提示等表现同样从所采用的状态生成。过时的战斗消息可直接丢弃。若诊断保留 `FIRE`，其载荷只描述生成参数。战斗进度由 `STATE.tick` 表达，待结算记录随完整状态一起恢复。

## 表现层

### 接口与状态来源

```text
sampler.accept(updates: FrameUpdates)
sampler.sample(render_time)                      -> ViewSample
presenter.compose(sample: ViewSample, render_time) -> MatchFrame, Cues
match_view.present(frame: MatchFrame)
audio.play(cue)
```

采样器选择本帧应观察的状态并插值。以相同的缓冲、时钟基准和采样时间调用 `sample` 得到相同结果，缓冲淘汰随接纳和播放进度管理。表现推导只依赖本帧采样状态、上帧留下的少量显示数据和渲染时间。`MatchFrame` 向绘制提供角色姿态、锚点、武器、弹体、光束、地形样本及 HUD 数据。相同的 `MatchFrame` 可反复提交。渲染驱动只消费一次本轮 `compose` 产生的一次性提示。

| 部分 | 本机采样 | 远程采样 |
| --- | --- | --- |
| 本地运动、瞄准、持枪和自有弹体 | 相邻已提交帧 | 本地预测帧，经位置校正 |
| 本地血量、倒地和灰屏 | 已提交状态 | 已接纳的权威状态 |
| 远端人物、搭箭姿态、弹体、光束、地面武器 | 本机提交时间 | 同一个延迟播放刻 `render_tick` |
| 地形 | 当前本地模拟 | 使用自上次呈现起的占用差分，保证近身地图与本地碰撞一致 |

连续字段在相邻端点之间插值，环形地图使用最短位移。离散字段和对象成员关系在跨过其采样端点时一起切换。可沿用现有有界外推和自适应播放余量，角色、武器与弹体读取同一远端采样点。选定帧都未包含的短时过程可以略过。`compose` 根据实际观察到的变化生成必要提示，例如首次确认倒地或弹体出现、枪姿态切换。物理后坐已经体现在状态里。

地形模块合并两次呈现之间的实心占用变化，画面读取合并后的差分。首次挂载从地图基线应用。

联机本地角色的倒地姿态与相关后期从权威状态推导，预测姿态中的倒地字段也按这一来源选择。位置与移动继续采样预测。远端弓箭从同一采样时间读取 `AIMING` 和弹体成员关系，搭箭和出箭随采样切换。`RoundProjection` 读取已采样的回合结果和会话状态，HUD 使用现有的显示结构。 [当前采样与弓箭特判](../../scenes/pvp_match_client.gd) · [界面投影](../../scenes/round_projection.gd)

### 多帧校正

收到权威校正时，在同一个采样点求新轨迹基准 `P_new` 和切换前已经显示的基准 `D_old`。`D_old` 包含上一次残差尚未消退的部分。会话的轨迹替换信息让采样器可以取得切换前后的端点，位置残差归表现推导。

```text
offset = shortest_torus_delta(P_new, D_old)
shown(t) = wrap(P_new(t) + offset * decay(t - correction_time))
```

新基准随输入和插值继续向前，每帧只衰减偏移。再次校正时，使用当时实际会显示的位置计算新偏移。若两个渲染帧间有多次替换，以原显示轨迹接到最终采样轨迹。真实复活、重开或确认的传送重置连续性，主动回溯中连续采样的位移仍可平滑。角色、武器挂点、名牌和相机跟随使用同一校正后锚点。

衰减按经过的秒数计算。初版可复用 `LocalMotion` 的短时残差机制，最终曲线由连续校正与不同渲染帧率的实测决定。表现层只保留残差、相关的离散状态和当前动画所需参数。 [现有位置校正](../../core/present/match_sampler.gd)

录像和死亡倒带优先沿用画面回放机制，播完或跳过通过会话提交重开意图。录像缓存不足时，单人流程可在同一个 `advance` 上处理死亡倒带及跳过意图，复用历史恢复原语生成提交帧，保持原有倒带时长和重开时机。 [死亡倒带](2026-11-24-p0-p1-p3-plan.md#单人死亡倒带)

## 迁移顺序

| 阶段 | 改动 | 完成条件 |
| --- | --- | --- |
| 1. 迁出接入与诊断 | 把输入缓冲、反馈、稳定排帧和接收队列从角色及预测器迁到会话。让 `PerfMonitor` 和测试工具消费独立的校正、排帧及权威开火记录。 | 现有窗口、重连、重发和诊断继续通过。公网测试工具可改为读取新出口。 |
| 2. 接通统一世界和主机 | 实现固定步入口、当前动态状态的精确恢复和版本化地形。把 `AuthorityWorld`、`SoloLevel` 的规则代码迁到世界及已装配的规则。 | 单人与本机双席 1v1 均通过同一个无界面主机推进，伤害、归因、掉落、颗粒和回合结算可逐帧核对。 |
| 3. 切换玩法历史 | 建立按实体查询的历史窗口和两个时间模块，分开精确恢复与选择性恢复。将规则所需的历史及游标纳入完整检查点，迁移单人的倒带历史读法。 | 单人和 Beta 的回溯、退出后的续接、账户及所需地形版本通过。新实例从 Beta 检查点立即回溯，结果与原实例一致。 |
| 4. 切换远程会话 | 发出完整 `STATE`，接上版本就绪检查、输入确认和 `restore + advance`。统一场景树的调度入口，同时更新两端协议。 | 本机与远程在同一份入模输入上逐帧等价。丢包、乱序、换回合和重连可恢复，旧战斗事件可从预测路径移除。 |
| 5. 切换表现与清理 | 本机、联机、试玩统一输出 `ViewSample`。迁移画面校正、HUD 和一次性提示，移除旧轨道与拼接代码。 | 三个入口正常播放、暂停或离开各自会话。旧类的生产调用方与测试夹具同步迁走，更新运行与性能文档。 |

迁移期间用已提交帧提供旧界面的数据。第 4 阶段切换校正之后，旧表现仍可从各自的输入读取战斗通知，直至第 5 阶段按采样状态绘制。提交前按阶段运行已有的相应用例，旧实现以所有调用方完成迁移为删除条件。

## 验收与性能

| 验收项 | 核对方式 |
| --- | --- |
| 检查点可接续 | 从已有回合的一份已解码 `STATE` 在新实例恢复。输入同一后缀，逐帧比对权威状态。覆盖在途榴弹、待结算爆炸、武器分配、地面掉落、复活计时、回合转移、随机选点和 Beta 历史。 |
| 本机与远程等价 | 固定同一地图、规则、种子和**最终入模**的输入记录，分别从本机和远程进入，比较权威提交帧。网络延迟与输入到达差异另用调度测试覆盖。 |
| 玩法范围 | 验证单人氧气与武器归属、世界地形与普通敌人、精英受击去重，及 Beta 个人范围、当前弹体直击结果、扣费和多人同时回溯。回溯之后检查日志可从所选位置继续写入。 |
| 网络恢复 | 丢失和乱序 `STATE`、地形先到或后到、基准丢失、重连、换回合、旧输入世代。锚点切换后校正仅由检查点、地形版本和输入决定，安装失败时保留上一个可用世界。 |
| 调度 | 无监听者时，致死一击仍在同一提交帧完成归因、倒地、掉落和计分。改变节点优先级与场景加载时序仍可复现同一输入结果。 |
| 表现 | 远端弓箭及弹体按同一采样点切换。预测倒地取消时画面维持确认状态，确认倒地只触发一次。测试环形边缘、连续校正、复活、不同 FPS 及重复绘制。实际检查单人、联机及编辑试玩场景，并按项目约定记录截图。 |

正常稳定步进使用借用帧。完整采集用于发送状态或建立独立检查点，校正直接消耗已解码的锚点。玩法历史按字段变化记录在有界窗口内，展示只保存所用端点。如需跳过等价锚点的重放，比对范围要覆盖所有影响下一步的状态和远端输入选择。对比数据可以逐步增量维护，先测计算成本与减少的重放量。

对照记录服务器步时、客户端校正与重放耗时、每秒捕获次数、历史占用、快照编码及发送量、地形差分和形状重建、渲染步时与校正距离。先测本机回环及抖动，再以同图同配置的 8 席 newfactory Beta 大乱斗对照。运行公网对照时沿用工作区的 WPR 和中继约定，排除首尾各 5 秒，并单独统计复活和主动回溯。优先实测 Beta 历史入场基线大小、增量带宽以及预测地形撤销成本。 [现有性能指标](../performance.md) · [测试入口](../tests.md) · [本机测试工具](../../../test-tools/README.md)

计划阶段的选择包括同进程本地主机、地形显示默认跟随本地运动，以及以现有物理步与玩法历史采样节奏为初始参数。平滑曲线、历史编码和重放比较优化以对照结果定案。现有玩法和协议说明在对应实现切换时随之更新。
