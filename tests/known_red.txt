# tests/known_red.txt —— 「已知红基线」(`tests/run_all.sh` 读它)
#
# 一行 = `路径 类别 理由`
#   · 路径   = 相对仓库根,必须与 run_all.sh 枚举出来的那一支**逐字相同**;
#   · 类别   = `OK+RC` | `FAIL` | `NO-VERDICT` | `TIMEOUT` | `*`(任意红类);
#   · 理由   = **必填**(欠账指针 + 日期)。缺理由 / 空行 / 类别不合法 ⇒ `run_all.sh` **红**。
#   · `#` 开头是注释;不要留空行(空行也是违规)。
#
# 语义(见 tests/run_all.sh 文件头「判据分层」):
#   · 基线内的红 = `KNOWN-RED`:**不进**新红计数,但**永远**印出文件名与条数;
#   · 基线内的红 ⇒ 全批判词 `RUN_ALL OK-WITH-KNOWN-RED(n runs, k registered)`、**退出码 0**;
#   · 不在基线里的红 ⇒ `RUN_ALL FAIL(r new-red + k registered)`、**退出码非 0**;
#   · **修好了就删行**:条目"这趟跑到了、却没红" = 过期 ⇒ 也红(同 registered-debt §三「销掉时删行」)。
#   · ★ **写错也红**(2026-10-05 加,评审 I1/M5):路径**不在候选面**(不存在/已改名)⇒ 红;
#     同一路径**出现两次**(哪怕类别不同)⇒ 红(旧实现被关联数组静默折叠,后者覆盖前者)。
#     ⇒ 所以"多写一条"**不是**安全的 —— 它在两个方向上都会红。
#
# ★ 为什么要有这个文件:本仓自己的话 —— `tests/probe/allscript_probe.gd:14`
#   "一条**永远红**的闸等于没有闸"。一建起来就永远 FAIL 的聚合入口,后面几个工作包
#   **没法**拿它判断"我这次改坏了没有"。基线是**透明**的:红照印,只是不再挡路。
# ★ 加条目不是"让检查变绿"的手段:每条都必须有**真实**的欠账指针与实测日期。
#   ★ 反例(本文件**不**收的那一种):一条"我刚修好、但还没重跑确认"的红 —— 那会变成
#     过期基线条目,`run_all.sh` 照样红;该做的是修完重跑,而不是先加行。
#

#   测试面削减里被删掉了(台账:docs/superpowers/specs/2026-10-09-test-surface-cut-90-design.md)。
#   条目指向不存在的文件 = "永久死行",会让登记簿说谎(本文件头第 7 条)⇒ 删行,不是保留。
